# ตกลงขอบเขตก่อนลงมือ

## เมื่อไหร่ต้องหยุดถาม

หยุดถามก่อนเสมอ เมื่อเข้าเงื่อนไขข้อใดข้อหนึ่ง:
- คำสั่งไม่ระบุว่าใครใช้ ใช้ทำอะไร หรือขอบเขตครอบคลุมแค่ไหน
- มีมากกว่าหนึ่งวิธีตีความที่นำไปสู่งานที่ต่างกันอย่างมีนัยสำคัญ
- ต้องสร้างไฟล์ใหม่ตั้งแต่ 2 ไฟล์ขึ้นไป
- ต้องติดตั้ง dependency ใหม่
- ต้องแก้ schema ฐานข้อมูล

## วิธีถาม

ถามให้จบในรอบเดียว ไม่เกิน 4 ข้อ แต่ละข้อต้องมีตัวเลือกให้ผู้ใช้เลือก ไม่ใช่คำถามปลายเปิดลอยๆ

ครอบคลุม: ขอบเขต / ผู้ใช้งาน / ข้อจำกัดทางเทคนิค / ระดับความสมบูรณ์ที่ต้องการ

ก่อนถาม ให้สำรวจโครงสร้างโปรเจกต์ก่อน (Glob/Grep) เพื่อให้คำถามอ้างอิงของจริง
ห้ามถามโดยไม่ดูอะไรเลย และห้ามสำรวจเกิน 15 tool call

## สิ่งที่ห้ามทำก่อนได้ข้อสรุป

- ห้ามสร้างไฟล์ใดๆ
- ห้ามติดตั้ง dependency
- ห้ามแก้ schema

## เมื่อขอบเขตชัดแล้ว

- ทำเฉพาะสิ่งที่ตกลงกัน ไม่ทำมากกว่านั้น
- ห้าม refactor โค้ดข้างเคียงพ่วงไปด้วย แม้เห็นว่าโค้ดตรงนั้นไม่ดี — ให้รายงานแทน
- ห้ามแก้ไฟล์ config (package.json, tsconfig.json, next.config, tailwind.config, .env) ที่ไม่ได้อยู่ในข้อตกลง
- งานเล็กต้องได้ diff เล็ก ถ้ากำลังจะเกิน 50 บรรทัดในงานที่ผู้ใช้บอกว่า "แก้นิดเดียว" ให้หยุดถามก่อน
- ระบุไฟล์ที่แก้ทั้งหมดในคำตอบสุดท้าย
