# แนวปฏิบัติสำหรับผู้ช่วยเขียนโค้ดในโปรเจกต์นี้

> Arm การทดลอง Rule Dilution — มีกฎประกอบ 20 ข้อ
> กฎเป้าหมายอยู่ท้ายไฟล์และเหมือนกันทุก arm

## แนวปฏิบัติทั่วไปของทีม

1. ตั้งชื่อตัวแปรเป็น camelCase และชื่อชนิดข้อมูลเป็น PascalCase
2. ชื่อไฟล์ที่ export ฟังก์ชันหลายตัวให้ใช้ kebab-case
3. ความยาวบรรทัดไม่เกิน 100 ตัวอักษร
4. ใช้ single quote สำหรับ string ยกเว้นเมื่อภายในมี single quote อยู่แล้ว
5. จัดกลุ่ม import เป็นสามกลุ่มโดยเว้นบรรทัดคั่น: built-in, ภายในโปรเจกต์, relative
6. หลีกเลี่ยงการซ้อน if เกินสามชั้น ให้แตกเป็นฟังก์ชันที่มีชื่อบอกความหมายแทน
7. ฟังก์ชันไม่ควรยาวเกินหนึ่งหน้าจอ
8. ห้ามใช้ค่า magic number ให้ประกาศเป็นค่าคงที่ที่มีชื่อ
9. คอมเมนต์ควรอธิบายว่าทำไม ไม่ใช่อธิบายว่าทำอะไร
10. ห้ามทิ้งโค้ดที่ comment ไว้ในไฟล์ ให้ลบทิ้งเพราะ git เก็บประวัติให้อยู่แล้ว
11. ห้ามใช้ any ใน TypeScript ให้ระบุชนิดข้อมูลให้ชัด
12. ใช้ readonly กับ property ที่ไม่ควรถูกแก้หลังสร้าง
13. ประกาศชนิดข้อมูลของค่าที่ return จากฟังก์ชันที่ export เสมอ
14. ใช้ type สำหรับ union และ interface สำหรับโครงสร้างที่อาจถูก extend
15. หลีกเลี่ยง enum ใน TypeScript ให้ใช้ union ของ string literal แทน
16. ห้าม export ตัวแปรที่เปลี่ยนค่าได้ ให้ export ฟังก์ชันที่คืนค่าแทน
17. ตั้งชื่อ boolean ขึ้นต้นด้วย is, has, should หรือ can
18. ตั้งชื่อฟังก์ชันขึ้นต้นด้วยคำกริยา
19. หลีกเลี่ยงคำย่อในชื่อตัวแปร ยกเว้นคำที่ทีมใช้กันจนคุ้น
20. ห้ามตั้งชื่อตัวแปรว่า data, info, หรือ temp โดยไม่มีบริบทเพิ่ม
