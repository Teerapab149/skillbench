เริ่มจากคำว่า "บริบท"

AI อย่าง Claude หรือ ChatGPT ไม่ได้จำอะไรข้ามงาน ทุกครั้งที่มันตอบหรือลงมือทำ มันรู้แค่สิ่งที่อยู่ตรงหน้าตอนนั้น เรียกว่าบริบท (context) ซึ่งรวมทุกอย่างที่ถูกส่งให้โมเดล ทั้งคำสั่งของระบบ คำสั่งของผู้ใช้ ไฟล์ที่มันเปิดอ่าน ผลจากคำสั่งที่มันรัน และสิ่งที่คุยกันมาก่อนหน้า

ผลคือ ถ้ากฎของทีมไม่ได้อยู่ในบริบท AI ก็ไม่รู้ว่ามีกฎนั้น ต่อให้เป็นกฎที่ทุกคนในทีมรู้ดีก็ตาม งานทั้งหมดในหน้านี้จึงวนอยู่กับคำถามเดียว คือจะเอาอะไรใส่ในบริบท ใส่ตอนไหน และใส่แค่ไหน

จาก Prompt Engineering สู่ Context Engineering

ช่วงแรกที่คนเริ่มใช้ ChatGPT สิ่งที่ทุกคนสนใจคือจะเขียนคำสั่งยังไงให้ได้คำตอบดี เรียกกันว่า prompt engineering

แต่พอ AI กลายเป็นเอเจนต์ที่ทำงานหลายขั้นได้เอง อ่านไฟล์ รันคำสั่ง แก้โค้ด สิ่งที่อยู่ในบริบทก็ไม่ได้มีแค่คำสั่งที่เราพิมพ์อีกต่อไป แต่มีทุกอย่างที่ไหลเข้ามาระหว่างทาง ทั้งเอกสาร ผลเทส และข้อความจากเครื่องมือ กลางปี 2025 คนในวงการเลยเริ่มเรียกงานนี้ว่า context engineering และ Anthropic อธิบายไว้ว่าเป็นวิธีคัดและดูแลข้อมูลในบริบทให้พอดีที่สุดในแต่ละช่วงที่โมเดลทำงาน

ทำไมไม่ใส่ทุกอย่างลงไปเลยบริบทมีขนาดจำกัด และยิ่งใส่เยอะ โมเดลยิ่งดึงข้อมูลที่ต้องใช้ออกมาได้แม่นน้อยลงทีละนิด Anthropic เรียกอาการนี้ว่า context rot และเปรียบว่าโมเดลมี "งบความสนใจ" ที่ข้อความทุกคำใช้ไปส่วนหนึ่ง เป้าหมายของ context engineering จึงไม่ใช่ใส่ให้เยอะที่สุด แต่ใส่เฉพาะที่จำเป็น และค่อยโหลดส่วนที่เหลือเมื่อต้องใช้

ไฟล์กฎ วิธีแรกที่ทีมใช้บอกกฎ

วิธีที่ง่ายที่สุดคือเขียนกฎทั้งหมดไว้ในไฟล์เดียว แล้วให้เครื่องมือโหลดเข้าบริบททุกครั้งที่เริ่มงาน แต่ละเครื่องมือมีชื่อไฟล์ของตัวเอง เช่น CLAUDE.md ของ Claude Code และ .cursorrules ของ Cursor ต่อมาในเดือนสิงหาคม 2025 มี AGENTS.md ออกมาเป็นรูปแบบกลางที่หลายเครื่องมืออ่านได้

ข้อดี คือเขียนง่าย ดูแลง่าย และมั่นใจได้ว่า AI เห็นกฎครบทุกข้อ ข้อเสีย คือกฎทุกข้อกินพื้นที่บริบทตลอดเวลา แม้ข้อที่ไม่เกี่ยวกับงานตรงหน้า เช่น ตอนแก้หน้าเว็บ AI ก็ยังต้องอ่านกฎเรื่องการคิดเงินไปด้วย

Agent Skills เปิดอ่านเมื่อจำเป็น

เดือนตุลาคม 2025 Anthropic เปิดตัว Agent Skills ซึ่งเอาหลัก "โหลดเมื่อจำเป็น" ของ context engineering มาใช้กับความรู้และกฎ skill หนึ่งชุดคือโฟลเดอร์ที่มีไฟล์ SKILL.md ข้างบนสุดของไฟล์เขียนชื่อกับคำอธิบายสั้น ๆ ว่าใช้ตอนไหน ข้างล่างคือเนื้อหาเต็ม และอาจมีไฟล์อื่นประกอบ AI จะเห็นข้อมูลเป็นสามชั้น

  1. ชื่อกับคำอธิบายAI เห็นของทุก skill ตั้งแต่เริ่มงาน ไว้ใช้ตัดสินว่า skill ไหนเกี่ยวกับงานนี้
  2. เนื้อหาเต็มใน SKILL.mdAI เปิดอ่านเมื่อเห็นว่างานตรงกับคำอธิบาย
  3. ไฟล์ประกอบAI เปิดเพิ่มเฉพาะตอนที่เนื้อหาเต็มบอกให้ไปดู

แนวคิดนี้เรียกว่า progressive disclosure คือค่อย ๆ เปิดข้อมูลเท่าที่ต้องใช้ ในเดือนธันวาคม 2025 Anthropic เปิด Agent Skills เป็นมาตรฐานกลางที่ agentskills.io เพื่อให้ skill ชุดเดียวกันใช้กับเครื่องมืออื่นได้

เรียงตามเวลา

  1. ช่วงแรกของ ChatGPTคนสนใจว่าจะเขียนคำสั่งยังไงให้ได้คำตอบดี เรียกกันว่า prompt engineering
  2. มิ.ย. 2025Tobi Lütke (Shopify) และ Andrej Karpathy ชวนให้เรียกงานนี้ว่า context engineering แทน เพราะสิ่งที่ส่งผลจริงคือข้อมูลทั้งหมดที่โมเดลเห็น ไม่ใช่แค่ถ้อยคำในคำสั่ง
  3. ส.ค. 2025AGENTS.md ออกมาเป็นรูปแบบไฟล์กฎกลางที่เครื่องมือหลายตัวอ่านได้ แทนที่แต่ละเครื่องมือจะมีไฟล์ของตัวเอง
  4. 29 ก.ย. 2025Anthropic เขียนบทความอธิบาย context engineering เป็นระบบ และชี้ว่าบริบทเป็นทรัพยากรที่มีจำกัด
  5. 16 ต.ค. 2025Anthropic เปิดตัว Agent Skills ให้เอเจนต์เปิดอ่านความรู้หรือกฎเฉพาะเมื่องานต้องใช้
  6. 18 ธ.ค. 2025Agent Skills เปิดเป็นมาตรฐานกลางที่ agentskills.io ให้เครื่องมืออื่นใช้รูปแบบเดียวกันได้
  7. ต้นปี 2026งานวิจัยชุดแรกเริ่มวัดว่า skill ช่วยเอเจนต์ได้แค่ไหน แต่ยังเทียบกับการไม่มี skill เป็นหลัก
  8. ต.ค. 2026งานของเรา เทียบไฟล์เดียวกับ Skills ตรง ๆ โดยให้กฎเหมือนกันทุกข้อ

ทำไมเราถึงวัดเรื่องนี้

Agent Skills ตั้งอยู่บนความเชื่อว่า ถ้ากฎที่ไม่เกี่ยวไม่มากวน AI จะทำตามกฎที่เกี่ยวได้ดีขึ้น ฟังดูมีเหตุผล แต่ก็มีความเสี่ยงอีกด้าน คือ AI อาจไม่เปิด skill ที่ควรเปิด แล้วไม่เห็นกฎที่สำคัญเลย

งานวิจัยที่ออกมาช่วงต้นปี 2026 วัดว่า "มี skill" ดีกว่า "ไม่มี skill" ไหม แต่เท่าที่เราค้น ยังไม่มีใครเทียบไฟล์เดียวกับ Skills ตรง ๆ โดยให้กฎเหมือนกันทุกข้อ และวัดว่า AI ทำผิดกฎจริงหรือเปล่าจากสิ่งที่มันทำกับระบบ เราเลยทำการทดลองนี้ขึ้นมา
