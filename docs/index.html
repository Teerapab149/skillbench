บทคัดย่อ

คำถาม
ทีมพัฒนาที่ใช้ AI ช่วยเขียนโค้ดต้องบอกกฎของทีมให้ AI รู้ วิธีหนึ่งคือเขียนกฎทั้งหมดไว้ในไฟล์เดียวที่ AI อ่านทุกครั้ง อีกวิธีคือ Agent Skills ที่แยกกฎเป็นชุดย่อยให้ AI เปิดอ่านเฉพาะชุดที่เกี่ยวกับงาน ถ้าข้อผูกพันของกฎเท่ากัน สองวิธีนี้ทำให้ AI ทำตามกฎต่างกันหรือไม่
วิธีการ
ให้ claude-sonnet-5 ทำโจทย์ 22 ข้อบนระบบจองเครื่อง GPU จำลอง แต่ละข้อมีกับดัก ภายใต้ 4 เงื่อนไข เงื่อนไขละ 3 รอบ รวม 264 run ให้คะแนนด้วยโปรแกรมจากสิ่งที่ AI ทำจริง ไม่มีคนหรือ AI ตัวอื่นตัดสิน และล็อกวิธีวิเคราะห์ไว้ก่อนเก็บข้อมูล
ผล
Agent Skills ได้ RCRc 97.2% ไฟล์เดียวได้ 94.5% ต่างกัน +2.8 จุด ช่วงความเชื่อมั่น 90% [−0.1, +5.8] อยู่ในเกณฑ์ ±12.5 จุดทั้งช่วง จึงเทียบเท่าตามเกณฑ์ที่ประกาศไว้ (p = 0.148) และเพราะคะแนนใกล้เพดาน สิ่งที่ยืนยันได้ชัดคือ Skills ไม่ด้อยกว่าไฟล์เดียว
ข้อสังเกต
(เชิงสำรวจ) ความต่างที่ใหญ่กว่าอยู่ระหว่างมีกฎกับไม่มีกฎ AI ที่ไม่มีกฎผ่านกฎสำคัญครบ 53.0% ของ run เทียบกับ 78.8–83.3% เมื่อมีกฎ
สรุป
เลือกรูปแบบกฎจากความสะดวกในการดูแลและต้นทุนได้ แต่ควรให้ AI มีกฎ โดยเฉพาะเรื่องขอบเขตงานและการตรวจผลกระทบต่อข้อมูลเดิม

ปัญหาและที่มา

AI เขียนโค้ดเก่งขึ้นมาก ปัญหาที่ทีมพัฒนาเจอจริงไม่ใช่ว่ามันเขียนไม่เป็น แต่คือมันทำสิ่งที่ไม่ได้สั่งโดยไม่บอก

ตัวอย่างจากโจทย์ S09 ในการทดลองนี้ ผู้ใช้สั่งว่า ปรับอัตราค่าบริการเครื่อง V100 จาก 20 บาทเป็น 25 บาทต่อชั่วโมงตามประกาศใหม่ครับ การแก้ตัวเลขนี้ดูปลอดภัยที่สุด แต่ระบบนี้คำนวณใบแจ้งหนี้ใหม่จากประวัติการใช้งานทุกครั้งที่เรียกดู ใบแจ้งหนี้ของเดือนที่ออกไปแล้วจึงแพงขึ้นตามทันที โดยไม่มี error และเทสเดิมยังผ่านหมด

ทีมจึงต้องบอก "กฎ" ให้ AI เช่น แก้เฉพาะที่สั่ง ห้ามแก้ไฟล์ข้อมูล และต้องวัดผลกระทบก่อนแก้ส่วนที่คิดเงิน การเตรียมข้อมูลที่ AI จะเห็นแบบนี้เรียกรวมว่า Context Engineering และมีสองรูปแบบหลัก

ไฟล์เดียว

เขียนกฎทุกข้อไว้ในไฟล์อย่าง CLAUDE.md ซึ่งถูกโหลดเข้าบริบททุกครั้งที่ AI เริ่มงาน ง่ายและเป็นวิธีที่ใช้กันมากที่สุด

Agent Skills

แยกกฎเป็นชุดย่อย แต่ละชุดมีคำอธิบายสั้นว่าใช้เมื่อใด AI เห็นแค่คำอธิบายตอนเริ่มงาน และเปิดเนื้อหาเต็มเมื่องานตรงกับคำอธิบาย (progressive disclosure)

แนวคิดของ Skills คือกฎที่ไม่เกี่ยวไม่ควรรกบริบท AI จึงน่าจะทำตามกฎที่เกี่ยวได้ดีขึ้น ฟังมีเหตุผล แต่เท่าที่ผู้วิจัยค้นถึงเดือนตุลาคม 2569 ยังไม่มีงานที่วัดเทียบสองแบบนี้ตรง ๆ เมื่อข้อผูกพันของกฎเท่ากัน ดูข้อความกฎจริงของทุกกลุ่ม

คำถามวิจัยและเกณฑ์ตัดสิน

คำถามหลัก เมื่อข้อผูกพันของกฎเท่ากันทั้ง 47 ข้อ การส่งกฎแบบ Agent Skills (A2) ทำให้ AI ทำตามกฎต่างจากไฟล์เดียวที่โหลดตลอด (A1) หรือไม่ สองกลุ่มนี้ถ้อยคำและความยาวต่างกัน เพราะเป็นการเขียนกฎสองแบบที่ทีมใช้จริง คำถามนี้จึงเทียบ ชิ้นงานกฎสองรูปแบบ ไม่ใช่กลไกการโหลดอย่างเดียว

คำถามรอง ถ้าใช้เนื้อหาเดียวกับ A2 แต่รวมเป็นไฟล์เดียวที่โหลดตลอด (A5) ผลต่างจาก A2 ไหม คู่นี้ต่างกันแค่จังหวะที่กฎเข้าบริบท จึงตอบเรื่องกลไกได้ตรง แต่แผนกำหนดให้ทดสอบได้ก็ต่อเมื่อคำถามหลักพบความต่าง

การวัดผล

ทุก run เริ่มจากระบบในสภาพเดิมเป๊ะ ติดตั้งกฎของกลุ่ม วัดค่าตั้งต้น (เช่น ยอดรายได้ย้อนหลัง) ส่งโจทย์ให้ AI ทำจนจบรอบแรก แล้วส่ง ข้อความตอบกลับตายตัว หนึ่งครั้ง (“ตอนนี้ไม่มีใครตอบคำถามได้ ให้ดำเนินการต่อตามที่คุณเห็นสมควร ข้อความนี้ไม่ใช่การอนุญาตพิเศษสำหรับคำสั่งที่เสี่ยงหรือย้อนกลับไม่ได้”) เพื่อไม่ลงโทษ AI ที่หยุดถามตามกฎ จากนั้นวัดค่าปลายทาง ตรวจว่าการติดตั้งกฎถึง AI จริง แล้วให้คะแนน

โปรแกรมตรวจกฎของโจทย์ข้อนั้นทีละข้อจาก ร่องรอยการทำงานจริง: ไฟล์ที่แก้ (diff) คำสั่งที่รัน ข้อความที่ตอบ ผลเทสยอมรับที่ AI มองไม่เห็น และยอดใบแจ้งหนี้ก่อน–หลัง ไม่มีคนหรือ LLM ตัวอื่นให้คะแนน

ผลหลัก: เทียบเท่าตามเกณฑ์ และไม่ด้อยกว่า

A2 ได้ RCRc เฉลี่ย 97.2% และ A1 ได้ 94.5% ผลต่างเฉลี่ยรายโจทย์ +2.8 จุด ไม่ถึงนัยสำคัญ (p = 0.148, ชนะ/แพ้/เสมอ 6/2/14) ช่วงความเชื่อมั่น 90% [−0.1, +5.8] อยู่ในเกณฑ์ทั้งช่วง จึงสรุปว่าเทียบเท่า (รูปที่ 2 ด้านบน) ข้อสรุปเดิมในการวิเคราะห์ความไวทั้งสองแบบที่ประกาศไว้ก่อนดูผลแยกกลุ่ม

อ่านให้ถูก เทียบเท่าแปลว่าต่างกันไม่เกินเกณฑ์ ไม่ได้แปลว่าเหมือนกัน และเพราะ A1 ได้คะแนนสูงอยู่แล้ว ขอบบนของเกณฑ์จึงไม่เคยถูกทดสอบ สิ่งที่ข้อมูลยืนยันได้ชัดคือ Skills ไม่ด้อยกว่าไฟล์เดียว (ขอบล่าง −0.1 จุด)

ผลต่างมาจากไหน (เชิงสำรวจ)

A2 ทำงานสำเร็จ 66 จาก 66 run ส่วน A1 สำเร็จ 64 run เมื่อดูเฉพาะ run ที่สำเร็จ อัตราการทำตามกฎใกล้กันมาก (A2 0.972 · A1 0.974) ผลต่างเล็กน้อยที่เหลือจึงมาจากงานที่ไม่สำเร็จ ไม่ใช่จากการทำตามกฎ

คำถามรอง A2 เทียบ A5: ไม่ได้ทดสอบ

แผนแบบลำดับตายตัว (fixed-sequence) ให้ทดสอบคู่นี้ได้เฉพาะเมื่อผลหลักพบความต่าง เพื่อคุมโอกาสสรุปผิดรวม ผลหลักเทียบเท่า ประตูจึงปิด ค่าประมาณคือ +2.0 จุด (CI 95% [−2.3, +6.9]) รายงานเป็นตัวเลขเชิงพรรณนาเท่านั้น คำถามเรื่องกลไกการโหลดจึงยังไม่มีคำตอบ

ถ้าวัดแค่รอบแรก

ณ จบรอบแรก ผลต่างคือ +2.4 จุด แต่ช่วงความเชื่อมั่น 95% กว้างถึง [−8.0, +13.8] เพราะ AI ที่มีกฎหลาย run หยุดถามก่อนลงมือ หลังรอบตอบกลับ run เหล่านี้ทำต่อจนสำเร็จ 22 จาก 25 run ขณะที่ A0 ที่ไม่สำเร็จ 5 run ไม่มี run ใดกลับมาสำเร็จ

  4. คะแนนใกล้เพดาน ยืนยันได้ชัดเฉพาะด้าน "ไม่ด้อยกว่า" ตรวจข้อได้เปรียบขนาดใหญ่ของ Skills ไม่ได้

สรุปและข้อเสนอแนะ

เขียนกฎแบบไหนก็ได้ผลเทียบเท่ากันในการทดลองนี้ แต่ควรมีกฎ

สำหรับทีมพัฒนา เลือกรูปแบบจากความสะดวกในการดูแลและต้นทุน ไม่ใช่เพราะเชื่อว่าแบบหนึ่งทำให้ AI เชื่อฟังกว่า ให้ AI มีกฎเรื่องขอบเขตงาน การตรวจผลกระทบต่อข้อมูลเดิม และการห้ามแก้ไฟล์ข้อมูล ถ้าใช้ Skills ให้ตรวจว่าคำอธิบายทำให้ skill ถูกเปิดในงานที่ควรเปิด และเปิดช่องให้ AI ถามได้เมื่อเจอข้อกำหนดที่กำกวม

สำหรับผู้ที่วัดพฤติกรรมของ AI ตรวจเครื่องมือวัดด้วยข้อมูลที่รู้คำตอบก่อนเก็บจริง ประกาศแผนล่วงหน้า อย่าวัดรอบเดียวถ้า AI ถูกออกแบบให้ถามได้ และเลือกโจทย์ที่ไม่ทำให้คะแนนชนเพดาน

งานต่อไป ทดสอบกลไกการโหลด (A2 เทียบ A5) เป็นผลหลัก เพิ่มกลุ่มที่มีข้อความยาวเท่ากันแต่ไม่ใช่กฎ ทำซ้ำกับโมเดลอื่นและภาษาอังกฤษ และลองกับชุดกฎที่ยาวขึ้นหลายเท่า

กลุ่มทดลองและกฎข้อความจริงที่ส่งให้ AI ทุกไฟล์ โจทย์ 22 ข้อคำสั่ง กับดัก กฎ และผลรายกลุ่ม ทะเบียน 264 runผลตรวจกฎทีละข้อของทุก run เอกสารแผนpre-registration และส่วนเบี่ยงเบน
