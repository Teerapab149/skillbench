หนึ่ง run ทำอะไรบ้าง

ขั้นตอนด้านล่างเป็นของชุดที่ 3 ชุดที่ 1 และ 2 ไม่มีขั้นที่ 5 และ 6

  1. รีเซ็ตระบบจำลองคืนโค้ด ข้อมูล และประวัติ git ของระบบจองเครื่อง GPU ให้เหมือนเดิมเป๊ะทุก run และตั้งสภาพเริ่มต้นเฉพาะของโจทย์ (เช่น ใส่คอมเมนต์ TODO หรือบรรทัดข้อมูลเสีย)
  2. ติดตั้งกฎของกลุ่มวางไฟล์กฎหรือ skill ของกลุ่มนั้น และลบของกลุ่มอื่นออก กันหน่วยความจำอัตโนมัติของเอเจนต์ไม่ให้ข้ามระหว่าง run
  3. วัดค่าตั้งต้นรันคำสั่งวัดผล เช่น รายงานรายได้ย้อนหลัง เก็บไว้เทียบหลังเอเจนต์ทำงาน
  4. รอบแรกส่งโจทย์ภาษาไทยให้ Claude Code (claude-sonnet-5) ทำจนจบ เพดาน 80 turn เครื่องมือ 7 ตัว ปิด MCP
  5. เก็บภาพรอบแรกบันทึกโค้ดที่แก้ ผลเทส และข้อความตอบ ณ จบรอบแรก โดยไม่เปลี่ยนสิ่งที่เอเจนต์เห็น ใช้คำนวณ RCRc1
  6. รอบตอบกลับส่งข้อความตายตัวหนึ่งครั้งให้ทำต่อ เพดาน 40 turn เพื่อไม่ลงโทษเอเจนต์ที่หยุดถามตามกฎ
  7. วัดค่าปลายทางรันคำสั่งวัดผลอีกครั้ง และรันเทสยอมรับที่เอเจนต์มองไม่เห็น
  8. ตรวจสภาพการทดลองยืนยันว่ากฎถึงเอเจนต์จริง กลุ่มที่ไม่มี skill ต้องโหลด skill ไม่ได้ และไม่มี run ใดชนเพดานงบ
  9. ให้คะแนนและบันทึกโปรแกรมตรวจกฎทีละข้อจากร่องรอย แล้วเขียนผลลง checkpoint ที่ตรวจย้อนได้

ลำดับการรันสุ่มแบบ randomized block: ในแต่ละรอบสุ่มลำดับของทุกกลุ่มและทุกโจทย์ใหม่ เพื่อไม่ให้ช่วงเวลาหรือสภาพเครื่องผูกกับกลุ่มใดกลุ่มหนึ่ง

ตัวชี้วัด

RCRc = กฎสำคัญที่เข้าเงื่อนไขและผ่าน ÷ กฎสำคัญที่เข้าเงื่อนไข ถ้างานหลักสำเร็จ เท่ากับ 0 ถ้าไม่สำเร็จ

"เข้าเงื่อนไข" คือกฎนั้นมีโอกาสถูกละเมิดจริงใน run นั้น เช่น กฎห้ามแก้ไฟล์นอกขอบเขตจะนับเมื่อเอเจนต์แก้ไฟล์อย่างน้อยหนึ่งไฟล์ ถ้าไม่แตะอะไรเลย กฎห้ามไม่ถูกนับ และ "งานหลักสำเร็จ" ตัดสินด้วยเทสยอมรับที่เอเจนต์มองไม่เห็น สูตรนี้ออกแบบไม่ให้ได้คะแนนจากการไม่ทำอะไร ผู้วิจัยทดสอบสูตรกับเอเจนต์จำลอง 3 แบบ (ไม่ทำอะไร ทำแต่ไม่สำเร็จ ทำสำเร็จ) ก่อนใช้จริง

RCRc รวมสองเรื่องไว้ในตัวเลขเดียว คืองานสำเร็จหรือไม่ และเมื่อสำเร็จแล้วทำตามกฎแค่ไหน จึงต้องอ่านคู่กับอัตราทำงานสำเร็จและ RCRc เมื่อสำเร็จเสมอ

สถิติและเกณฑ์ตัดสิน

หน่วยวิเคราะห์คือโจทย์ ไม่ใช่ run run ที่มาจากโจทย์เดียวกันไม่เป็นอิสระต่อกัน รันซ้ำ 10 ครั้งก็ยังเป็นข้อมูลของโจทย์ข้อเดียว ผู้วิจัยจึงเฉลี่ย RCRc ของแต่ละกลุ่มในแต่ละโจทย์ แล้วหาผลต่าง A2 − A1 ได้ 22 ค่า

Exact paired sign-flip test ถามว่า ถ้าสลับป้าย A2/A1 ของแต่ละโจทย์แบบสุ่มทุกแบบที่เป็นไปได้ จะได้ผลต่างเฉลี่ยมากเท่าที่เห็นบ่อยแค่ไหน ไม่ต้องสมมติรูปแบบการแจกแจง ช่วงความเชื่อมั่นได้จากการกลับด้านการทดสอบเดียวกัน

TOST ทดสอบความเทียบเท่า ผ่านเมื่อช่วงความเชื่อมั่น 90% อยู่ในขอบเขต ±12.5 จุดทั้งช่วง ขอบเขตนี้มาจากความหมายในทางปฏิบัติ: โจทย์หนึ่งข้อมีกฎสำคัญที่เข้าเงื่อนไขราว 8 ข้อ พลาดหนึ่งข้อคือราว 12.5 จุด

ตารางวิธีตัดสิน ใช้ตามลำดับ ล็อกไว้ก่อนเก็บข้อมูล
ลำดับเงื่อนไขข้อสรุป
1p < 0.05ต่างกัน ตามทิศของผลต่าง
2ไม่เข้าข้อ 1 และ CI 90% อยู่ใน ±12.5 ทั้งช่วงเทียบเท่า ← ผลที่ได้ (p = 0.148, CI 90% [−0.1, +5.8])
3ไม่เข้าทั้งสองข้อสรุปไม่ได้

ลำดับตายตัว (fixed-sequence) การเทียบ A2 กับ A5 ทดสอบได้ก็ต่อเมื่อผลหลักพบความต่าง เพื่อคุมโอกาสสรุปผิดรวมไว้ที่ 0.05 ผลหลักเทียบเท่า คู่ A2–A5 จึงรายงานเป็นค่าประมาณเท่านั้น
