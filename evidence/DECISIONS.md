### 2026-09-04 — ไม่พยายามทำ runtime ให้สะอาดเป็นศูนย์ แต่นิยามเป็น baseline set B

**ตัดสินโดย:** Teerapab
**ผู้ช่วยเสนอ (ผิด):** เขียนว่า "ตัวแปรต้นถูกทำลายทุก run" และเข้าใจผิดว่า `system:init.skills` คือ skill ที่ถูกโหลด

**ทางเลือกที่ปฏิเสธ:** ประกาศว่าการทดลองใช้ไม่ได้ — เกินกว่าที่ข้อมูลรองรับ
**ผล:** `config/arms.json` `_settingSourcesNote` · ตัวแปรต้นนิยามใหม่เป็นส่วนต่างจาก baseline set B

### 2026-09-06 — สร้างระบบเก็บหลักฐานการทำงานร่วมกับ AI

**ตัดสินโดย:** Teerapab
**เหตุผลที่ผู้ใช้ให้:** ใช้ AI เป็นเครื่องมือโดยมีหลักฐานชัดเจนไม่ใช่ปัญหา แต่ต้องมี safety ไว้ป้องกันตัวเอง และควรใช้กับงานทุกอย่าง ไม่จำกัดแค่งานมหาลัย
**ผู้ช่วยเสนอ:** แบ่งสองชั้น — hook เป็นชั้นบังคับ (ลืมไม่ได้) และ skill เป็นชั้นวินัย (อธิบายว่าทำไม)
**หลักฐานความปลอดภัยต่อการทดลอง (ตรวจแล้วทั้งสามข้อ):**
- `evidence/` และ `scripts/` ไม่อยู่ใน `experimentDigest()`
- skill ส่วนตัว 13 ตัวในเครื่อง **ทับกับ baseline 18 ตัวที่ run มองเห็นเป็นศูนย์** จึงติดตั้ง skill ใหม่ได้โดย manifest ไม่พัง
- hook เขียนเฉพาะ repo ที่มี `evidence/.ledger-enabled` ซึ่ง fixture ไม่มี
**ผลข้างเคียงที่พบ:** บันทึกใน `config/arms.json` ที่เขียนว่า baseline 18 ตัวคือ "บันเดิลมากับ CLI 15 + ของผู้ใช้ 3" **ผิด** — เป็นของ CLI ทั้ง 18 ตัว
**ทางเลือกที่ปฏิเสธ:** ติดตั้ง hook แบบไม่มีตัวกัน — จะกลายเป็นตัวแปรที่ไม่มีใครประกาศระหว่างเก็บข้อมูล ซึ่งคือความผิดพลาดแบบเดียวกับที่โปรเจกต์นี้ไล่กำจัดมาตลอด
