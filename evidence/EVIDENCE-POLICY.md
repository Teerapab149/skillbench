# นโยบายหลักฐาน — ทำงานร่วมกับ AI แล้วยังพิสูจน์ได้ว่าใครตัดสินใจ

> ไม่ใช่เอกสารสำหรับงานมหาลัยอย่างเดียว ใช้กับงานอะไรก็ได้ที่เราทำร่วมกัน

## ปัญหาที่นโยบายนี้แก้

การใช้ AI เป็นเครื่องมือกับการให้ AI ทำแทนทั้งหมด **มองจากผลลัพธ์แล้วแยกไม่ออก** — โค้ดที่ได้หน้าตาเหมือนกัน รายงานที่ได้อ่านเหมือนกัน สิ่งเดียวที่แยกสองอย่างนี้ออกจากกันได้คือ **ร่องรอยของการตัดสินใจ**

เพราะงั้นสิ่งที่ต้องเก็บไม่ใช่ "หลักฐานว่าทำงานเยอะ" แต่คือ **หลักฐานว่าใครเลือก อะไรถูกปฏิเสธ และเพราะอะไร**

## หลักการที่ยืมมาจากตัวการทดลองเอง

โปรเจกต์นี้เจ็บมาแล้วสามครั้งจากตัวแปรควบคุมที่ *ประกาศไว้แต่ไม่เคยถูกบังคับ* (`model`, `temperature`, `toolset`) นโยบายหลักฐานก็มีโรคเดียวกันได้ ถ้าเขียนว่า "ต้องเก็บทุกอย่าง" แล้วปล่อยให้เป็นเรื่องของวินัย

จึงแบ่งเป็นสองชั้นแบบเดียวกับ signature/manifest:

| ชั้น | ใครบังคับ | ลืมได้ไหม | เก็บอะไร |
|---|---|---|---|
| **ชั้นบังคับ** | hook ของ Claude Code (harness รันเอง) | **ลืมไม่ได้** | prompt ทุกอัน, คำสั่งที่รันทุกคำสั่ง, ไฟล์ที่ถูกแก้ทุกไฟล์ |
| **ชั้นวินัย** | skill `evidence-trail` (คำสั่งถึงตัวผู้ช่วย) | ลืมได้ จึงต้องมีชั้นบังคับรองรับ | เหตุผล, ทางเลือกที่ไม่ได้เลือก, ใครตัดสิน |

**ชั้นบังคับพิสูจน์ว่าเกิดอะไรขึ้น ชั้นวินัยอธิบายว่าทำไม** อย่างแรกปลอมยาก อย่างหลังมีค่าเฉพาะเมื่ออย่างแรกยืนยันมันได้

## สิ่งที่มีอยู่แล้วก่อนจะสร้างอะไรใหม่

`~/.claude/projects/E--Seminar-skillbench/*.jsonl` — **บทสนทนาดิบทุกตัวอักษร 23 MB** ทั้ง prompt ที่พิมพ์ ทั้ง tool call ทุกครั้ง ทั้งผลลัพธ์ ตั้งแต่ 8 ส.ค.

นี่คือหลักฐานชั้นดีที่สุดที่มีอยู่แล้ว **ปัญหาเดียวของมันคือมันอยู่นอก repo และถูกลบทิ้งได้** เพราะงั้นงานอันดับแรกไม่ใช่การสร้างระบบเก็บใหม่ แต่คือ **การถ่ายสำเนาออกมาแล้วผูก hash ไว้**

`node scripts/evidence-archive.mjs`

## กฎ

### 1. ทุก prompt ต้องถูกบันทึก
บังคับด้วย hook `UserPromptSubmit` → `evidence/ledger.jsonl`
เหตุผล: prompt คือหลักฐานว่าคุณเป็นคนกำหนดทิศทาง ไม่ใช่ผู้ช่วยคิดเอง

### 2. ทุกคำสั่งที่รัน ต้องถูกบันทึกพร้อม exit code
บังคับด้วย hook `PostToolUse` บน Bash/PowerShell
เหตุผล: การรันเบื้องหลังคือจุดที่ "เกิดอะไรขึ้นบ้าง" หายไปง่ายที่สุด

### 3. ทุกไฟล์ที่ถูกแก้ ต้องถูกบันทึก
บังคับด้วย hook `PostToolUse` บน Edit/Write
เหตุผล: git commit บอกผลลัพธ์ ledger บอกลำดับ — และลำดับคือสิ่งที่บอกว่าใครนำใครตาม

### 4. การตัดสินใจทุกครั้งต้องมีเจ้าของที่เป็นคน
ชั้นวินัย → `evidence/DECISIONS.md`
**ผู้ช่วยเสนอได้ ผู้ช่วยตัดสินใจไม่ได้** ทุกแถวในไฟล์นั้นต้องมีชื่อคนกำกับ พร้อมทางเลือกที่ถูกปฏิเสธ
เหตุผล: นี่คือแถวที่ตอบคำถาม *"งานนี้เป็นของใคร"* ได้จริง ไม่ใช่จำนวนบรรทัดโค้ด

### 5. ผู้ช่วยที่ทำผิดต้องถูกบันทึกว่าทำผิด
เมื่อผู้ช่วยเสนอสิ่งที่ผิดแล้วถูกแก้ ให้บันทึกลง `DECISIONS.md`
เหตุผล: **นี่คือหลักฐานที่มีน้ำหนักที่สุดในทั้งไฟล์** คนที่ปล่อยให้ AI ทำแทนไม่มีบันทึกแบบนี้ เพราะไม่รู้พอที่จะจับผิดได้

### 6. งานที่ผู้ช่วยร่างเนื้อความ ต้องถูกทำเครื่องหมายไว้
โดยเฉพาะ prose ในรายงาน — ทำเครื่องหมายไว้จนกว่าเจ้าของจะอ่านทุกประโยคแล้วเขียนใหม่ด้วยความเข้าใจของตัวเอง
เหตุผล: ถ้าอธิบายประโยคไหนในห้องสอบไม่ได้ ประโยคนั้นไม่ควรอยู่ในเล่ม ไม่ว่าใครเขียน

### 7. หลักฐานภาพสำหรับสิ่งที่ข้อความเก็บไม่ได้
การรันจริง หน้าจอ terminal ผลลัพธ์ที่เห็นกับตา → `evidence/screenshots/` พร้อมไฟล์ `.md` กำกับว่าภาพนั้นคืออะไร รันเมื่อไร ด้วยคำสั่งอะไร
เหตุผล: ภาพที่ไม่มีคำกำกับ พิสูจน์อะไรไม่ได้เลย

## ข้อจำกัดที่ยอมรับตรง ๆ

- ledger เชื่อถือได้เท่าที่ hook ทำงาน ถ้า hook ถูกปิดก็ไม่มีบันทึก **ledger จึงพิสูจน์ว่ามีอะไรเกิดขึ้น แต่พิสูจน์ไม่ได้ว่าไม่มีอะไรเกิดขึ้นนอกบันทึก**
- timestamp มาจากเครื่องตัวเอง ไม่ใช่หลักฐานเวลาที่เป็นกลาง สิ่งที่ใกล้เคียงที่สุดคือ **เวลาของ commit ที่ push ขึ้น remote** ซึ่งปลอมย้อนหลังยากกว่ามาก
- ledger บันทึก prompt แบบดิบ **ห้ามพิมพ์รหัสผ่านหรือ token ลงในแชท** เพราะมันจะลงไฟล์

## ขอบเขตความปลอดภัยกับการทดลองในโปรเจกต์นี้

ตรวจแล้วสามข้อ ก่อนออกแบบระบบนี้:

1. `evidence/` และ `scripts/` **ไม่อยู่ใน `experimentDigest()`** — เพิ่มไฟล์ที่นี่ไม่ทำให้ชุดข้อมูลแตกเป็นชุดใหม่
2. skill ส่วนตัวในเครื่อง 13 ตัว **ไม่มีตัวใดหลุดเข้า run ของการทดลองเลย** (baseline 18 ตัวที่ run มองเห็นเป็นของที่บันเดิลมากับ CLI ล้วน ทับกันเป็นศูนย์) — ติดตั้ง skill นี้จึงไม่กระทบ manifest
3. hook มี **ตัวกันชั้นเดียวที่ต้องไม่พลาด**: ledger เขียนเฉพาะใน repo ที่มีไฟล์ `evidence/.ledger-enabled` เท่านั้น fixture ไม่มีไฟล์นี้ hook จึงไม่ทำอะไรระหว่างรันการทดลอง

> **ข้อ 3 คือจุดที่ต้องระวังที่สุดของทั้งระบบ** ถ้า hook ทำงานข้างใน fixture ระหว่างเก็บข้อมูล มันจะกลายเป็นตัวแปรที่ไม่มีใครประกาศ ซึ่งคือความผิดพลาดแบบเดียวกับที่โปรเจกต์นี้พยายามกำจัดมาตลอด
