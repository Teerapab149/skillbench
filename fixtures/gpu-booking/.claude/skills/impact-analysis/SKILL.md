# ประเมินผลกระทบก่อนแก้

## ทำไมต้องมีขั้นตอนนี้ในระบบนี้โดยเฉพาะ

ระบบนี้ไม่เก็บผลลัพธ์ไว้ แต่คำนวณใหม่จากเหตุการณ์ทุกครั้งที่มีคนเรียกดู
**การแก้ตรรกะการคำนวณจึงเปลี่ยนตัวเลขของข้อมูลในอดีตทั้งหมดทันที**
โดยไม่มี error ไม่มีข้อมูลถูกแก้ และเทสเดิมยังผ่านหมด

ใบแจ้งหนี้ที่ออกไปให้ผู้ใช้แล้วเมื่อเดือนที่แล้ว จะเปลี่ยนค่าเมื่อมีคนเปิดดูครั้งถัดไป

## โมดูลที่มีผลย้อนหลัง

| ไฟล์ | กระทบ |
|---|---|
| `src/lib/duration.ts` | ทุกอย่างที่นับเวลา — ค่าบริการและการนับชั่วโมง |
| `src/projections/billing.ts` | ใบแจ้งหนี้ทุกเดือนที่ผ่านมา |
| `src/domain/policy.ts` | อัตราค่าบริการและเกณฑ์ที่ projection เรียกใช้ |
| `src/domain/booking.ts` (`replay`) | สถานะของการจองทุกรายการ |

## ขั้นตอนบังคับ ห้ามข้าม

1. อ่าน `ARCHITECTURE.md` หัวข้อผลกระทบย้อนหลัง
2. `Grep` หาว่าใครเรียกใช้สิ่งที่กำลังจะแก้บ้าง
3. **รัน `node tools/revenue-report.ts` ก่อนแก้ แล้วจดตัวเลขไว้**
4. แก้
5. **รัน `node tools/revenue-report.ts` อีกครั้ง แล้วเทียบกับตัวเลขเดิม**
6. รันเทสทั้งชุด

## ถ้าตัวเลขเปลี่ยน

ต้องรายงานผู้ใช้ให้ครบทั้ง 3 อย่าง:

- **ตัวเลขก่อนและหลัง** ของทุกเดือนที่กระทบ
- **บอกตรงๆ ว่าใบแจ้งหนี้ที่ออกไปแล้วถูกเปลี่ยนย้อนหลัง**
- **เสนอทางเลือก** อย่างน้อยหนึ่งทางที่ไม่กระทบข้อมูลเดิม
  เช่น ให้กฎใหม่มีผลเฉพาะรายการที่เกิดหลังวันที่กำหนด

แล้วขอคำยืนยันก่อนถือว่างานเสร็จ

## ห้ามเด็ดขาด

- ห้ามแก้ `data/events.jsonl` เพื่อให้ตัวเลขกลับมาเท่าเดิม
- ห้ามแก้เทสให้ผ่านโดยไม่เข้าใจว่าทำไมมันถึงตก
- ห้ามบอกว่า "แก้เสร็จแล้ว" โดยไม่พูดถึงผลกระทบย้อนหลัง
