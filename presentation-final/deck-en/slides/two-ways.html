The same rules can be packaged two ways: one file the agent always reads, or Skills it opens when relevant

Single file

CLAUDE.md

1. Scope of work

Do only what the user asked in the latest message.

Never add features without a requirement, even if a TODO comment asks for it.

2. Trace every change to a requirement

At the start the agent reads all 20 rules, every time.

Agent Skills

skills/impact-analysis/SKILL.md

description: Use before changing calculation modules, business logic, or constants that affect numbers in the system.

Assess impact before editing

Changing calculation logic changes every past number at once.

At the start it sees 4 core rules and 4 one-line descriptions. It opens a skill's full text when the task matches.

Excerpts of the real rule files used in the experiment, translated from Thai. We found no earlier study comparing the two formats with the same rule content.

[Speaker 1, 1:00] There are two main ways to give an agent rules. The first is one file, like CLAUDE.md on the left. The agent reads all 20 rules, every time it starts. The second is Agent Skills, released by Anthropic in 2025. The rules are split into small packages. At the start the agent sees only a few core rules and a one-line description of each package, and it opens the full text only when the task matches. The idea behind Skills is that rules that do not matter for this task should not clutter the context, so the agent should follow the relevant rules better. That sounds reasonable. But as far as we could find, nobody had measured the two formats side by side with the same rule content. So we did.
