## 1. สรุปความก้าวหน้าในหนึ่งย่อหน้า

ตั้งแต่รายงานครั้งที่ 1 งานเปลี่ยนจากขั้น **สอบเทียบเครื่องมือวัด** ไปเป็น
**เก็บข้อมูลเปรียบเทียบจริงครบสองชุด รวม 396 run** วิเคราะห์เสร็จทั้งคู่
และร่างรายงานครบทั้งเจ็ดบท ผลเปรียบเทียบหลัก**สรุปไม่ได้ทั้งสองชุด**
แต่เหตุผลที่สรุปไม่ได้ต่างกัน และความต่างนั้นคือสิ่งที่งานนี้เพิ่มเข้ามา

## 2. สิ่งที่ทำไปตั้งแต่รายงานครั้งที่ 1

### 2.1 การทดลองชุดที่ 1 — เก็บครบและวิเคราะห์แล้ว

ประกาศการจัดสรรไว้ 330 cell (5 กลุ่ม × 11 โจทย์ × 6 รอบ) เก็บได้จริง **220 cell**
โดยใช้**กฎสำรองที่ประกาศไว้ล่วงหน้า** ซึ่งกำหนดให้ตัดรอบเท่ากันทุกกลุ่มเมื่อชนโควตา
ทุกกลุ่มและทุกโจทย์ยังอยู่ครบ ไม่มีกลุ่มใดถูกทิ้ง

**ผลหลัก** ตัวชี้วัด `CRIT` เทียบกลุ่ม skill กับกลุ่มไฟล์เดียว

| skill | ไฟล์เดียว | ผลต่าง | 95% CI | ชนะ/แพ้/เสมอ | p |
|---:|---:|---:|---|---|---:|
| 36.4% | 27.3% | +9.1 จุด | [−6.8%, +27.3%] | 3/2/6 | **0.500** |

### 2.2 สิ่งที่ชุดที่ 1 ทำให้เห็น — เครื่องมือวัดเองเป็นตัวจำกัด

การทดสอบหลักใช้หน่วยข้อมูลเป็น**โจทย์** ไม่ใช่ run โจทย์ที่สองกลุ่มได้คะแนนเท่ากัน
จะไม่ให้ข้อมูลเลย ในชุดที่ 1 เหลือโจทย์ที่ให้ผลต่างไม่เป็นศูนย์เพียง 5 จาก 11 ข้อ

ผลคือ **ค่า p ต่ำที่สุดที่การออกแบบนี้มีทางได้เท่ากับ 0.063** ซึ่งสูงกว่าเกณฑ์ 0.05 อยู่แล้ว
**นัยสำคัญจึงเป็นไปไม่ได้ตั้งแต่ก่อนเห็นข้อมูล ไม่ว่าผลจริงจะชัดเจนเพียงใด**

สาเหตุอยู่ที่ตัวชี้วัด `CRIT` ซึ่งนับว่าผ่านก็ต่อเมื่อกฎวิกฤต 9–10 ข้อผ่านพร้อมกัน
พลาดข้อเดียวได้ศูนย์ คะแนนจึงกองที่พื้นและโจทย์ส่วนใหญ่เสมอกัน

### 2.3 การทดลองชุดที่ 2 — ซ่อมเครื่องมือวัดแล้วทำใหม่

ประกาศแผนวิเคราะห์ชุดใหม่เป็นลายลักษณ์อักษรลงวันที่ **ก่อนเก็บข้อมูลชุดที่ 2**
โดยระบุไว้ตรง ๆ ว่าเอกสารนี้เขียนหลังเห็นผลของชุดที่ 1 แล้ว และเห็นอะไรไปบ้าง

**สิ่งที่เปลี่ยน**

| | เปลี่ยนเป็น | เหตุผล |
|---|---|---|
| ตัวชี้วัดหลัก | `RCRc` | ตัวเดิมนับกฎที่**ไม่เคยถูกทดสอบ**ว่าผ่าน ซึ่งเป็นการวัดที่ผิดอยู่แล้ว |
| กลุ่มทดลอง | เพิ่ม A5 · ตัด A3 A4 | A5 คือข้อความชุดเดียวกับ skill แต่โหลดตลอดเวลา เพื่อแยกกลไกออกจากปริมาณข้อความ |
| ขนาด | 4 × 11 × 4 = 176 cell | **เก็บครบทุกช่อง ไม่ต้องใช้กฎสำรอง** |

**ผลหลัก** ตัวชี้วัด `RCRc` เทียบกลุ่ม skill กับกลุ่มไฟล์เดียว

| skill | ไฟล์เดียว | ผลต่าง | 95% CI | ชนะ/แพ้/เสมอ | p |
|---:|---:|---:|---|---|---:|
| 61.5% | 50.5% | +11.0 จุด | [−2.1%, +27.5%] | 3/2/6 | **0.250** |

### 2.4 ทำไมชุดที่ 2 ยังสรุปไม่ได้ และทำไมนั่นไม่ใช่ความล้มเหลว

หลังซ่อมเครื่องมือวัด **ค่า p ต่ำสุดที่เป็นไปได้ลดลงเหลือ 0.0625**
นัยสำคัญจึงเป็นไปได้จริงแล้ว แต่ผลที่วัดได้อยู่ที่ 0.250

> **การซ่อมได้ผลตามที่ตั้งใจ — มันย้ายอุปสรรคจาก "เป็นไปไม่ได้" ไปเป็น "ไม่พอ"**

สิ่งที่ยังขาดคือ **จำนวนโจทย์** ซึ่งเป็นข้อจำกัดที่ระบุไว้ตั้งแต่ต้นว่าหนักที่สุด
และยังหนักที่สุดอยู่หลังผ่านไปสองชุด

## 3. ข้อสังเกตที่ได้จากข้อมูล

### 3.1 กฎซื้อความสอดคล้องมาด้วยราคาคือความสำเร็จของงาน

ตัวชี้วัดของชุดที่ 2 แยกออกเป็นสองส่วนได้ และสองส่วนเดินคนละทาง

| กลุ่ม | ทำงานสำเร็จ | ตามกฎเมื่อทำสำเร็จ | ผลคูณ |
|---|---:|---:|---:|
| ไม่มีกฎเลย | **75.0%** | 0.895 | 0.671 |
| ไฟล์เดียวโหลดตลอด | 52.3% | **0.967** | 0.505 |
| skill | 63.6% | **0.967** | 0.615 |
| ข้อความเดียวกับ skill โหลดตลอด | 54.5% | **0.967** | 0.527 |

กลุ่มที่มีกฎทุกกลุ่มตามกฎได้ดีกว่าและได้**เท่ากันหมด** ขณะที่กลุ่มที่ไม่มีกฎ
ทำงานสำเร็จมากที่สุด

**ข้อจำกัดที่ต้องระบุคู่กัน:** ไม่ได้ทดสอบทางสถิติ · การทดสอบแต่ละส่วนแยกกัน
ไม่ได้ประกาศไว้ล่วงหน้าจึงเพิ่มทีหลังไม่ได้ · และกลุ่มที่ไม่มีกฎถูกประกาศไว้
ว่าเป็นกลุ่มเชิงพรรณนา **ข้อสังเกตนี้จึงเป็นสมมติฐานที่ข้อมูลชี้ทาง ไม่ใช่ข้อสรุป**

### 3.2 กลไกโหลดตามเงื่อนไขทำงานตามที่โฆษณา

ความแม่นของการยิง skill ในชุดที่ 2: `trace-to-requirement` = 1.000 ·
`acceptance-first` = 0.842 · `impact-analysis` = 0.872

**skill ถูกโหลดตรงจังหวะที่ควรโหลด แต่ผลปลายทางไม่ขยับพอให้วัดได้**
ปัญหาจึงไม่ได้อยู่ที่การส่งกฎถึงเอเจนต์

## 4. เหตุการณ์ระหว่างเก็บข้อมูลและกลไกที่จับได้

งานนี้ตรวจตัวแปรควบคุม**ทุก run** ไม่ใช่ประกาศไว้เฉย ๆ และกลไกนั้นจับของได้จริงสามเรื่อง
ที่ไม่มีใครคาดไว้ตั้งแต่ต้น

| สิ่งที่เกิด | ผลต่อข้อมูล |
|---|---|
| ชุด skill ที่ติดมากับเครื่องมือเปลี่ยนเอง 18 → 15 → 18 | run ที่สภาพไม่ตรงถูกปฏิเสธ ไม่เข้าชุดข้อมูล |
| เอเจนต์เรียก skill ในกลุ่มที่ไม่ได้ติดตั้ง skill (12 ครั้ง) | ไม่มี skill ใดโหลดสำเร็จ จึงไม่ปนเปื้อน · รายงานจำนวนครั้งไว้ตามที่ผูกมัด |
| **เอเจนต์เขียนกฎของการทดลองลงหน่วยความจำถาวรนอกพื้นที่ทดลอง** | จับได้ทันทีที่ run นั้นจบ หยุดทั้งชุด run ถูกปฏิเสธ **ไม่มี run ถัดไปได้อ่าน** |
| ระบบถูกยุติกลางคันโดยไม่ทราบสาเหตุ 4 ครั้ง · ชนโควตาหลายครั้ง | ไม่เสียข้อมูลที่เก็บแล้วแม้แต่ run เดียว |

เรื่องที่สามร้ายแรงที่สุด — ไฟล์ที่เอเจนต์เขียนมีทั้ง**สรุปกฎของกลุ่มหนึ่ง**
และ**เฉลยของโจทย์ข้อที่ไม่มีเอเจนต์ตัวใดทำสำเร็จเลย** ถ้า run ถัดไปได้อ่าน
ตัวแปรต้นของการทดลองจะพังทันทีโดยไม่มีใครรู้ และตัวเลขจะดูปกติทุกประการ

**ข้อที่ต้องระบุตามตรง:** กลไกจับได้เพราะมีคนเผื่อไว้ล่วงหน้าว่าหน่วยความจำอัตโนมัติ
เป็นตัวแปรที่ต้องคุม **เราไม่มีทางรู้ว่ายังมีช่องทางแบบเดียวกันที่ยังไม่มีใครนึกถึงอีกกี่ช่อง**

## 7. ข้อจำกัดที่ยอมรับล่วงหน้า

1. **จำนวนโจทย์เป็นเพดานของกำลังการทดสอบ** ไม่ใช่จำนวนรอบ — หน่วยข้อมูลคือโจทย์
   การเพิ่มรอบทำให้ค่าประมาณแม่นขึ้นแต่ไม่เพิ่มกำลังการทดสอบ
2. **ตัวชี้วัดหลักของชุดที่ 2 ถูกเปลี่ยนหลังเห็นผลของชุดที่ 1** แม้จะมีด่านพิสูจน์
   ที่ล้มได้รองรับ และมีหลักฐานว่าการเปลี่ยนไม่ได้ขับเคลื่อนด้วยผล
   ข้อนี้ต้องระบุทุกครั้งที่อ้างผลของชุดที่ 2
3. **ตัวชี้วัด `RCRc` ตอบคำถามว่า "ทำงานได้ไหม" มากกว่า "ตามกฎแค่ไหน"** —
   วัดได้ว่ามันเท่ากับผลของเทสยอมรับเป๊ะใน 74.3% ของ run
4. **ผู้วิจัยเป็นผู้ออกแบบทั้งกฎ โจทย์ และตัวตรวจ** สมมติฐานที่ผิดร่วมกัน
   ระหว่างกฎกับตัวตรวจ กลไกอัตโนมัติทั้งหมดจับไม่ได้
5. **ขอบเขตการสรุปแคบ** — โมเดลเดียว เครื่องมือรุ่นเดียว โครงงานจำลองเดียว กฎชุดเดียว
6. **ชุดที่ 2 ไม่มีข้อสรุปเรื่องความทนทานต่อการฉีดคำสั่ง** เพราะตัดกลุ่มนั้นออก
   ผลเรื่องนี้มีเฉพาะในชุดที่ 1 และห้ามนำมารวมกัน
