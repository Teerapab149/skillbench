## สไลด์ 5 — สไลด์สำคัญที่สุด: เหตุผลที่สรุปไม่ได้ ต่างกัน

```
ชุดที่ 1   สรุปไม่ได้เพราะ  " เป็นไปไม่ได้ "
           p ต่ำสุดที่ออกแบบนี้ทำได้ = 0.063  ซึ่งสูงกว่า 0.05 อยู่แล้ว
           → ต่อให้ผลชัดแค่ไหน ก็ไม่มีทางผ่าน

ชุดที่ 2   สรุปไม่ได้เพราะ  " ไม่ถึง "
           หลังซ่อมเครื่องมือวัด p ต่ำสุด = 0.0625  ผ่านได้จริง
           → แต่ผลที่วัดได้อยู่ที่ 0.250
```

**การซ่อมได้ผล — มันย้ายอุปสรรคจาก "เป็นไปไม่ได้" มาเป็น "ไม่พอ"**
สิ่งที่ยังขาดคือจำนวนโจทย์ ไม่ใช่เครื่องมือวัดอีกต่อไป

## สไลด์ 8 — สิ่งที่ระบบจับได้ระหว่างเก็บข้อมูล

เล่าเป็นเรื่อง ไม่ต้องลงรายละเอียด — นี่คือสไลด์ที่แสดงว่างานนี้คุมตัวแปรจริง

1. **ชุด skill ของเครื่องมือเปลี่ยนเอง** 18 → 15 → 18 โดยไม่มีใครติดตั้งอะไร
2. **เอเจนต์เรียก skill ที่ไม่มีอยู่** ในกลุ่มที่ไม่ได้ติดตั้ง skill (12 ครั้ง โหลดได้ 0)
3. **เอเจนต์เขียนกฎของการทดลองลงหน่วยความจำถาวรนอกพื้นที่ทดลอง** —
   ไฟล์หนึ่งสรุปกฎของกลุ่ม A1 อีกไฟล์บอกเฉลยของโจทย์ข้อที่ยากที่สุด
4. ระบบถูกยุติกลางคันโดยไม่ทราบสาเหตุ 4 ครั้ง · ชนโควตาอีกหลายครั้ง

**ทั้งหมดถูกจับได้และหยุดทันที ไม่มี run ปนเปื้อนเข้าชุดข้อมูลเลยแม้แต่ run เดียว**

## สไลด์ 11 (ถ้ามีเวลา) — สิ่งที่งานนี้ให้ไว้จริง

เมื่อผลเปรียบเทียบสรุปไม่ได้ทั้งสองชุด สิ่งที่เหลือเป็นผลงานคือ **วิธีวัดและเครื่องมือ**

- คุมเนื้อหากฎให้เท่ากันโดยตรวจด้วยเครื่อง ไม่ใช่ด้วยคำยืนยัน
- ตรึงสภาพเครื่องมือแล้วตรวจซ้ำทุก run — จับได้จริงสามเรื่องที่ไม่มีใครคาดไว้
- ตัวชี้วัดที่มีด่านพิสูจน์ตัวเองและ**ล้มได้** (และเคยล้มจริง)
- ทุกตัวเลขมีต้นทางเดียว มีด่านกันเอกสารไม่ตรงข้อมูล
