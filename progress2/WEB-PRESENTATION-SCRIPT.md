# บทพูดนำเสนอความก้าวหน้าครั้งที่ 2 — เว็บไซต์ SkillBench

**เวลาเป้าหมาย: 10–12 นาที** (ไม่รวมถาม–ตอบ)  
**เว็บไซต์:** <https://teerapab149.github.io/skillbench/progress2/>

เอกสารนี้เขียนให้เปิดอ่านและพูดตามได้จริง ใช้ข้อความในบล็อกคำพูดเป็นคำพูดหลัก ส่วนข้อความในวงเล็บเหลี่ยมเป็นคำสั่งสำหรับผู้นำเสนอ **ไม่ต้องอ่านออกเสียง**

## ก่อนเริ่ม

- เปิดเว็บไซต์ไว้ที่หน้าแรก และซูม browser ราว 90–100%
- ใช้เมนูด้านซ้ายเปลี่ยนหน้า อย่า scroll หาเนื้อหาระหว่างพูด
- หน้าภาคผนวกเปิดเฉพาะเมื่ออาจารย์ถาม
- ประโยคที่ต้องจำให้ได้ตลอดการนำเสนอคือ: **“ยังสรุปไม่ได้ ไม่ได้แปลว่าไม่ต่างกัน”**

## 1 · บอกไว้ vs เกิดขึ้นจริง — 1 นาที 15 วินาที

[อยู่หน้าแรก/กด `1 · บอกไว้ vs เกิดขึ้นจริง`]

**หน้าที่ของหน้านี้:** เชื่อมจากการนำเสนอครั้งแรก และเปิดเผยการเปลี่ยนแปลงของแผนก่อนที่อาจารย์จะถาม

> “รอบที่แล้วผมจบที่เครื่องมือวัดเสร็จ แต่ยังเปรียบเทียบไม่ได้ครับ ตอนนั้นเก็บได้ 64 run ซึ่งเป็น calibration ไม่ใช่ข้อมูลสำหรับตอบคำถามหลัก
>
> ระหว่างเก็บพบว่าเพดาน 25 turn ไปตัด A2 ก่อนทำงานเสร็จ A2 ใช้ turn มากกว่าใน 9 จาก 11 โจทย์ ถ้าฝืนเอาข้อมูลนั้นมาเทียบ ผลจะสะท้อนเพดานที่เราตั้งเอง ไม่ใช่พฤติกรรมของ AI
>
> หลังจากนั้นจึงเพิ่มเพดาน เก็บข้อมูลใหม่ ล็อกโมเดล และตอนนี้เปรียบเทียบ A2 กับ A1 ได้ครบทั้งสองชุดแล้ว รวม 396 run”

[ชี้การ์ดสถานะ 4 ใบ แล้วชี้ตารางเฉพาะ 3 แถว]

> “ตารางนี้คือสิ่งที่รายงานไว้ครั้งก่อนเทียบกับสิ่งที่เกิดขึ้นจริงครับ จุดสำคัญมีสามอย่าง
>
> หนึ่ง ข้อมูลจาก 64 run เพิ่มเป็น 396 run ที่เปรียบเทียบได้
>
> สอง ชุดแรกตั้งใจเก็บ 9 รอบต่อโจทย์ แต่ชน quota และจบที่ 4 รอบ ส่วนชุดที่สองจึงประกาศ 4 รอบไว้ล่วงหน้าก่อนเริ่มเก็บ
>
> สาม เราเพิ่มรอบทดลองที่สอง และเพิ่ม A5 เพื่อแยกให้ได้ว่า ผลที่เห็นมาจากกลไก skill หรือแค่มาจากข้อความของกฎที่ต่างกันครับ”

**ประโยคเปลี่ยนหน้า**

> “แต่การเพิ่มข้อมูลอย่างเดียวไม่พอ เพราะระหว่างทางเราพบว่าตัววัดของรอบแรกเองก็ยังมีข้อจำกัดครับ”

## 2 · ทำไมต้องมีรอบที่สอง — 40 วินาที

[กด `2 · ทำไมต้องมีรอบที่สอง`]

**หน้าที่ของหน้านี้:** ให้เห็นภาพว่าปัญหาของคะแนนแบบเดิมคือคะแนนกองที่ศูนย์

> “หน้านี้แสดงผลรายโจทย์ แต่ละคอลัมน์คือโจทย์หนึ่งข้อ และแต่ละขีดคือหนึ่ง run
>
> ปัญหาของรอบแรกคือหลายโจทย์ A1 กับ A2 ได้ศูนย์เท่ากัน ถ้าสองฝ่ายได้ศูนย์ทั้งคู่ เราจะยังตอบไม่ได้เลยว่าพฤติกรรมของมันเหมือนกันจริง หรือแค่เครื่องมือวัดหยาบเกินไปจนมองไม่เห็นความต่าง
>
> เพราะฉะนั้นรอบสองจึงไม่ได้แค่เก็บใหม่ แต่ต้องแก้วิธีให้คะแนนด้วยครับ”

**อย่า** อธิบายตารางเปลี่ยนแผนในหน้านี้ซ้ำกับหน้าแรก

## 3 · ทำไมเปลี่ยนวิธีให้คะแนน — 1 นาที 30 วินาที

[กด `3 · ทำไมเปลี่ยนวิธีให้คะแนน`]

**หน้าที่ของหน้านี้:** อธิบาย CRIT และ RCRc ให้ชัดที่สุด นี่คือหน้าที่อาจารย์น่าจะถามมากที่สุด

> “รอบแรกใช้ CRIT ครับ คือดูว่ากฎวิกฤตผ่านครบทุกข้อไหม ผ่านครบได้ 1 แต่พลาดเพียงข้อเดียวได้ 0 ไม่มีคะแนนระหว่างกลาง
>
> เปรียบเหมือนข้อสอบที่ต้องถูกทุกข้อถึงผ่าน คนที่ถูก 7 จาก 8 ข้อ กับคนที่ไม่ถูกเลย ได้ศูนย์เหมือนกัน แบบนี้จึงแยกความต่างของพฤติกรรมไม่ได้
>
> รอบสองจึงใช้ RCRc ซึ่งนับสัดส่วนของกฎวิกฤตที่เข้าเงื่อนไขและทำตามได้ เช่นทำได้ 7 จาก 8 ข้อ จะได้ 0.875 ไม่ใช่ศูนย์”

[หยุดเล็กน้อย แล้วชี้คำว่า “แต่ต้องทำงานสำเร็จก่อน”]

> “แต่ RCRc ไม่ได้ผ่อนเกณฑ์ครับ ถ้างานหลักไม่สำเร็จ คะแนนจะเป็นศูนย์ทันที ไม่ว่าจะทำตามกฎย่อยได้มากแค่ไหน เพื่อไม่ให้ AI ที่ไม่ทำอะไรเลยได้คะแนนสูงเพียงเพราะยังไม่ได้ละเมิดกฎ
>
> งานสำเร็จหรือไม่ ตัดสินด้วย acceptance test ที่เขียนไว้ก่อนเก็บข้อมูล และเอเจนต์มองไม่เห็นครับ”

**ประโยคบังคับพูด**

> “ดังนั้น 36.4% ของรอบแรกกับ 61.5% ของรอบสอง **เทียบข้ามกันไม่ได้** เพราะเป็นคนละไม้บรรทัด สิ่งที่เทียบได้คือ A2 กับ A1 ภายในรอบเดียวกันเท่านั้นครับ”

**ถ้าโดนถามว่าเปลี่ยน metric เพื่อให้ผลสวยหรือไม่**

> “เปลี่ยนหลังเห็นข้อจำกัดของรอบแรกจริงครับ จึงประกาศแผนใหม่ก่อนเก็บข้อมูลรอบสอง รายงานผลรอบแรกไว้ครบ และตั้งด่านทดสอบตัววัดใหม่ไว้ก่อนใช้ เพื่อไม่ให้เปลี่ยนกติกาเพียงเพราะไม่ชอบผลเดิมครับ”

## 4 · ผลการเปรียบเทียบ — 1 นาที 30 วินาที

[กด `4 · ผลการเปรียบเทียบ`]

**หน้าที่ของหน้านี้:** ตอบคำถามวิจัยหลัก โดยไม่อ้างเกินข้อมูล

> “คำถามหลักของงานคือ ถ้ากฎเนื้อหาเดียวกันทุกตัวอักษร แต่ A1 ยัดไว้ในไฟล์เดียวที่โหลดตลอดเวลา และ A2 แยกเป็น skill ที่โหลดตามงาน ผลต่างกันไหม
>
> เราจึงเทียบ A2 กับ A1 เป็นคู่หลัก เพราะคู่นี้ต่างกันที่วิธีส่งกฎเข้า context ไม่ใช่เนื้อหาของกฎ”

[ชี้แผนภาพ 44 run → 11 โจทย์ → ผลต่าง]

> “แม้แต่ละฝั่งมี 44 run แต่เราเฉลี่ย run ของโจทย์เดียวกันก่อน แล้วจึงเปรียบเทียบเป็น 11 โจทย์ เพราะ 4 run ของโจทย์เดียวกันไม่ใช่ข้อมูลอิสระ 4 ชิ้นครับ”

[ชี้ตารางผล]

> “ผลออกมาว่า A2 นำ A1 ทั้งสองรอบ รอบแรกต่าง 9.1 จุด และรอบสองต่าง 11.0 จุด
>
> แต่รอบสองมีช่วงความเชื่อมั่นตั้งแต่ลบ 2.1 ถึงบวก 27.5 และ p เท่ากับ 0.250 จึงยังคร่อมทั้งกรณีที่ A2 นำและกรณีที่ A2 อาจตามอยู่ครับ”

**สรุปให้ชัด**

> “ข้อสรุปที่ถูกต้องตอนนี้คือ skill มีทิศทางนำ แต่หลักฐานยังไม่แรงพอให้บอกว่า skill ดีกว่าอย่างมีนัยสำคัญ ไม่ใช่ว่าเราพบว่า ‘สองวิธีไม่ต่างกัน’ ครับ”

## 5 · ทำไมยังฟันธงไม่ได้ — 1 นาที 15 วินาที

[กด `5 · ทำไมยังฟันธงไม่ได้`]

**หน้าที่ของหน้านี้:** ตอบคำถามว่า “มี 176 run แล้วทำไมยังไม่พอ?”

> “รอบสองมี 176 run ก็จริง แต่หน่วยวิเคราะห์ของเราไม่ใช่ 176 ครับ หน่วยที่แท้จริงคือ 11 โจทย์ เพราะ run ที่มาจากโจทย์เดียวกันมีเงื่อนไขเดียวกันและผลคล้ายกัน
>
> เปรียบเหมือนถามคน 4 คนในบ้านเดียวกัน ไม่เท่ากับถามคนจาก 4 บ้าน จำนวนบ้านคือหน่วยข้อมูลจริง ไม่ใช่จำนวนคน”

[ชี้ `m = 5`]

> “จาก 11 โจทย์ มีเพียง 5 โจทย์ที่ A2 กับ A1 ต่างกัน ส่วนที่เหลือเสมอกัน จึงไม่ให้ข้อมูลกับการทดสอบแบบ sign-flip
>
> ที่ m เท่ากับ 5 ต่อให้ A2 ชนะทั้ง 5 ข้อ ค่า p ต่ำสุดที่เป็นไปได้ยังเป็น 0.0625 ซึ่งสูงกว่าเกณฑ์ 0.05 อยู่แล้วครับ”

**สรุป**

> “เพราะฉะนั้นคอขวดของงานนี้ไม่ใช่จำนวน run ต่อโจทย์ แต่คือจำนวนโจทย์ที่ให้ข้อมูล หากจะต่อยอด ควรเพิ่ม scenario มากกว่ารันโจทย์เดิมซ้ำครับ”

## 6 · กฎเปลี่ยนพฤติกรรมจริง — 55 วินาที

[กด `6 · กฎเปลี่ยนพฤติกรรมจริง`]

**หน้าที่ของหน้านี้:** แสดงสิ่งที่น่าสนใจในข้อมูลโดยติดป้ายว่าเป็นข้อสังเกต ไม่ใช่ข้อสรุปหลัก

> “แม้ผลหลักยังฟันธงไม่ได้ แต่ข้อมูลมีสัญญาณพฤติกรรมที่น่าสนใจในโจทย์ผลกระทบซ่อนเร้นครับ
>
> ระบบนี้เก็บเหตุการณ์แล้วคำนวณยอดย้อนหลังใหม่ทุกครั้ง ถ้าแก้สูตรวันนี้ ใบแจ้งหนี้เดือนก่อนอาจเปลี่ยนตามโดยไม่มี error ฟ้องเลย
>
> กลุ่มไม่มีกฎไม่เคยไปรันตรวจผลกระทบเลย 0 จาก 8 run แต่สามกลุ่มที่มีกฎรวมกันตรวจ 19 จาก 24 run และรายงานผลกระทบให้ผู้ใช้ 23 จาก 24 run”

**ต้องตามด้วยข้อจำกัดทันที**

> “แต่ส่วนนี้เป็นข้อสังเกตเชิงพรรณนาเท่านั้นครับ เราไม่ได้ประกาศล่วงหน้าว่าจะทดสอบกฎรายข้อ และจำนวนข้อมูลต่อกลุ่มยังเล็ก จึงใช้เป็นหลักฐานตั้งต้นสำหรับงานต่อยอด ไม่ใช่ข้อสรุปยืนยันครับ”

## 7 · วินัยแลกกับงานที่เสร็จ — 50 วินาที

[กด `7 · วินัยแลกกับงานที่เสร็จ`]

**หน้าที่ของหน้านี้:** แสดง trade-off อย่างสมดุล ไม่เชียร์ skill ข้างเดียว

> “RCRc แยกออกเป็นสองเรื่อง คือ งานสำเร็จไหม และเมื่อสำเร็จแล้วทำตามกฎได้แค่ไหน
>
> กลุ่มที่มีกฎทำตามกฎได้ใกล้กันมากเมื่อปิดงานสำเร็จ แต่ความต่างสำคัญอยู่ที่โอกาสปิดงาน
>
> A0 ที่ไม่มีกฎปิดงานได้บ่อยกว่า แต่หน้าก่อนแสดงว่ากลุ่มนี้ไม่ค่อยตรวจผลกระทบของข้อมูลเก่าเลย การปิดงานเร็วในกรณีนี้จึงไม่ได้แปลว่าปลอดภัยหรือดีกว่าครับ”

> “ภาพที่ข้อมูลบอกจึงเป็น trade-off: กฎอาจช่วยให้ AI มีวินัยขึ้น แต่มีต้นทุนต่อการปิดงาน ซึ่งเป็นสิ่งที่ต้องเปิดเผย ไม่ควรเลือกเล่าเพียงด้านใดด้านหนึ่ง”

---

## 8 · คุมตัวแปรยังไง — 45 วินาที

[กด `8 · คุมตัวแปรยังไง`]

**หน้าที่ของหน้านี้:** แสดงว่าการคุมตัวแปรทำงานจริง ไม่ใช่คำกล่าวในระเบียบวิธี

> “การคุมตัวแปรในงานนี้มีหลักฐานที่ตรวจจับได้จริงครับ ระหว่างเก็บข้อมูล มีเอเจนต์หนึ่งเขียน memory ออกนอกพื้นที่ทดลอง ซึ่งหาก run ถัดไปอ่านได้ ก็จะเกิดการปนเปื้อนข้ามกลุ่ม
>
> ระบบจับได้ทันที หยุดชุดนั้น ปฏิเสธ run และไม่มี run ถัดไปได้ใช้ข้อมูลนั้นครับ”

> “อีกด้าน เราตรวจ manipulation check ว่า A2 โหลด skill ถูกจังหวะหรือไม่ ผล F1 เท่ากับ 1.000 หมายความว่าการส่ง skill ทำงานถูกทุกครั้ง จึงไม่ใช่กรณีที่ผลไม่ต่างเพราะระบบไม่เคยส่งกฎถึงเอเจนต์ครับ”

---

## 9 · สิ่งที่พลาด — 45 วินาที

[กด `9 · สิ่งที่พลาด`]

**หน้าที่ของหน้านี้:** รับผิดชอบข้อจำกัดเองก่อนโดนถาม

> “สิ่งที่พลาดชัดที่สุดคือ รอบแรกผมรายงานเองว่าทางออกคือเพิ่มจำนวนโจทย์ ไม่ใช่เพิ่มจำนวนรอบ แต่ตอนออกแบบรอบสองผมยังใช้ 11 โจทย์เดิม
>
> สำหรับชุดใหม่ เราสามารถเพิ่มโจทย์ได้โดยไม่ทำให้ข้อมูลชุดเดิมเสียสมดุล แต่ผมเลือกไม่เพิ่มเพราะเวลาและ quota ซึ่งเมื่อมองย้อนกลับไปเป็นการตัดสินใจที่ไม่ดีครับ”

> “การเพิ่มโจทย์ไม่ได้รับประกันว่าจะได้ผล significant แต่จะเพิ่มโอกาสให้การทดสอบมีข้อมูลเพียงพอ นี่จึงเป็นข้อเสนอแนะอันดับแรกสำหรับงานต่อยอดครับ”

# ภาคผนวก — เปิดเมื่อถูกถามเท่านั้น

## ถามว่า “A1 กับ A2 ต่างกันจริงตรงไหน?”

[เปิด `กฎที่ส่งให้เอเจนต์`]

> “A1 กับ A2 มีกฎเนื้อหาเดียวกันครับ A1 รวมไว้ในไฟล์เดียวและโหลดทุกงาน ส่วน A2 แยกกฎเป็น skill และโหลดเมื่อเข้าเงื่อนไข จึงเป็นการทดสอบวิธีจัดส่งกฎเข้า context ไม่ใช่การเปรียบเทียบว่าใครได้คำสั่งดีกว่ากัน”

## ถามว่า “โจทย์วัดอะไรบ้าง?”

[เปิด `โจทย์ทั้ง 11 ข้อ`]

> “โจทย์มี 11 ข้อ: งานปกติ 3 ข้อ และกับดัก 5 ตระกูลรวม 8 ข้อ กับดักไม่ได้วัดว่า AI เขียนโค้ดเก่งไหม แต่วัดว่ามันทำเกินคำสั่ง มองข้ามผลกระทบ หรือเดาแทนการถามหรือไม่ครับ”

## ถามว่า “ตรวจสอบย้อนกลับได้ไหม?”

[เปิด `ไล่ดู run ทีละตัว`]

> “ได้ครับ ทุก run มีไฟล์ที่แก้ คำสั่งที่รัน ข้อความตอบ และผลตรวจของกฎแต่ละข้อ สามารถเปิดย้อนดูระดับ run ได้เลย รวมถึงคำสั่งที่ใช้เก็บและวิเคราะห์ข้อมูลจริงครับ”

# คำตอบสั้นสำหรับคำถามที่น่าจะโดน

## “สรุปแล้ว A1 หรือ A2 ดีกว่า?”

> “ยังตอบไม่ได้อย่างยืนยันครับ A2 นำ A1 ทั้งสองรอบราว 9–11 จุด แต่ช่วงความเชื่อมั่นยังคร่อมศูนย์ จึงมีเพียงทิศทาง ไม่ใช่หลักฐานพอจะฟันธง”

## “เปลี่ยนตัวชี้วัดหลังเห็นผล ไม่ผิดหลักหรือ?”

> “ถ้าเปลี่ยนเพื่อไล่หาผลสวยจะผิดครับ กรณีนี้เราเปิดเผยว่าเห็นผลเดิมแล้ว เปลี่ยนเพราะพบข้อบกพร่องของการวัด ประกาศแผนใหม่ก่อนเก็บรอบสอง และเก็บผลรอบแรกไว้ครบ จึงให้ผู้อ่านตรวจสอบได้ครับ”

## “ทำไมไม่เพิ่มโจทย์ตั้งแต่รอบสอง?”

> “เป็นข้อผิดพลาดของการออกแบบรอบสองครับ ตอนนั้นตัดสินใจตามข้อจำกัดเวลาและ quota แต่เมื่อมองย้อนกลับไป การเพิ่ม scenario น่าจะสำคัญกว่าการเพิ่ม run ของโจทย์เดิม ผมบันทึกไว้เป็นข้อจำกัดและข้อเสนอสำหรับงานต่อยอดแล้วครับ”

## “ผลไม่ significant แล้วงานได้อะไร?”

> “งานตอบได้ว่าการทดลองต้องใช้ scenario ที่ให้ข้อมูลมากกว่านี้, ระบบ skill ถูกส่งถึงเอเจนต์จริง, มีสัญญาณเชิงพฤติกรรมที่กฎช่วยให้ AI ตรวจผลกระทบมากขึ้น, และเปิดเผย trade-off ระหว่างวินัยกับโอกาสปิดงานครับ ส่วนคำถามว่าแบบไหนดีกว่า ยังตอบไม่ได้อย่างซื่อตรงครับ”
