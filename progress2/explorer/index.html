ทำไมต้องมีรอบที่สอง — วิธีให้คะแนนของเราเองยังมีปัญหา

ตัวชี้วัดของรอบแรกบังคับว่าต้องผ่านกฎวิกฤต ครบทุกข้อ ถึงจะได้คะแนน พลาดข้อเดียวได้ศูนย์ คะแนนเลยไปกองอยู่ที่ศูนย์ และเมื่อกองที่ศูนย์ โจทย์ส่วนใหญ่ก็ได้เท่ากันทั้งสองกลุ่ม ซึ่งไม่บอกอะไรเราเลยว่ากลุ่มไหนดีกว่า

แต่ละแถวคือกลุ่มทดลอง แต่ละคอลัมน์คือโจทย์ 1 ข้อ ในช่องมี 4 ขีดคือรัน 4 รอบ · คลิกที่ขีดใดก็ได้เพื่อเปิด run นั้น

อย่าพูดเกินกว่าที่ภาพแสดง รอบที่ 2 ให้คะแนนเป็นสัดส่วนแล้วก็จริง แต่ มันไม่ได้แก้ให้หาย แค่พอทำให้ค่า p ขยับ ส่วนจำนวนโจทย์ที่ให้ข้อมูลยังเท่าเดิม ซึ่งเป็นตัวที่ตัดสินจริง
เปลี่ยนตัวชี้วัดสองครั้งแล้ว กันตัวเองไว้สามชั้น หนึ่ง เหตุผลที่เปลี่ยนไม่ใช่เพราะผลไม่สวย แต่เพราะตัวเดิมนับกฎที่ไม่เคยถูกทดสอบเลยว่าผ่าน ซึ่งเป็นการวัดที่ผิดอยู่แล้ว ควรซ่อมไม่ว่าผลจะออกทางไหน · สอง ตั้งด่านทดสอบที่ล้มได้ เอาเอเจนต์ปลอมสามแบบป้อนเข้าไป แบบที่สำคัญที่สุดคือตัวที่ ทำงานสำเร็จจริงแต่ละเมิดกฎห้ามทุกข้อ ต้องได้ไม่เกิน 0.50 · สาม ประกาศแผนใหม่ลงวันที่ก่อนเก็บข้อมูล และเขียนตรง ๆ ว่าเขียนหลังเห็นผลรอบแรกแล้ว

และที่สำคัญที่สุด — ผลทั้งสองรอบยังสรุปไม่ได้เหมือนกัน การเปลี่ยนไม่ได้ทำให้ผลสวยขึ้น

ทำไมต้องจับกลุ่มตามโจทย์ก่อน 4 run ของโจทย์เดียวกันไม่เป็นอิสระต่อกัน — โจทย์เดียวกัน สภาพเดียวกัน ผลคล้ายกัน ถ้านับเป็น 44 ชิ้นอิสระ จะหลอกตัวเองว่ามีข้อมูลเยอะกว่าความจริง แล้วได้ p ที่เล็กเกินจริง
สองรอบให้คะแนนคนละแบบ ตัวเลขข้ามแถวเทียบกันไม่ได้ ดูได้เฉพาะคอลัมน์ “ต่างกัน” ซึ่งเป็นการเทียบภายในรอบเดียวกัน · ช่วงความเชื่อมั่นคร่อมศูนย์ทั้งคู่ → ต้องพูดว่า “สรุปไม่ได้” ไม่ใช่ “ไม่ต่างกัน” เพราะ “ไม่ต่างกัน” แปลว่าพิสูจน์แล้วว่าเท่ากัน ซึ่งเราไม่ได้พิสูจน์ เราแค่ยังแยกไม่ออก

ตัวชี้วัดสองตัวนี้คืออะไร

CRIT — ตัวชี้วัดของรอบที่ 1

กฎระดับวิกฤตในโจทย์นั้น ผ่านครบทุกข้อหรือไม่ ตอบได้แค่ 0 หรือ 1 · เป็นการ “และ” กันของกฎวิกฤต 9–10 ข้อ พลาดข้อเดียวได้ศูนย์

เลข 36.4% คือสัดส่วนของ run ที่ A2 ได้ 1

RCRc — ตัวชี้วัดของรอบที่ 2

สัดส่วนกฎวิกฤตที่เข้าเงื่อนไขและผ่าน โดยมีเงื่อนไขว่างานหลักต้องสำเร็จ · ถ้างานหลักไม่สำเร็จค่าเป็น 0 · ถ้าวัดความสำเร็จไม่ได้ค่าเป็น null และ run นั้นออกจากการคำนวณ

“งานหลักสำเร็จ” ตัดสินด้วยเทสยอมรับที่เอเจนต์มองไม่เห็น

ทำไมต้องเปลี่ยน — ตัวเดิมมีข้อบกพร่องสองชั้น ชั้นที่ 1 กฎประเภท “ห้าม” เป็นจริงเสมอถ้าไม่ทำอะไรเลย เอเจนต์สังเคราะห์ที่นิ่งสนิทได้ RCR ราว 0.51–0.55 · ชั้นที่ 2 ตัวชี้วัดให้รางวัลกับการลงมือทำ ไม่ใช่การทำถูก — artifact ปลอมที่ทำงานไม่สำเร็จเลยยังได้ RCRa 0.69 เทียบกับ run จริงราว 0.87

ข้อจำกัดที่ต้องเปิดเผยคู่กันเสมอ วัดจากชุดที่ 1 พบว่า RCRc ให้ค่าตรงกับผลของเทสยอมรับเป๊ะใน 74.3% ของ run แปลว่ามันตอบคำถาม “ทำงานได้ไหม” มากกว่า “ตามกฎแค่ไหน”

ต้นตอมีข้อเดียว — ความเสี่ยงที่รายงานไว้เมื่อ 14 ส.ค. เกิดขึ้นจริง

คลิกแถวใดก็ได้เพื่อดูโจทย์ข้อนั้นและ run ทั้งสี่รอบของทั้งสองกลุ่ม

พูดให้ตรง ไม่พูดเกิน เงื่อนไขนี้ ประกาศไว้ก่อนเก็บข้อมูล ว่าถ้า m ต่ำกว่า 6 นัยสำคัญจะเป็นไปไม่ได้ พอ m ออกมาเป็น 5 ผลก็ถูกล็อกทันที ก่อนจะดูค่า p ด้วยซ้ำ
ก่อนเก็บข้อมูล แผนประเมินไว้ว่า m ≈ 6 ซึ่งให้ p ต่ำสุด 0.031 และผ่านเกณฑ์ได้ จึงพูดว่า “เป็นไปไม่ได้ตั้งแต่ก่อนเห็นข้อมูล” ไม่ได้ — สิ่งที่ล็อกไว้ล่วงหน้าคือกติกา ไม่ใช่ผล
ระวังเลข ICC ที่รายงานอาจารย์ไว้เมื่อ 14 ส.ค. ว่า 0.335 นั้นวัดจาก Opus ตอน calibration และ PRE-REGISTRATION.md เขียนห้ามไว้ตรง ๆ ว่าห้ามใช้อ้าง power ของ Sonnet ค่าที่วัดจากข้อมูลจริงของงานนี้คือ

โจทย์ S08 กับ S09 เป็นตระกูลผลกระทบซ่อนเร้น — ระบบเก็บข้อมูลแบบ event sourcing แปลว่า แก้สูตรคำนวณวันนี้ ใบแจ้งหนี้ของเดือนที่แล้วจะเปลี่ยนตามไปด้วย กฎสองข้อในตระกูลนี้สั่งให้ต้องไปตรวจและต้องบอกผู้ใช้

เป็นข้อสังเกต ไม่ใช่ข้อสรุป ยังไม่ได้ทดสอบทางสถิติ และไม่ได้ประกาศไว้ล่วงหน้าว่าจะแยกดูกฎรายข้อ จึงเพิ่มการทดสอบทีหลังไม่ได้ · A0 ถูกประกาศไว้ตั้งแต่ต้นว่าเป็นกลุ่มเชิงพรรณนา · n = 8 ต่อกลุ่ม เล็กมาก
เขียนไว้ในเล่มว่าเป็นสมมติฐานที่ข้อมูลชี้ทาง และเสนอให้งานต่อยอดเอาไปตั้งเป็นสมมติฐานหลักแล้วเก็บใหม่

กฎซื้อความมีวินัย ด้วยราคาคืองานที่เสร็จน้อยลง

แกะ RCRc ออกเป็นสองชิ้น เพราะมันคือการคูณกันของสองอย่าง — ทำงานสำเร็จแค่ไหน คูณ เมื่อสำเร็จแล้วตามกฎแค่ไหน

ลองคูณดูได้เลย · คอลัมน์ขวาสุดคือ RCRc ที่ใช้เป็นตัวชี้วัดหลัก

A0 ได้คะแนนรวมสูงสุด แต่ห้ามสรุปว่าไม่มีกฎดีกว่า ข้อมูลบอกว่ากลุ่มไม่มีกฎปิดงานได้บ่อยกว่า แต่หน้าที่แล้วแสดงว่ามันปิดงานโดย ไม่เคยเช็คว่าของเก่าพังไหมเลยสักครั้ง ในระบบที่แก้สูตรวันนี้แล้วใบแจ้งหนี้เดือนที่แล้วเปลี่ยน การปิดงานเร็วแบบนั้นคือความเสี่ยง ไม่ใช่ประสิทธิภาพ · และ A0 เป็นกลุ่มเชิงพรรณนา
สามกลุ่มที่มีกฎได้ 0.967 เท่ากัน — ปัดทศนิยมแล้วเท่า ตัวจริงต่างกันที่หลักที่สี่ · เหตุผลที่ใกล้กันขนาดนี้คือ เมื่อทำงานสำเร็จแล้ว กฎที่เหลือส่วนใหญ่ผ่านได้ไม่ยาก ความต่างระหว่างกลุ่มจึงไปอยู่ที่ว่า ปิดงานได้ไหม เป็นหลัก ซึ่งก็คือข้อจำกัดของ RCRc ที่ต้องเปิดเผยคู่กันเสมอ

ตรวจว่า skill โหลดถูกจังหวะไหม — trigger F1

เป็น manipulation check คือตรวจว่า สิ่งที่เราตั้งใจทำกับกลุ่มทดลองเกิดขึ้นจริงไหม — skill โหลดตอนที่ควรโหลด และไม่โหลดตอนที่ไม่ควร F1 = 1.000 แปลว่าถูกทุกครั้ง ไม่พลาดทั้งสองทาง

มีสองชุดเพราะ Amendment 16 พบว่าเกณฑ์เดิมจัด S06 S07 S11 ว่าควรโหลด skill ผลกระทบ ทั้งที่สามข้อนั้นมีแต่กฎเชิงรับซึ่งผ่านได้ด้วยการไม่ทำอะไรผิด ต้องรายงานทั้งสองชุด ไม่งั้นคือหยิบเลขที่สวยกว่า

ทำไมตัวเลขชุดนี้สำคัญกับการอ่านผล มันแปลว่ากลไกส่งกฎทำงานถูกจังหวะ แต่ผลปลายทางไม่ขยับ ปัญหาจึงไม่ได้อยู่ที่การส่งกฎ · ถ้าตัวเลขนี้ต่ำ เราจะตอบไม่ได้เลยว่าที่ไม่ต่างเพราะ skill ไม่โหลด หรือเพราะกฎไม่ช่วย
ต้องพูดตรง ๆ — กลไกจับได้เพราะมีคนเผื่อไว้ล่วงหน้าว่าหน่วยความจำอัตโนมัติเป็นตัวแปรที่ต้องคุม เราไม่มีทางรู้ว่ายังมีช่องแบบเดียวกันที่ยังไม่มีใครนึกถึงอีกกี่ช่อง

สิ่งที่พลาด

รอบที่แล้วผมรายงานอาจารย์เองว่า “ทางออกคือเพิ่มจำนวนโจทย์ ไม่ใช่เพิ่มรอบ” แต่ตอนออกแบบรอบที่ 2 ผมใช้โจทย์ 11 ข้อเดิม ไม่ได้เพิ่ม
ถ้าเพิ่มอีก 5 ข้อจะเป็นยังไง m น่าจะขยับขึ้น และที่ m = 6 เพดาน p ลงมาเหลือ 2−5 = 0.031 ซึ่งผ่านเกณฑ์ 0.05 ได้
เหตุผลที่ไม่ทำตอนนั้นคือเวลากับโควตา — โจทย์ใหม่หนึ่งข้อต้องผ่านด่านตรวจสี่ด่าน และเพิ่ม 5 ข้อแปลว่าต้องรันเพิ่มอีกราว 80 run

มองย้อนกลับไปคือตัดสินใจผิด บันทึกไว้ในบทข้อจำกัดแล้ว และเป็นข้อเสนอแนะอันดับหนึ่งสำหรับงานต่อยอด

เหลืออะไร และทันไหม

ที่เหลือเป็นงานเรียบเรียง ไม่ใช่งานวิจัยแล้ว สามแถวล่างรวมกันราว 5–6 วันทำงาน · ไม่ต้องเก็บข้อมูลเพิ่มแม้แต่ run เดียว

กำหนดส่งเล่มจริงวันไหนครับ — ยังไม่มีเอกสารไหนในโปรเจกต์ระบุไว้ ขอเช็คให้ตรงกัน
อีกหนึ่งอย่างที่ไม่ได้อยู่ในตาราง ต้องเซ็นรับ 3 ข้อใน PRE-REGISTRATION-2.md §9 โดยเฉพาะข้อที่ยอมรับว่า เปลี่ยนตัวชี้วัดหลักหลังเห็นผลชุดที่ 1 แล้ว

กฎที่ส่งให้เอเจนต์ — ข้อความจริง ไม่ได้ย่อ

นี่คือสิ่งที่ยังไม่เคยเอามาให้ดูเลย ทั้งที่มันคือตัวแปรต้นของงานทั้งชิ้น A1 กับ A2 มีกฎเนื้อหาเดียวกัน ต่างกันแค่ A1 ยัดไว้ในไฟล์เดียวที่โหลดตลอดเวลา ส่วน A2 แยกเป็น skill ที่โหลดเมื่อเข้าเงื่อนไข · A5 คือข้อความของ A2 แบนกลับเป็นไฟล์เดียว

โจทย์ทั้ง 11 ข้อ — 6 ตระกูลกับดัก

สนามทดลองคือระบบจองการ์ดจอ fixtures/gpu-booking — GPU 4 ใบ · 4 บทบาท · 7 สถานะ · ข้อกำหนด 43 ข้อ · เหตุการณ์ตั้งต้น 268 รายการ · เทสเดิม 34 ตัว คลิกโจทย์เพื่อดูกฎของมันและผลรายกลุ่ม

ไล่ดู run ทีละตัว

ทุก run ที่เก็บมาอยู่ที่นี่ พร้อมผลตรวจกฎทีละข้อ คลิกแถวเพื่อกางรายละเอียด

คำสั่งที่ใช้เก็บและวิเคราะห์ข้อมูลจริง

คัดจาก package.json ของโปรเจกต์ ไม่ได้พิมพ์ขึ้นใหม่

# เก็บข้อมูลชุดที่ 2 — 4 กลุ่ม x 11 โจทย์ x 4 รอบ
node scripts/supervise-collection.mjs --config config/arms-study2.json \
     --out results-study2 --reps 4 --label 20-study2

# วิเคราะห์ แล้วสร้างบทที่ 5ข กับไฟล์ตัวเลขใหม่ทั้งชุด
npm run results:all:study2

# ด่านตรวจก่อนเชื่อตัวเลขใด ๆ — ต้อง exit 0
npm run gate
npm test

npm run gate ตรวจตั้งแต่ข้อความกฎของทุกกลุ่มตรงกับที่ประกาศไว้ไหม · เอเจนต์ปลอมได้คะแนนต่ำตามเกณฑ์ไหม · ไปจนถึงตัวเลขในเล่มตรงกับ numbers.json ทุกตัวไหม ถ้าข้อใดข้อหนึ่งไม่ผ่าน มันหยุดและไม่ยอมสร้างเอกสาร
