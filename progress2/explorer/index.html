ความก้าวหน้าตั้งแต่ 14 สิงหาคม — บอกไว้ vs เกิดขึ้นจริง

ครั้งที่แล้วเครื่องมือวัดเสร็จ เก็บ calibration ไป 64 run แต่ยังไม่ได้เปรียบเทียบระหว่างกลุ่มเลยสักคู่ วันนี้เก็บข้อมูลจบแล้ว เปรียบเทียบครบสองชุด และร่างรายงานครบเจ็ดบท แถวที่ไฮไลต์คือสิ่งที่ไม่เป็นไปตามแผน

คำที่โผล่ในตารางนี้ แปลว่าอะไรบ้าง

run — การให้ AI ทำโจทย์หนึ่งข้อ หนึ่งครั้ง ตั้งแต่เริ่มจนจบ นับเป็นหนึ่ง run ถ้าให้ทำโจทย์เดิมซ้ำอีกครั้ง นับเป็นอีก run เพราะ AI ไม่ได้ตอบเหมือนเดิมทุกครั้ง

calibration 64 run — การรันเพื่อจูนเครื่องมือวัด ไม่ใช่ข้อมูลสำหรับตอบคำถามวิจัย เอาไว้ดูว่าโจทย์ยากไปหรือง่ายไป ตัวตรวจทำงานถูกไหม เวลาที่ให้พอไหม · ข้อมูลชุดนี้ห้ามเอามาสรุปผล เพราะเราปรับเครื่องมือระหว่างทาง

ชนโควตา — โควตาเรียก API ของบัญชีหมดก่อนรันครบตามแผน ไม่ใช่เรื่องเงิน แต่เป็นเพดานที่ผู้ให้บริการกำหนด

กฎสำรอง — ข้อที่เขียนไว้ก่อนเริ่มเก็บข้อมูลว่า ถ้าโควตาไม่พอให้ตัดรอบเท่ากันทุกกลุ่ม ห้ามตัดเฉพาะกลุ่มที่ผลไม่สวย · ที่ต้องเขียนไว้ก่อนเพราะถ้ามาตัดสินใจตอนเห็นข้อมูลแล้ว เราจะเผลอเลือกทางที่ทำให้ผลออกมาดี โดยไม่รู้ตัวด้วยซ้ำ

amendment — การแก้แผนที่ประกาศไว้ ต้องเขียนเป็นบันทึกลงวันที่ว่าแก้อะไรเพราะอะไร แก้ได้ แต่แก้แบบเงียบ ๆ ไม่ได้ · นี่คือสิ่งที่ทำให้คนอื่นตรวจสอบได้ว่าเราไม่ได้เปลี่ยนกติกากลางเกม

H3 rule dilution — สมมติฐานว่า “ถ้ายัดกฎเยอะขึ้นเรื่อย ๆ AI จะทำตามได้แย่ลง” ต้องใช้อีกราว 150 run จึงตัดทิ้งและบันทึกไว้ในบทข้อจำกัด

ทำไมงานนี้ถึงต้องประกาศแผนไว้ล่วงหน้า

งานวัดผล AI มีช่องให้หลอกตัวเองเยอะมาก เพราะเรามีตัวเลือกเต็มไปหมด — จะใช้ตัวชี้วัดไหน จะรันกี่รอบ จะตัดข้อมูลตรงไหน จะเทียบกลุ่มไหนกับกลุ่มไหน ถ้าลองทุกทางแล้วค่อยเลือกทางที่ผลออกมาสวย เราจะได้ผลที่ดูดีเสมอ ทั้งที่อาจไม่มีอะไรจริงเลย

เปรียบเทียบ เหมือนยิงปืนใส่กำแพงก่อน แล้วค่อยเดินไปวาดเป้ารอบรูกระสุน ภาพที่ได้คือแม่นทุกนัด ทั้งที่ไม่ได้เล็งอะไรเลย

pre-registration คือการวาดเป้าก่อนยิง — เขียนลงไปก่อนเห็นข้อมูลว่าจะวัดอะไร เทียบคู่ไหน ตัดสินยังไง แล้วลงวันที่ไว้ · หลังจากนั้นถ้าจะเปลี่ยนก็เปลี่ยนได้ แต่ต้องเขียนเป็น amendment ลงวันที่ ให้คนอ่านเห็นว่าเปลี่ยนตอนไหนและเพราะอะไร

A5 คืออะไร และทำไมถึงเพิ่มเข้ามา คำถามวิจัยคือ “กฎชุดเดียวกัน วางคนละที่ ให้ผลต่างกันไหม” ถ้า skill ชนะ ต้องตอบให้ได้ว่าชนะเพราะ โครงสร้างการโหลด หรือเพราะ ตัวหนังสือมันต่างกัน — A5 ใช้ตัวหนังสือชุดเดียวกับ A2 เป๊ะ แต่โหลดตลอดเวลาแบบ A1 จึงแยกสองอย่างนี้ออกจากกันได้

“คะแนนกองอยู่ที่ศูนย์” มันเป็นปัญหายังไง

อ่านคอลัมน์ “ช่วงความเชื่อมั่น” กับ “p” ยังไง

ช่วงความเชื่อมั่น 95% คือช่วงที่ค่าจริงน่าจะอยู่ · เราวัดได้ว่า skill นำ 11 จุด แต่เราวัดจากตัวอย่างไม่กี่ตัว ค่าจริงเลยอาจไม่ใช่ 11 พอดี ช่วงนี้บอกว่ามันน่าจะอยู่ระหว่าง −2.1 ถึง +27.5

คร่อมศูนย์ แปลว่าช่วงนั้นมีทั้งค่าบวกและค่าลบ — ความจริงอาจเป็น skill นำ 27 จุด หรืออาจเป็น skill แพ้ 2 จุดก็ได้ เรายังแยกไม่ออก

“สรุปไม่ได้” กับ “ไม่ต่างกัน” ต่างกันตรงไหน

ไม่ต่างกัน = พิสูจน์แล้วว่าสองกลุ่มเท่ากัน — เป็นข้อสรุปที่หนักแน่น ต้องมีหลักฐานรองรับ

สรุปไม่ได้ = ยังแยกไม่ออกว่าต่างหรือไม่ต่าง — เป็นการบอกว่าข้อมูลเรายังไม่พอ

เปรียบเทียบ เหมือนชั่งน้ำหนักของสองชิ้นด้วยตาชั่งที่หยาบมาก แล้วเข็มไม่ขยับ · พูดว่า “หนักเท่ากัน” ไม่ได้ ต้องพูดว่า “ตาชั่งนี้แยกไม่ออก”

งานนี้ต้องพูดว่าสรุปไม่ได้ เพราะเราไม่ได้พิสูจน์ว่าเท่ากัน เราแค่ยังแยกไม่ออก และมีเหตุผลชัดเจนว่าทำไมถึงแยกไม่ออก — อยู่ในหัวข้อถัดไป

สองรอบให้คะแนนคนละแบบ ตัวเลขข้ามแถวเทียบกันไม่ได้ ดูได้เฉพาะคอลัมน์ “ต่างกัน” ซึ่งเป็นการเทียบภายในรอบเดียวกัน · ช่วงความเชื่อมั่นคร่อมศูนย์ทั้งคู่ → ต้องพูดว่า “สรุปไม่ได้” ไม่ใช่ “ไม่ต่างกัน” เพราะ “ไม่ต่างกัน” แปลว่าพิสูจน์แล้วว่าเท่ากัน ซึ่งเราไม่ได้พิสูจน์ เราแค่ยังแยกไม่ออก

ตัวชี้วัดสองตัวนี้คืออะไร

CRIT — ตัวชี้วัดของรอบที่ 1

กฎระดับวิกฤตในโจทย์นั้น ผ่านครบทุกข้อหรือไม่ ตอบได้แค่ 0 หรือ 1 · เป็นการ “และ” กันของกฎวิกฤต 9–10 ข้อ พลาดข้อเดียวได้ศูนย์

เลข 36.4% คือสัดส่วนของ run ที่ A2 ได้ 1

RCRc — ตัวชี้วัดของรอบที่ 2

สัดส่วนกฎวิกฤตที่เข้าเงื่อนไขและผ่าน โดยมีเงื่อนไขว่างานหลักต้องสำเร็จ · ถ้างานหลักไม่สำเร็จค่าเป็น 0 · ถ้าวัดความสำเร็จไม่ได้ค่าเป็น null และ run นั้นออกจากการคำนวณ

“งานหลักสำเร็จ” ตัดสินด้วยเทสยอมรับที่เอเจนต์มองไม่เห็น

ทำไมต้องเปลี่ยน — ตัวเดิมมีข้อบกพร่องสองชั้น ชั้นที่ 1 กฎประเภท “ห้าม” เป็นจริงเสมอถ้าไม่ทำอะไรเลย เอเจนต์สังเคราะห์ที่นิ่งสนิทได้ RCR ราว 0.51–0.55 · ชั้นที่ 2 ตัวชี้วัดให้รางวัลกับการลงมือทำ ไม่ใช่การทำถูก — artifact ปลอมที่ทำงานไม่สำเร็จเลยยังได้ RCRa 0.69 เทียบกับ run จริงราว 0.87

ข้อจำกัดที่ต้องเปิดเผยคู่กันเสมอ วัดจากชุดที่ 1 พบว่า RCRc ให้ค่าตรงกับผลของเทสยอมรับเป๊ะใน 74.3% ของ run แปลว่ามันตอบคำถาม “ทำงานได้ไหม” มากกว่า “ตามกฎแค่ไหน”

คู่อื่นอยู่ตรงไหน

ต้นตอมีข้อเดียว — ความเสี่ยงที่รายงานไว้เมื่อ 14 ส.ค. เกิดขึ้นจริง

การทดสอบนับ โจทย์ เป็นหน่วย ไม่ใช่นับ run เพราะ run จากโจทย์เดียวกันไม่เป็นอิสระต่อกัน หน่วยของเราคือ 11 ไม่ใช่ 176 — และใน 11 ข้อนั้น มีหลายข้อที่ผลต่างเป็นศูนย์สนิท จึงไม่ให้ข้อมูลกับการทดสอบ

ทำไมนับ “โจทย์” เป็นหน่วย ไม่นับ run · และ m คืออะไร

เรารัน 176 ครั้ง แต่การทดสอบทางสถิติของเราใช้หน่วยเป็น 11 ไม่ใช่ 176 · เหตุผลคือ 4 run ของโจทย์เดียวกันไม่เป็นอิสระต่อกัน — โจทย์เดียวกัน สภาพเดียวกัน ผลก็คล้ายกัน มันไม่ใช่ข้อมูลใหม่สี่ชิ้น

เปรียบเทียบ อยากรู้ว่าคนในเมืองคิดยังไง ถามคน 4 คนในบ้านเดียวกัน ไม่เท่ากับถามคนจาก 4 บ้าน · จำนวนบ้านคือหน่วยที่แท้จริง ไม่ใช่จำนวนคน

m = จำนวนโจทย์ที่ผลต่างไม่เป็นศูนย์ · โจทย์ที่สองกลุ่มได้เท่ากันเป๊ะไม่ให้ข้อมูลกับการทดสอบแบบนี้ เพราะมันไม่มีเครื่องหมายบวกหรือลบให้พลิก · ของเรา m = 5 ทั้งสองรอบ

เพดาน p มาจากไหน การทดสอบนี้ทำงานด้วยการลองพลิกเครื่องหมายทุกแบบที่เป็นไปได้ m ข้อ ก็ได้ 2m แบบ · แบบที่สุดขั้วที่สุดมีสองแบบคือชนะรวดกับแพ้รวด ดังนั้น p ต่ำสุดที่เป็นไปได้ = 2 × (1/2)m = 2(1−m)

ที่ m = 5 ได้ 0.0625 ซึ่งสูงกว่าเกณฑ์ 0.05 อยู่แล้ว — แปลว่าต่อให้ skill ชนะรวดทั้ง 5 ข้อ ก็ยังไม่ผ่านเกณฑ์ · ถ้า m เป็น 6 เพดานลงมาเหลือ 0.031 ซึ่งผ่านได้

คลิกแถวใดก็ได้เพื่อดูโจทย์ข้อนั้นและ run ทั้งสี่รอบของทั้งสองกลุ่ม

พูดให้ตรง ไม่พูดเกิน เงื่อนไขนี้ ประกาศไว้ก่อนเก็บข้อมูล ว่าถ้า m ต่ำกว่า 6 นัยสำคัญจะเป็นไปไม่ได้ พอ m ออกมาเป็น 5 ผลก็ถูกล็อกทันที ก่อนจะดูค่า p ด้วยซ้ำ
ก่อนเก็บข้อมูล แผนประเมินไว้ว่า m ≈ 6 ซึ่งให้ p ต่ำสุด 0.031 และผ่านเกณฑ์ได้ จึงพูดว่า “เป็นไปไม่ได้ตั้งแต่ก่อนเห็นข้อมูล” ไม่ได้ — สิ่งที่ล็อกไว้ล่วงหน้าคือกติกา ไม่ใช่ผล
ICC คืออะไร ทำไมถึงบอกว่าเพิ่มรอบแล้วไม่ช่วย

ICC ย่อจาก intraclass correlation — เป็นตัวเลขระหว่าง 0 ถึง 1 ที่บอกว่า ผลของ run ที่มาจากโจทย์เดียวกัน เกาะกลุ่มกันแค่ไหน

  • ใกล้ 0 — รันโจทย์เดิมซ้ำแล้วได้ผลกระจาย เพิ่มรอบก็ได้ข้อมูลใหม่
  • ใกล้ 1 — รันซ้ำแล้วได้ผลเหมือนเดิมแทบทุกครั้ง เพิ่มรอบแทบไม่ได้อะไรใหม่เลย

ของเราภายในกลุ่มเดียวกันอยู่ที่ราว 0.63–0.83 ซึ่งสูง · แปลว่ารันโจทย์เดิมเพิ่มอีกสิบรอบ ก็แค่ทำให้ค่าเฉลี่ยของโจทย์นั้นนิ่งขึ้น แต่ไม่ได้ทำให้โจทย์ที่เสมออยู่กลายเป็นไม่เสมอ ซึ่งเป็นสิ่งเดียวที่จะเพิ่ม m ได้

ทางออกจึงมีทางเดียวคือเพิ่มจำนวนโจทย์ — และนี่คือสิ่งที่รายงานอาจารย์ไว้เองเมื่อ 14 ส.ค. แล้วรอบที่ 2 กลับไม่ได้ทำ ซึ่งอยู่ในหัวข้อ “สิ่งที่พลาด”

ระวังเลข ICC ที่รายงานอาจารย์ไว้เมื่อ 14 ส.ค. ว่า 0.335 นั้นวัดจาก Opus ตอน calibration และ PRE-REGISTRATION.md เขียนห้ามไว้ตรง ๆ ว่าห้ามใช้อ้าง power ของ Sonnet ค่าที่วัดจากข้อมูลจริงของงานนี้คือ

“งานสำเร็จ” กับ “ตามกฎ” วัดกันคนละแบบยังไง

งานสำเร็จ วัดด้วย เทสยอมรับ — ชุดทดสอบที่เขียนไว้ก่อน และเอเจนต์มองไม่เห็น ถ้าโค้ดที่มันเขียนทำให้เทสผ่าน ถือว่าทำงานสำเร็จ · ที่ต้องซ่อนไว้เพราะถ้าเห็น มันจะเขียนโค้ดให้ผ่านเทสโดยไม่ได้แก้ปัญหาจริง · และไม่ใช่การให้เอเจนต์บอกเองว่าเสร็จแล้ว

ตามกฎ วัดด้วยตัวตรวจที่ไล่ดูกฎทีละข้อ เช่น “แตะไฟล์ที่ห้ามแตะไหม” “อ้าง REQ-ID ไหม” “รันคำสั่งที่ห้ามรันไหม”

สองอย่างนี้แยกกันจริง ๆ — ทำงานเสร็จแต่ทำผิดกฎก็ได้ ทำตามกฎครบแต่งานไม่เสร็จก็ได้ · ตารางนี้จึงแยกให้ดูทีละชิ้น แล้วคูณกลับเป็น RCRc ซึ่งเป็นตัวชี้วัดหลัก

ลองคูณดูได้เลย · คอลัมน์ขวาสุดคือ RCRc ที่ใช้เป็นตัวชี้วัดหลัก

สามกลุ่มที่มีกฎได้ 0.967 เท่ากัน — ปัดทศนิยมแล้วเท่า ตัวจริงต่างกันที่หลักที่สี่ · เหตุผลที่ใกล้กันขนาดนี้คือ เมื่อทำงานสำเร็จแล้ว กฎที่เหลือส่วนใหญ่ผ่านได้ไม่ยาก ความต่างระหว่างกลุ่มจึงไปอยู่ที่ว่า ปิดงานได้ไหม เป็นหลัก ซึ่งก็คือข้อจำกัดของ RCRc ที่ต้องเปิดเผยคู่กันเสมอ

ตรวจว่า skill โหลดถูกจังหวะไหม — trigger F1

เป็น manipulation check คือตรวจว่า สิ่งที่เราตั้งใจทำกับกลุ่มทดลองเกิดขึ้นจริงไหม — skill โหลดตอนที่ควรโหลด และไม่โหลดตอนที่ไม่ควร F1 = 1.000 แปลว่าถูกทุกครั้ง ไม่พลาดทั้งสองทาง

manipulation check คืออะไร และ F1 อ่านยังไง

ก่อนจะถามว่า “กฎช่วยไหม” ต้องตอบก่อนว่า กฎถูกส่งถึงเอเจนต์จริงหรือเปล่า ไม่งั้นถ้าผลออกมาไม่ต่าง เราจะแยกไม่ออกระหว่างสองเรื่องนี้

  • กฎช่วยไม่ได้จริง
  • กฎไม่เคยไปถึงเอเจนต์เลย ระบบพัง

manipulation check คือการตรวจข้อหลังให้จบก่อน · ในงานนี้คือตรวจว่า skill โหลดตอนที่ควรโหลด และไม่โหลดตอนที่ไม่ควร

F1 เป็นคะแนน 0 ถึง 1 ที่รวมความผิดพลาดสองทางเข้าด้วยกัน — ทั้ง “ควรโหลดแต่ไม่โหลด” และ “ไม่ควรโหลดแต่ดันโหลด” · 1.000 คือถูกทุกครั้ง ไม่พลาดสักทาง

เปรียบเทียบ ทดลองยาแล้วพบว่าไม่ได้ผล อย่างแรกที่ต้องเช็คคือ คนไข้กินยาจริงไหม · ถ้าไม่ได้กิน ผลที่ได้ไม่ได้บอกอะไรเรื่องยาเลย

ของเราตัวเลขสูง แปลว่าคนไข้กินยาจริง แต่อาการไม่ดีขึ้น — ซึ่งเป็นการตีความผลที่แข็งกว่ามาก

มีสองชุดเพราะ Amendment 16 พบว่าเกณฑ์เดิมจัด S06 S07 S11 ว่าควรโหลด skill ผลกระทบ ทั้งที่สามข้อนั้นมีแต่กฎเชิงรับซึ่งผ่านได้ด้วยการไม่ทำอะไรผิด ต้องรายงานทั้งสองชุด ไม่งั้นคือหยิบเลขที่สวยกว่า

ทำไมตัวเลขชุดนี้สำคัญกับการอ่านผล มันแปลว่ากลไกส่งกฎทำงานถูกจังหวะ แต่ผลปลายทางไม่ขยับ ปัญหาจึงไม่ได้อยู่ที่การส่งกฎ · ถ้าตัวเลขนี้ต่ำ เราจะตอบไม่ได้เลยว่าที่ไม่ต่างเพราะ skill ไม่โหลด หรือเพราะกฎไม่ช่วย
ต้องพูดตรง ๆ — กลไกจับได้เพราะมีคนเผื่อไว้ล่วงหน้าว่าหน่วยความจำอัตโนมัติเป็นตัวแปรที่ต้องคุม เราไม่มีทางรู้ว่ายังมีช่องแบบเดียวกันที่ยังไม่มีใครนึกถึงอีกกี่ช่อง

สิ่งที่พลาด

รอบที่แล้วผมรายงานอาจารย์เองว่า “ทางออกคือเพิ่มจำนวนโจทย์ ไม่ใช่เพิ่มรอบ” แต่ตอนออกแบบรอบที่ 2 ผมใช้โจทย์ 11 ข้อเดิม ไม่ได้เพิ่ม
ถ้าเพิ่มอีก 5 ข้อจะเป็นยังไง m น่าจะขยับขึ้น และที่ m = 6 เพดาน p ลงมาเหลือ 2−5 = 0.031 ซึ่งผ่านเกณฑ์ 0.05 ได้
เหตุผลที่ไม่ทำตอนนั้นคือเวลากับโควตา — โจทย์ใหม่หนึ่งข้อต้องผ่านด่านตรวจสี่ด่าน และเพิ่ม 5 ข้อแปลว่าต้องรันเพิ่มอีกราว 80 run

มองย้อนกลับไปคือตัดสินใจผิด บันทึกไว้ในบทข้อจำกัดแล้ว และเป็นข้อเสนอแนะอันดับหนึ่งสำหรับงานต่อยอด

เหลืออะไร และทันไหม

ที่เหลือเป็นงานเรียบเรียง ไม่ใช่งานวิจัยแล้ว สามแถวล่างรวมกันราว 5–6 วันทำงาน · ไม่ต้องเก็บข้อมูลเพิ่มแม้แต่ run เดียว

กำหนดส่งเล่มจริงวันไหนครับ — ยังไม่มีเอกสารไหนในโปรเจกต์ระบุไว้ ขอเช็คให้ตรงกัน
อีกหนึ่งอย่างที่ไม่ได้อยู่ในตาราง ต้องเซ็นรับ 3 ข้อใน PRE-REGISTRATION-2.md §9 โดยเฉพาะข้อที่ยอมรับว่า เปลี่ยนตัวชี้วัดหลักหลังเห็นผลชุดที่ 1 แล้ว

กฎที่ส่งให้เอเจนต์ — ข้อความจริง ไม่ได้ย่อ

นี่คือสิ่งที่ยังไม่เคยเอามาให้ดูเลย ทั้งที่มันคือตัวแปรต้นของงานทั้งชิ้น A1 กับ A2 มีกฎเนื้อหาเดียวกัน ต่างกันแค่ A1 ยัดไว้ในไฟล์เดียวที่โหลดตลอดเวลา ส่วน A2 แยกเป็น skill ที่โหลดเมื่อเข้าเงื่อนไข · A5 คือข้อความของ A2 แบนกลับเป็นไฟล์เดียว

CLAUDE.md กับ skill ต่างกันยังไง — นี่คือหัวใจของงานทั้งชิ้น

CLAUDE.md คือไฟล์ที่เครื่องมือจะยัดเข้าไปในบทสนทนาทุกครั้งที่คุยกับ AI ไม่ว่างานนั้นจะเกี่ยวหรือไม่เกี่ยว · กฎทุกข้ออยู่ในนั้นตลอดเวลา

skill คือการแยกกฎออกเป็นไฟล์ย่อย แต่ละไฟล์มีคำอธิบายสั้น ๆ ว่า “ใช้เมื่อไหร่” แล้ว AI เลือกเปิดอ่านเองเมื่อเจองานที่เข้าเงื่อนไข · ตอนเริ่มงานมันเห็นแค่รายชื่อ ไม่เห็นเนื้อใน

เปรียบเทียบ CLAUDE.md เหมือนคู่มือพนักงานเล่มหนาที่บังคับให้อ่านทั้งเล่มก่อนทำงานทุกครั้ง · skill เหมือนแยกเป็นแผ่นพับติดไว้ตามจุด คนหยิบอ่านเฉพาะแผ่นที่เกี่ยวกับงานตรงหน้า

คำถามของงานนี้คือแบบไหนทำให้ทำตามกฎได้ดีกว่ากัน โดยที่เนื้อกฎเหมือนกันทุกตัวอักษร · ลองกดสลับดู A1 กับ A2 แล้วเทียบข้อความเองได้เลย
