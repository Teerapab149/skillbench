## 7.1 สรุปสิ่งที่ทำ

งานวิจัยนี้ตั้งคำถามว่า **การบรรจุกฎการทำงานไว้ในไฟล์เดียวที่โหลดตลอดเวลา
กับการบรรจุกฎชุดเดียวกันไว้ใน skill ที่โหลดเมื่อจำเป็น ให้ผลต่างกันหรือไม่**
โดยคุมเนื้อหาของกฎให้เหมือนกันทุกตัวอักษร ต่างกันเฉพาะกลไกการส่งกฎถึงเอเจนต์

การทดลองมี **สองชุด** บนโจทย์วิศวกรรมซอฟต์แวร์ 11 ข้อชุดเดียวกัน
ตัดสินด้วยตัวตรวจที่เป็นโปรแกรมล้วน ไม่มีคนหรือ LLM ให้คะแนน
และประกาศแผนวิเคราะห์เป็นลายลักษณ์อักษรพร้อมวันที่ก่อนเก็บข้อมูลทั้งสองครั้ง

| | ชุดที่ 1 | ชุดที่ 2 |
|---|---|---|
| บทบาท | พัฒนาเครื่องมือวัดและสอบเทียบ | ทดลองยืนยัน |
| กลุ่ม | A0 A1 A2 A3 A4 | A0 A1 A2 **A5** |
| ข้อมูล | 220 run (ประกาศ 330 ใช้กฎสำรอง) | **176 run ครบทุกช่อง** |
| ตัวชี้วัดหลัก | `CRIT` | `RCRc` |
| ผล A2 เทียบ A1 | +9.1 จุด · p = 0.500 | +11.0 จุด · p = 0.250 |

ชุดที่ 2 เกิดขึ้นเพราะชุดที่ 1 แสดงให้เห็นว่า **เครื่องมือวัดเองเป็นตัวจำกัด** —
`CRIT` เป็นการ "และ" กันของกฎวิกฤต 9–10 ข้อ คะแนนจึงกองที่พื้นและโจทย์ส่วนใหญ่
ได้ค่าเท่ากันทั้งสองกลุ่ม ทำให้นัยสำคัญเป็นไปไม่ได้ทางคณิตศาสตร์ตั้งแต่ก่อนเห็นข้อมูล

## 7.2 ข้อสรุปหลัก

**การเปรียบเทียบหลักสรุปไม่ได้ทั้งสองชุด**

ผลต่างเป็นบวกในทิศทางของ skill ทั้งสองครั้ง (+9.1 จุด และ +11.0 จุด)
แต่ช่วงความเชื่อมั่นคร่อมศูนย์ทั้งคู่ และค่า p ไม่ถึงระดับนัยสำคัญทั้งคู่

**และทั้งสองชุดสรุปไม่ได้ด้วยเหตุผลเดียวกัน คือจำนวนโจทย์ที่ให้ข้อมูลน้อยเกินไป**

การทดสอบหลักใช้โจทย์เป็นหน่วยข้อมูล โจทย์ที่สองกลุ่มได้เท่ากันจึงไม่ให้ข้อมูลเลย
ทั้งสองชุดเหลือโจทย์ที่ผลต่างไม่เป็นศูนย์ **5 ข้อจาก 11 เท่ากันพอดี**
ค่า p ต่ำสุดที่การออกแบบมีทางได้จึงเป็น **0.0625 ทั้งสองชุด** ซึ่งสูงกว่าเกณฑ์ 0.05
**นัยสำคัญจึงเป็นไปไม่ได้ทางคณิตศาสตร์ทั้งสองชุด ตั้งแต่ก่อนเห็นข้อมูล**
ไม่ว่าผลจริงจะชัดเจนเพียงใด

สิ่งที่การซ่อมตัวชี้วัดทำได้คือทำให้**ค่าประมาณคมขึ้น** ไม่ใช่ขยับเพดาน

| | ชุดที่ 1 | ชุดที่ 2 | เปลี่ยนไหม |
|---|---:|---:|---|
| โจทย์ที่ให้ข้อมูล `m` | 5 | 5 | **ไม่เปลี่ยน** |
| p ต่ำสุดที่เป็นไปได้ | 0.0625 | 0.0625 | **ไม่เปลี่ยน** |
| p ที่สังเกตได้ | 0.500 | 0.250 | ดีขึ้น |
| ขอบล่างของ 95% CI | −6.8% | −2.1% | ดีขึ้น |

ข้อสรุปจึงตรงกับสิ่งที่ PRE-REGISTRATION-2 §7 เขียนไว้ล่วงหน้าว่า **ถ้า `m` จริง
ต่ำกว่า 6 นัยสำคัญจะเป็นไปไม่ได้** คอขวดคือ **จำนวนโจทย์** ไม่ใช่เครื่องมือวัด
และไม่ใช่จำนวนรอบ ซึ่งเป็นข้อจำกัดที่ระบุไว้ตั้งแต่บทที่ 1 ว่าหนักที่สุด
และยังหนักที่สุดอยู่หลังผ่านไปสองชุด

### สมมติฐานสี่ข้อ ตอบได้จริงสองข้อ

| | สถานะ |
|---|---|
| H1 กฎรูปลำดับ/ข้อห้าม/ขอบเขตตัวเลข เทียบกฎรูปค่านิยม | **ทดสอบไม่ได้** |
| H2 โครงสร้างการจัดวางกฎมีผล เมื่อคุมเนื้อหาและความยาว | **สรุปไม่ได้** ทั้งสองชุด |
| H3 การเจือจางของกฎที่โหลดพร้อมกัน | **ไม่ได้เก็บข้อมูลจริง** |
| H4 กลุ่มที่มีกฎใช้ token น้อยกว่ากลุ่มที่ไม่มีกฎ | **ไม่สนับสนุน** |

H1 ทดสอบไม่ได้เพราะ **ไม่มีกฎรูปค่านิยมอยู่ในเครื่องมือวัดเลยสักข้อ** ซึ่งเป็นผลโดยตรง
จากข้อบังคับที่งานนี้ตั้งเองว่าตัวตรวจต้องเป็นโปรแกรมที่ตัดสินแบบกำหนดผลได้แน่นอน
**ข้อบังคับที่ทำให้ตัวเลขทั้งเล่มเชื่อถือได้ คือข้อเดียวกับที่ทำให้ H1 ทดสอบไม่ได้**

H4 ไม่สนับสนุนและผลไปคนละทางกับที่ทำนาย โดย**ทั้งสองชุดให้รูปแบบเดียวกัน**:
กลุ่มไฟล์เดียวใช้ token น้อยกว่ากลุ่มที่ไม่มีกฎจริงตามกลไกที่เสนอ แต่กลุ่ม skill
ใช้มากกว่า ทั้งที่บรรจุกฎเนื้อหาเดียวกัน ถ้ากลไกที่เสนอถูกต้อง มันควรได้ผลกับ
ทุกกลุ่มที่มีกฎ ไม่ใช่เฉพาะกลุ่มเดียว

รายละเอียดทั้งสี่ข้ออยู่ในบทที่ 6 หัวข้อ 6.1.1

**ตัวชี้วัดรองและคู่เปรียบเทียบอื่นไม่ถูกทดสอบ** ตามลำดับที่ประกาศไว้ล่วงหน้า
คู่ A5 เทียบ A2 ซึ่งตั้ง arm ขึ้นมาทั้ง arm เพื่อตอบ จึงรายงานเชิงพรรณนาเท่านั้น

## 7.3 สิ่งที่ใกล้เคียงข้อค้นพบที่สุดที่งานนี้มี

ชุดที่ 2 แยกตัวชี้วัดหลักออกเป็นสองส่วนได้ และสองส่วนนั้นเดินคนละทาง

| กลุ่ม | ทำงานสำเร็จ | ตามกฎเมื่อทำสำเร็จ |
|---|---:|---:|
| A0 ไม่มีกฎเลย | **75.0%** | 0.895 |
| A1 ไฟล์เดียวโหลดตลอด | 52.3% | **0.967** |
| A2 skill | 63.6% | **0.967** |
| A5 ข้อความเดียวกับ A2 โหลดตลอด | 54.5% | **0.967** |

**กลุ่มที่มีกฎทุกกลุ่มตามกฎได้ดีกว่ากลุ่มที่ไม่มีกฎ และได้เท่ากันหมดที่ 0.967
ขณะที่กลุ่มที่ไม่มีกฎทำงานสำเร็จมากที่สุด**

ถ้ารูปแบบนี้เป็นจริง มันแปลว่า **กฎซื้อความสอดคล้องมาด้วยราคาคือความสำเร็จของงาน**
ซึ่งเป็นคำตอบที่มีประโยชน์กับคนที่ต้องตัดสินใจว่าจะเขียนกฎให้เอเจนต์หรือไม่
มากกว่าคำตอบว่ากลไกไหนดีกว่ากัน

**ข้อจำกัดที่ต้องเขียนคู่กันทุกครั้งที่อ้างตารางนี้**

1. **ไม่ได้ทดสอบทางสถิติ** การทดสอบแต่ละส่วนแยกกันไม่ได้ประกาศไว้ล่วงหน้า
   **จึงห้ามเพิ่มทีหลัง** ตัวเลขข้างบนเป็นค่าเชิงพรรณนา
2. **A0 ถูกประกาศไว้ว่าเป็นกลุ่มเชิงพรรณนา** ไม่ใช่คู่เปรียบเทียบที่อ้างนัยสำคัญได้
3. กำลังการทดสอบที่ไม่พอสำหรับตัวชี้วัดหลัก ก็ไม่พอสำหรับส่วนย่อยของมันเช่นกัน

ข้อสังเกตนี้จึงเป็น **สมมติฐานที่ข้อมูลชี้ทาง ไม่ใช่ข้อสรุป** และเป็นสิ่งที่ควร
ออกแบบการทดลองชุดถัดไปมาทดสอบโดยตรง

### 7.3.1 หลักฐานรายพฤติกรรมที่ชัดกว่าตัวชี้วัดรวม

ตัวชี้วัดรวมกลบความต่างรายพฤติกรรมไว้ การเจาะดูกฎ `IM2` เฉพาะโจทย์ตระกูล
**ผลกระทบซ่อนเร้น** (S08 และ S09 · 8 run ต่อกลุ่ม) ให้ความต่างที่ใหญ่ที่สุด
เท่าที่พบในงานนี้

| กลุ่ม | รัน `revenue-report` เทียบก่อน–หลัง | แจ้งผู้ใช้ว่ายอดย้อนหลังเปลี่ยน |
|---|---:|---:|
| A0 ไม่มีกฎเลย | **0 / 8** | 4 / 8 |
| รวมกลุ่มที่มีกฎ | **19 / 24** | **23 / 24** |

**กลุ่มที่ไม่มีกฎไม่เคยรันคำสั่งตรวจผลกระทบเลยแม้แต่ครั้งเดียว**
และนี่คือพฤติกรรมที่กฎข้อนั้นเขียนสั่งไว้ตรงตัว จึงเป็นความสัมพันธ์ที่
อธิบายด้วยกลไกได้ ไม่ใช่ความบังเอิญเชิงตัวเลข

ข้อนี้ยัง**อธิบายตาราง 7.3 ให้ชัดขึ้น** — A0 ทำงานสำเร็จบ่อยที่สุดส่วนหนึ่ง
เพราะมันข้ามขั้นตอนตรวจสอบที่กลุ่มอื่นทำ

ข้อจำกัดเหมือนเดิมทุกข้อ และหนักกว่าเดิมเพราะ `n` = 8 ต่อกลุ่ม
**เป็นข้อสังเกต ไม่ใช่ข้อสรุป** รายละเอียดอยู่ในบทที่ 6 หัวข้อ 6.1.4

## 7.4 ข้อสังเกตอื่นที่ต้องรายงานแม้ไม่ใช่ข้อสรุป

**กลไกโหลดตามเงื่อนไขทำงานตามที่โฆษณา** Trigger F1 ของ `trace-to-requirement`
เท่ากับ 1.000 และ `acceptance-first` 0.842 skill ถูกโหลดตรงจังหวะที่ควรโหลด
**แต่ผลปลายทางไม่ขยับพอให้วัดได้** ปัญหาจึงไม่ได้อยู่ที่การส่งกฎถึงเอเจนต์

**A2 โหลด skill เฉลี่ยเพียง 2.36 จาก 4 ตัว และไม่มี run ใดโหลดครบทั้งสี่**
ข้อความที่ A2 เห็นจริงจึงน้อยกว่าเพดานมาก ซึ่งทำให้ A5 ที่ถือข้อความระดับเพดาน
ไม่ใช่กลุ่มควบคุมปริมาณข้อความที่สะอาดอย่างที่ตั้งใจ

**ไม่มี run ใดในชุดที่ 2 ชนเพดานงบ turn** ผลที่ได้จึงไม่ใช่ผลของการถูกตัดกลางคัน

## 7.5 สิ่งที่งานนี้ให้ไว้จริง

เมื่อผลเปรียบเทียบสรุปไม่ได้ทั้งสองชุด สิ่งที่เหลือเป็นผลงานคือ **วิธีวิทยาและเครื่องมือ**

- **การคุมเนื้อหากฎให้เท่ากันตรวจสอบได้ด้วยเครื่อง** ครอบคลุมทุก arm ที่อ้างว่ามีกฎชุดเดียวกัน
- **การตรึงสภาพเครื่องมือแล้วตรวจซ้ำทุก run** ซึ่งจับได้จริงสามเรื่องที่ไม่มีใครคาดไว้:
  ชุด skill ของเครื่องมือเปลี่ยนเอง · เอเจนต์เรียก skill ที่ไม่มีอยู่ ·
  และ **เอเจนต์เขียนกฎของการทดลองลงหน่วยความจำถาวรนอกพื้นที่ทดลอง**
- **สมุดบันทึกความพยายามแบบเพิ่มอย่างเดียว** ที่แยก "ถูกขัดจังหวะ" ออกจาก "ล้มเหลวจริง"
- **ตัวชี้วัดที่มีด่านพิสูจน์ตัวเอง** — เอเจนต์ที่ไม่ทำงานสำเร็จต้องได้คะแนนใกล้ศูนย์
  และเอเจนต์ที่ละเมิดกฎทุกข้อแต่ทำงานสำเร็จต้องตกเกินครึ่ง ด่านนี้ล้มได้และเคยล้มจริง
- **สายการผลิตตัวเลขที่มีต้นทางเดียว** เอกสารผลของทั้งสองชุดถูกสร้างจากไฟล์ตัวเลข
  ของชุดตัวเอง และมีด่านที่ทำให้เอกสารที่ไม่ตรงกับข้อมูลผ่านไปไม่ได้

ระหว่างเก็บข้อมูลสองชุด ระบบถูกยุติกลางคันโดยไม่ทราบสาเหตุหลายครั้ง ชนขีดจำกัด
การใช้งานอีกหลายครั้ง และเจอการปนเปื้อนหนึ่งครั้ง **โดยไม่สูญเสียข้อมูลที่เก็บแล้ว
แม้แต่ run เดียว และไม่มี run ที่ปนเปื้อนเข้าชุดข้อมูลเลย**

## 7.6 ข้อเสนอแนะสำหรับงานถัดไป

**ข้อที่สำคัญที่สุดยังเหมือนเดิม: เพิ่มจำนวนโจทย์ ไม่ใช่จำนวนรอบ** สองชุดที่ผ่านมา
ยืนยันข้อนี้ด้วยข้อมูล — การซ่อมตัวชี้วัดไม่ได้ขยับเพดานของ p เลย เพราะจำนวนโจทย์
ที่ให้ข้อมูลยังเท่าเดิมที่ 5 ข้อ เพดานจึงคงอยู่ที่ 0.0625 ทั้งสองชุด
ถ้าต้องการกำลังการทดสอบที่สมเหตุสมผล
ต้องมีโจทย์ที่แยกแยะได้เกิน 10 ข้อ ซึ่งหมายถึงชุดโจทย์รวมราวสองเท่าของที่มี

**ทดสอบสองส่วนแยกกันตั้งแต่ต้น** ออกแบบให้ "ทำงานสำเร็จ" กับ "ตามกฎเมื่อสำเร็จ"
เป็น endpoint คนละตัวที่ประกาศไว้ล่วงหน้า แทนที่จะเป็นผลคูณตัวเดียว
เพราะข้อมูลชี้ว่าสองส่วนนี้เดินคนละทาง และผลคูณจะกลบกันเอง

**คุมปริมาณข้อความที่ระดับที่โหลดจริง ไม่ใช่ที่เพดาน** การวัดว่า skill ถูกโหลด
กี่ตัวต่อ run ต้องทำก่อนออกแบบกลุ่มควบคุม ไม่ใช่หลังจากนั้น

**ถือว่าหน่วยความจำถาวรเป็นตัวแปรควบคุมตั้งแต่วันแรก** และตรวจทุก run
ช่องทางนี้ไม่ได้อยู่ในแผนเดิมและเกือบทำให้การทดลองปนเปื้อนโดยไม่มีใครรู้

**แยกผู้ออกแบบตัวตรวจออกจากผู้ออกแบบกฎ** เพื่อตัดสมมติฐานที่ผิดร่วมกัน
ซึ่งกลไกตรวจสอบอัตโนมัติทั้งหมดในงานนี้จับไม่ได้

## 7.7 ข้อจำกัดของข้อสรุปในบทนี้

ข้อสรุปทั้งหมดผูกกับ: โมเดลหนึ่งตัว · เครื่องมือบรรทัดคำสั่งหนึ่งตัวและรุ่นเดียว ·
โครงงานจำลองหนึ่งโครงงาน · ชุดกฎหนึ่งชุดที่ผู้วิจัยเขียนเอง · และเพดานงบ turn ค่าหนึ่ง

เพิ่มเติมสำหรับชุดที่ 2: **ตัวชี้วัดหลักถูกเปลี่ยนหลังเห็นผลของชุดที่ 1**
แม้จะมีด่านพิสูจน์รองรับและมีหลักฐานว่าการเปลี่ยนไม่ได้ขับเคลื่อนด้วยผล
ข้อนี้ต้องระบุทุกครั้งที่อ้างผลของชุดที่ 2 และผู้อ่านมีสิทธิ์ให้น้ำหนักกับชุดที่ 1 มากกว่า

รายละเอียดข้อจำกัดทั้งหมดอยู่ในบทที่ 6 ซึ่งหัวข้อ 6.x.1 ถึง 6.x.12 เขียนไว้
ก่อนเห็นผลเปรียบเทียบของชุดที่ 1 และหัวข้อ 6.x.13 เพิ่มหลังชุดที่ 2
