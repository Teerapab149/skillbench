# บทที่ 7 — สรุปผลและข้อเสนอแนะ

> ตัวเลขทุกตัวในบทนี้อ้างอิงจากบทที่ 5 ซึ่งสร้างอัตโนมัติจาก `results/numbers.json`
> ห้ามแก้ตัวเลขในบทนี้โดยไม่แก้ที่ต้นทาง

---

## 7.1 สรุปสิ่งที่ทำ

งานวิจัยนี้ตั้งคำถามว่า **การบรรจุกฎการทำงานไว้ในไฟล์เดียวที่โหลดตลอดเวลา
กับการบรรจุกฎชุดเดียวกันไว้ใน skill ที่โหลดเมื่อจำเป็น ให้ผลต่างกันหรือไม่**
โดยคุมเนื้อหาของกฎให้เหมือนกันทุกตัวอักษร ต่างกันเฉพาะกลไกการส่งกฎถึงเอเจนต์

การทดลองใช้ 5 กลุ่ม (ไม่มีกฎ · ไฟล์เดียวโหลดตลอด · skill · ควบคุมเชิงความยาว ·
skill ที่มีลูกล่อ) กับโจทย์วิศวกรรมซอฟต์แวร์ 11 ข้อบนโครงงานจำลองเดียวกัน
ตัดสินด้วยตัวตรวจที่เป็นโปรแกรมล้วน ไม่มีคนหรือ LLM ให้คะแนน
และประกาศสมมติฐาน ตัวชี้วัด และแผนวิเคราะห์ไว้ล่วงหน้าก่อนเก็บข้อมูลเปรียบเทียบ

เก็บข้อมูลได้ **220 run** (4 รอบ × 11 โจทย์ × 5 กลุ่ม, 44 run ต่อกลุ่มเท่ากันทุกกลุ่ม)
ตามกฎสำรองที่ประกาศไว้ล่วงหน้าเมื่อชนโควตาการใช้งาน

## 7.2 ข้อสรุปหลัก

**การเปรียบเทียบหลัก (skill เทียบกับไฟล์เดียวโหลดตลอด บนตัวชี้วัด CRIT) สรุปไม่ได้**

ผลต่างที่วัดได้เป็นบวกเล็กน้อยในทิศทางของ skill แต่ช่วงความเชื่อมั่นคร่อมศูนย์
และค่า p ไม่ถึงระดับนัยสำคัญ

**เหตุผลที่ต้องเขียนว่า "สรุปไม่ได้" ไม่ใช่ "ไม่ต่างกัน"** เป็นเรื่องเลขคณิตที่รู้ล่วงหน้า:
การทดสอบหลักเป็นการสลับเครื่องหมายที่ระดับโจทย์ หน่วยข้อมูลจึงเป็นโจทย์ 11 ข้อ
ไม่ใช่ run 220 run และโจทย์ที่สองกลุ่มได้คะแนนเท่ากันจะไม่ให้ข้อมูลเลย
ในข้อมูลชุดนี้เหลือโจทย์ที่ผลต่างไม่เป็นศูนย์เพียง 5 ข้อ ทำให้ค่า p ต่ำที่สุด
ที่การออกแบบมีทางได้เท่ากับ 0.063 — **นัยสำคัญที่ระดับ 0.05 เป็นไปไม่ได้
ตั้งแต่ก่อนเห็นข้อมูล ไม่ว่าผลจะออกทางใด**

ดังนั้นงานนี้จึง **ไม่มีหลักฐานว่ากลไกทั้งสองต่างกัน และไม่มีหลักฐานว่าเหมือนกัน**
ทั้งสองข้อความต้องเขียนคู่กันเสมอ

**ตัวชี้วัดร่วม (RCR) ไม่ถูกนำมาอ้าง** เพราะประกาศไว้ล่วงหน้าว่าจะตีความได้
ก็ต่อเมื่อตัวชี้วัดหลักให้ผลชัดเจนก่อน เงื่อนไขนั้นไม่เกิดขึ้น
ค่าที่วัดได้จึงรายงานไว้เป็นข้อมูลประกอบเท่านั้น ไม่ใช่ข้อสรุป

## 7.3 ข้อสังเกตที่ต้องรายงานแม้จะไม่ใช่ข้อสรุป

**กลุ่มควบคุมเชิงความยาวไม่ได้ทำได้แย่กว่ากลุ่มที่มีกฎ** ซึ่งสอดคล้องกับข้อจำกัด
ที่ระบุไว้ล่วงหน้าใน 6.x.5 ว่ากลุ่มนี้ไม่ใช่ยาหลอกที่พิสูจน์แล้วว่าไม่มีผลทางความหมาย
ข้อสังเกตนี้ไม่ใช่ข้อค้นพบ เพราะการเปรียบเทียบที่เกี่ยวข้องกับกลุ่มนี้
ถูกประกาศไว้ล่วงหน้าว่าเป็น secondary และกำลังการทดสอบก็ไม่พอเช่นเดียวกัน
แต่ต้องรายงานเพราะการละไว้จะทำให้ภาพรวมบิดเบือน

**กลุ่มที่ไม่มีกฎเลยไม่ได้ทำได้แย่กว่ากลุ่มที่มีกฎอย่างชัดเจน** ซึ่งชี้กลับไปที่
คำถามที่อยู่นอกขอบเขตของงานนี้ คือกฎชุดที่ใช้ทดลองมีผลต่อพฤติกรรมมากพอ
จะวัดได้ด้วยเครื่องมือนี้หรือไม่ ตั้งแต่ต้น

**เพดานงบ turn ไม่ binding** — ไม่มี run ใดในชุดข้อมูลสุดท้ายใช้ turn จนหมดงบ
ผลที่ได้จึงไม่ใช่ผลของการถูกตัดกลางคัน

## 7.4 สิ่งที่งานนี้ให้ไว้จริง

เมื่อผลเปรียบเทียบสรุปไม่ได้ สิ่งที่เหลือเป็นผลงานคือ **วิธีวิทยาและเครื่องมือ**
ซึ่งออกแบบมาเพื่อให้การทดลองแบบนี้ทำซ้ำและตรวจสอบได้:

- **การคุมเนื้อหากฎให้เท่ากันตรวจสอบได้ด้วยเครื่อง** ไม่ใช่ด้วยคำยืนยันของผู้วิจัย
- **การตรึงสภาพเครื่องมือไว้แล้วตรวจซ้ำทุก run** ซึ่งจับได้จริงว่าชุด skill
  ที่ติดมากับเครื่องมือเปลี่ยนเองระหว่างเก็บข้อมูล และปฏิเสธ run นั้นทิ้ง
- **สมุดบันทึกความพยายามแบบเพิ่มอย่างเดียว** ที่แยก "ถูกขัดจังหวะ" ออกจาก "ล้มเหลวจริง"
  ทำให้การหยุดกลางคันไม่กลายเป็นข้อมูลที่ผิดเงียบ ๆ
- **กฎสำรองที่ประกาศไว้ก่อนเห็นข้อมูล** ทำให้การปิดการเก็บข้อมูลก่อนครบ
  เป็นการทำตามแผน ไม่ใช่การเลือกจุดหยุดหลังเห็นผล
- **สายการผลิตตัวเลขที่มีต้นทางเดียว** เอกสารผลและสไลด์ถูกสร้างจากไฟล์ตัวเลขไฟล์เดียว
  และมีด่านตรวจที่ทำให้เอกสารที่ไม่ตรงกับข้อมูลผ่านไปไม่ได้

ระหว่างเก็บข้อมูลจริง ระบบถูกยุติกลางคันโดยไม่ทราบสาเหตุ 4 ครั้ง
และชนขีดจำกัดการใช้งานอีกหลายครั้ง **โดยไม่สูญเสียข้อมูลที่เก็บแล้วแม้แต่ run เดียว**
ซึ่งเป็นหลักฐานเชิงปฏิบัติของข้อออกแบบข้างต้น

## 7.5 ข้อเสนอแนะสำหรับงานถัดไป

**ข้อที่สำคัญที่สุด: เพิ่มจำนวนโจทย์ ไม่ใช่จำนวนรอบ** เพราะหน่วยข้อมูลคือโจทย์
การเพิ่มรอบทำให้ค่าประมาณรายโจทย์แม่นขึ้นแต่ไม่เพิ่มกำลังการทดสอบ
ถ้าต้องการโอกาสถึงนัยสำคัญที่สมเหตุสมผล ต้องออกแบบให้มีโจทย์ที่แยกแยะได้
มากกว่า 6 ข้ออย่างมั่นใจ ซึ่งแปลว่าต้องมีโจทย์รวมมากกว่า 11 ข้ออย่างมีนัย

**ออกแบบตัวชี้วัดที่ไม่ใช่การ "และ" กันของกฎทุกข้อ** เป็นตัวชี้วัดหลัก
เพราะตัวชี้วัดแบบนั้นผลักคะแนนไปกองที่ศูนย์ ทำให้โจทย์จำนวนมากไม่ให้ข้อมูล

**พิสูจน์ว่ากลุ่มควบคุมเชิงความยาวเฉื่อยจริง** ก่อนใช้เป็นฐานเปรียบเทียบ
มิฉะนั้นการตีความทุกคู่ที่เกี่ยวข้องกับกลุ่มนี้จะค้างอยู่ที่ "แยกไม่ออก"

**แยกผู้ออกแบบตัวตรวจออกจากผู้ออกแบบกฎ** เพื่อตัดสมมติฐานที่ผิดร่วมกัน
ซึ่งกลไกตรวจสอบอัตโนมัติทั้งหมดในงานนี้จับไม่ได้

**วางแผนรับมือกับการที่สภาพของเครื่องมือเปลี่ยนเองระหว่างเก็บข้อมูล**
งานนี้ตรวจจับได้เฉพาะสิ่งที่ปรากฏใน metadata ของเครื่องมือ
หากผู้ให้บริการเปลี่ยนพฤติกรรมของโมเดลโดยไม่เปลี่ยนสิ่งเหล่านั้น จะตรวจไม่พบ

## 7.6 ข้อจำกัดของข้อสรุปในบทนี้

ข้อสรุปทั้งหมดผูกกับ: โมเดลหนึ่งตัว · เครื่องมือบรรทัดคำสั่งหนึ่งตัวและรุ่นเดียว ·
โครงงานจำลองหนึ่งโครงงาน · ชุดกฎหนึ่งชุดที่ผู้วิจัยเขียนเอง · และเพดานงบ turn ค่าหนึ่ง
การขยายผลไปยังกฎชุดอื่น โจทย์ประเภทอื่น หรือเครื่องมืออื่น ไม่มีหลักฐานรองรับจากงานนี้

รายละเอียดข้อจำกัดทั้งหมดอยู่ในบทที่ 6 ซึ่งเขียนไว้ก่อนเห็นผลเปรียบเทียบระหว่างกลุ่ม
