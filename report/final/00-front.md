รายงานฉบับนี้เป็นส่วนหนึ่งของรายวิชา 477-401 สัมมนาระบบสารสนเทศทางธุรกิจ จัดทำขึ้นเพื่อศึกษาว่า การเขียนกฎให้เอเจนต์เขียนโค้ดในรูปแบบ Agent Skills ทำให้เอเจนต์ปฏิบัติตามกฎได้ต่างจากการเขียนกฎไว้ในไฟล์เดียวหรือไม่ เนื้อหาครอบคลุมแนวคิดที่เกี่ยวข้อง การออกแบบการทดลอง ระบบวัดผลที่ผู้จัดทำพัฒนาขึ้น ผลการทดลอง การอภิปรายผล และข้อเสนอแนะสำหรับทีมพัฒนาที่นำเอเจนต์ไปใช้งาน

งานนี้ทดลองสามชุด สองชุดแรกให้ผลที่สรุปไม่ได้ แต่ทำให้พบข้อบกพร่องของเครื่องมือวัดที่ต้องแก้ ชุดที่สามจึงออกแบบใหม่ ประกาศแผนการวิเคราะห์ไว้ล่วงหน้า และได้ข้อสรุปที่ตอบคำถามวิจัยได้ ผู้จัดทำรายงานส่วนเบี่ยงเบนจากแผนทุกข้อไว้ในเล่ม และเปิดเผยโค้ด ข้อมูล และประวัติการแก้ไขทั้งหมดไว้ใน repository ของโครงการ เพื่อให้ผู้อ่านตรวจสอบและทำซ้ำได้

งานนี้เกี่ยวข้องกับปัญญาประดิษฐ์สองบทบาทที่แยกจากกัน บทบาทแรกคือ *สิ่งที่ถูกทดลอง* ได้แก่โมเดล Claude Sonnet 5 ที่ทำงานผ่าน Claude Code ในการทดลองทั้ง 264 run บทบาทที่สองคือ *เครื่องมือและผู้ช่วยของผู้จัดทำ* ผู้จัดทำใช้ Claude (Anthropic) เป็นเครื่องมือในงานต่อไปนี้ ได้แก่ ร่างเอกสารแผนการทดลองและโจทย์ตามที่ผู้จัดทำกำหนด เขียนและแก้โค้ดของระบบวัดผล เฝ้าติดตามการรันแต่ละรอบแทนผู้จัดทำ ช่วยวิเคราะห์ข้อมูล ตรวจทานแผนด้วย session แยก และช่วยเรียบเรียงร่างของรายงานฉบับนี้ ข้อเท็จจริงที่ว่าเครื่องมือนี้เป็นโมเดลตระกูลเดียวกับที่ถูกทดลอง ได้ระบุไว้เป็นข้อจำกัดในหัวข้อ 6.4.

<!-- D6-EDIT-1: แยกย่อหน้า, เปลี่ยน "ลงนามรับรองแผนด้วยตนเอง" เป็น "อนุมัติแผนด้วยตนเองผ่านแชท…", เปลี่ยนการหยุดที่ 3 รอบจาก "ผู้จัดทำตัดสินใจ" เป็นลำดับเหตุการณ์ D3 แล้ว D6 (ผู้วิจัยต้องตรวจว่าตรงความจริง) -->
ผู้จัดทำเป็นผู้คิดหัวข้อและคำถามวิจัย และเป็นผู้ตัดสินใจเรื่องหลัก ทั้งการออกแบบการทดลอง การเก็บข้อมูล และการวิเคราะห์ ผู้จัดทำอนุมัติแผนด้วยตนเองผ่านช่องแชทของเครื่องมือ ซึ่งบันทึกชื่อและเวลาลงเอกสารก่อนล็อกด้วย git tag ส่วนการหยุดเก็บข้อมูลที่ 3 รอบ ผู้จัดทำสั่งหยุดตั้งแต่วันที่ 9 ต.ค. และเมื่อทบทวนอีกครั้งในวันที่ 10 ต.ค. ได้ให้ Claude ประเมินจากข้อมูลแบบไม่แยกกลุ่มก่อนยืนยันการหยุด (หัวข้อ 3.7.3. และภาคผนวก ข) ผู้จัดทำตรวจผลและข้อความทั้งหมด และรับผิดชอบต่อเนื้อหาและข้อผิดพลาดของรายงาน เอกสารทำงานที่คัดมาไว้ในภาคผนวก ก และ ข เขียนขึ้นระหว่างใช้เครื่องมือนี้ จึงมีถ้อยคำบางจุดที่เรียก Claude ว่า "ผู้ออกแบบ" หรือ "ผู้ช่วย" ผู้จัดทำคงข้อความเดิมไว้ตามต้นฉบับ และใส่หมายเหตุอธิบายกำกับไว้

ผู้จัดทำขอขอบพระคุณ ผู้ช่วยศาสตราจารย์ ดร.รุชดี บิลหมัด อาจารย์ที่ปรึกษา ที่ให้คำแนะนำตลอดการทำงาน และหวังว่ารายงานฉบับนี้จะเป็นประโยชน์ต่อผู้ที่สนใจการนำเอเจนต์ปัญญาประดิษฐ์ไปใช้ในงานพัฒนาระบบ

**คำถาม** ทีมพัฒนาที่ใช้ AI ช่วยเขียนโค้ด (ในรายงานนี้เรียกว่า *เอเจนต์*) ต้องแจ้งกฎของทีมให้เอเจนต์ทราบ เช่น แก้เฉพาะส่วนที่สั่ง ห้ามลบข้อมูล และต้องตรวจผลกระทบก่อนแก้ส่วนที่คิดเงิน วิธีแจ้งกฎมีสองแบบหลัก คือเขียนกฎทุกข้อไว้ในไฟล์เดียวที่เอเจนต์อ่านทุกครั้ง หรือใช้ Agent Skills ซึ่งแยกกฎเป็นชุดย่อยให้เอเจนต์เปิดอ่านเฉพาะชุดที่เกี่ยวกับงาน งานนี้ถามว่าสองแบบทำให้เอเจนต์ทำตามกฎได้ต่างกันหรือไม่

**วิธีทดลอง** ผู้จัดทำสร้างระบบจองเครื่อง GPU จำลองและโจทย์ที่มีกับดัก เช่น คอมเมนต์ในโค้ดที่สั่งให้ทำสิ่งที่ผู้ใช้ไม่ได้ขอ แล้วให้เอเจนต์ตัวเดียวกันทำโจทย์ภายใต้กฎหลายรูปแบบ ให้คะแนนด้วยโปรแกรมจากสิ่งที่เอเจนต์ทำจริง และล็อกวิธีวิเคราะห์ไว้ก่อนเก็บข้อมูลทุกครั้ง การทดลองมีสามชุด ชุดที่ 1 (220 ครั้ง) และชุดที่ 2 (176 ครั้ง) สรุปไม่ได้ ส่วนหนึ่งเพราะตัวชี้วัด จำนวนโจทย์ และตัวตรวจบางข้อยังบกพร่อง ชุดที่ 3 แก้ข้อจำกัดเหล่านั้น ใช้โจทย์ 22 ข้อ 4 เงื่อนไข (ไม่มีกฎ กฎไฟล์เดียว Agent Skills และข้อความเดียวกับ Agent Skills ที่ให้อ่านตลอดเวลา) รวม 264 ครั้ง

**ผลที่พบ**

1. รูปแบบของกฎไม่ทำให้ผลต่างกันเกินเกณฑ์ (ผลหลัก) Agent Skills ได้คะแนนสูงกว่าไฟล์เดียวเฉลี่ย 2.8 จุดจาก 100 ช่วงความเชื่อมั่น 90% (−0.1 ถึง +5.8 จุด) อยู่ในเกณฑ์ ±12.5 จุดที่ตั้งไว้ล่วงหน้าทั้งช่วง จึงสรุปว่า*เทียบเท่า*กัน เนื่องจากไฟล์เดียวได้ 94.5% อยู่แล้ว สิ่งที่ยืนยันได้ชัดคือ Agent Skills *ไม่ด้อยกว่า*ไฟล์เดียว แต่ตรวจข้อได้เปรียบขนาดใหญ่ไม่ได้ (หัวข้อ 6.4.)
2. การมีกฎสัมพันธ์กับการทำตามกฎมากกว่ารูปแบบของกฎ (เชิงสำรวจ) เอเจนต์ที่ไม่ได้รับกฎผ่านกฎสำคัญครบราวครึ่งหนึ่งของครั้ง เทียบกับราวสี่ในห้าเมื่อได้รับกฎ และไม่ตรวจหรือไม่รายงานผลกระทบต่อใบแจ้งหนี้ย้อนหลังใน 25% ของครั้งที่มีโอกาส เทียบกับไม่เกิน 3% เมื่อได้รับกฎ บนคะแนนหลัก ไฟล์เดียวสูงกว่าไม่มีกฎ 9.5 จุด แต่ยังสรุปไม่ได้ และแยกไม่ได้ว่าความต่างมาจากเนื้อหาของกฎหรือจากข้อความที่เพิ่มในบริบท
3. Agent Skills ใช้ต้นทุนต่ำกว่าราว 10% (เชิงสำรวจ) และเร็วกว่าราว 30 วินาทีต่องาน ข้อมูลยังไม่พอบอกว่าเกี่ยวกับการโหลดกฎเฉพาะส่วนหรือไม่
4. ยังตอบไม่ได้ว่ากลไก "เปิดอ่านเฉพาะที่ใช้" มีผลหรือไม่ เพราะตามแผนที่ล็อกไว้ การเปรียบเทียบนั้นทดสอบได้เฉพาะเมื่อผลหลักพบความต่าง

**ข้อเสนอแนะ** ทีมพัฒนาเลือกรูปแบบของกฎได้ตามความสะดวกในการดูแลและต้นทุน แต่ควรให้เอเจนต์มีกฎที่ครอบคลุมขอบเขตงานและการตรวจผลกระทบต่อข้อมูลเดิม ถ้าใช้ Agent Skills ควรตรวจว่าคำอธิบายของแต่ละ skill ทำให้ถูกโหลดในงานที่ควรโหลด และเปิดช่องให้เอเจนต์ถามได้เมื่อพบข้อกำหนดที่ไม่ชัดเจน ผลนี้มาจากโมเดลเดียว (Claude Sonnet 5) คำสั่งภาษาไทย และระบบจำลองหนึ่งระบบ จึงไม่ควรนำไปใช้กับเงื่อนไขที่ต่างออกไปมากโดยไม่ทดสอบซ้ำ
