# 6. อภิปรายผลและข้อจำกัด

## 6.1. มีกฎหรือไม่ต่างกันมาก แต่รูปแบบของกฎต่างกันไม่เกินเกณฑ์

ผลของชุดที่ 3 แยกออกเป็นสองระดับที่ชัดเจน ระดับแรกคือการมีกฎเทียบกับไม่มีกฎ เอเจนต์ที่ไม่ได้รับกฎใดเลย (A0) ทำงานสำเร็จได้เกือบเท่ากลุ่มอื่น แต่ผ่านกฎ critical ครบน้อยกว่าและแตะไฟล์นอกขอบเขตบ่อยกว่าชัดเจน (ตารางที่ 13) การเปรียบเทียบนี้เป็นเชิงสำรวจ แต่ความต่างใหญ่และชี้ทางเดียวกันทุกตัวชี้วัด ระดับที่สองคือรูปแบบของกฎ การทดสอบตามแผนสรุปได้ว่า Agent Skills (A2) กับไฟล์กฎไฟล์เดียว (A1) ให้ RCRc เทียบเท่ากันภายในเกณฑ์ที่ตั้งไว้ (ตารางที่ 10) และข้อสรุปนี้คงเดิมภายใต้การวิเคราะห์ความไวทั้งสองแบบ (ตารางที่ 11)

เมื่อแยก RCRc ออกเป็นสองส่วน (ตารางที่ 13ก) จะเห็นว่าผลต่างเล็กน้อยที่เหลืออยู่มาจากการทำงานสำเร็จ ไม่ใช่จากการทำตามกฎ ในงานที่ทำเสร็จ สองรูปแบบทำตามกฎได้เกือบเท่ากันทุกประการ ข้อสังเกตนี้มาจากการวิเคราะห์เชิงสำรวจ แต่ช่วยตอบคำถามที่ตัวเลข RCRc ตัวเดียวตอบไม่ได้ ว่าความต่างอยู่ที่ส่วนไหน

ผลระดับแรกสอดคล้องกับข้อสังเกตเชิงคุณภาพของรายงานสัมมนาปีการศึกษา 2568 (ศุภกร กรอบเพ็ชร และ ศศิชา โสมวิภาต, 2568) ที่พบว่าเอเจนต์ที่มีบริบทปฏิเสธคำสั่งที่อาจทำลายโปรเจกต์ ขณะที่เอเจนต์ที่ไม่มีบริบทพยายามทำตาม งานนี้ยืนยันทิศทางเดียวกันด้วยข้อมูล 264 run โดย A0 แตะไฟล์ข้อมูลและทำให้ข้อมูลย้อนหลังเปลี่ยนบ่อยกว่ากลุ่มที่มีกฎหลายเท่า (ตารางที่ 14ก)

ผลระดับที่สองขัดกับความคาดหวังที่อยู่เบื้องหลังแนวคิดการโหลดเฉพาะส่วนที่เกี่ยวข้อง (progressive disclosure) ว่าการไม่ใส่กฎที่ไม่เกี่ยวข้องเข้าบริบทจะช่วยให้เอเจนต์ทำตามกฎที่เกี่ยวข้องได้ดีขึ้น งานด้านบริบทยาวอย่าง Lost in the Middle (Liu et al., 2024) ชี้ว่าข้อมูลที่อยู่กลางบริบทยาวถูกใช้น้อยลง แต่กฎของ A1 ยาวเพียงราว 2,000 token ซึ่งสั้นมากเมื่อเทียบกับบริบทของงานจริงที่อ่านไฟล์และเรียกเครื่องมือรวมหลายแสน token (ตารางที่ 14) ที่ขนาดนี้ การโหลดกฎทั้งหมดตลอดเวลาจึงอาจยังไม่ถึงจุดที่ทำให้กฎถูกมองข้าม ข้อสรุปของงานนี้จึงใช้ได้กับชุดกฎขนาดนี้ และยังไม่ได้ตอบว่าเมื่อกฎยาวขึ้นหลายเท่า ผลจะเหมือนเดิมหรือไม่

ข้อมูลการโหลด skill ช่วยอธิบายผลอีกทางหนึ่ง A2 โหลด skill เพียงบางตัวในเกือบทุก run (ตารางที่ 17) แต่ยังได้ผลเทียบเท่า A1 ที่เห็นกฎครบทุกข้อตลอดเวลา แปลว่าในงานส่วนใหญ่ เอเจนต์เลือกโหลดเฉพาะ skill ที่เกี่ยวกับงานได้ถูกพอ และ skill ที่ไม่ได้โหลดมักเป็นกฎที่งานนั้นไม่ต้องใช้ ข้อมูล Trigger F1 สนับสนุนการตีความนี้ skill ที่ผูกกับงานแก้โค้ดทุกงานอย่าง `trace-to-requirement` ถูกเรียกเกือบตรงทุกครั้ง ส่วน `impact-analysis` ถูกเรียกเกินจำเป็นบ่อย ความผิดพลาดของการโหลดจึงเอียงไปทางโหลดเกิน ซึ่งเสียเพียงต้นทุน ไม่ได้ทำให้กฎหายไป

ส่วนคำถามเรื่องกลไกการโหลด ซึ่งตอบด้วยคู่ A2 กับ A5 ที่ใช้ข้อความเหมือนกันทุกตัวอักษร งานนี้**ยังตอบไม่ได้** ตามแผนการทดสอบแบบลำดับตายตัว คู่นี้ทดสอบได้ก็ต่อเมื่อผลหลักพบความต่าง ซึ่งไม่พบ ค่าประมาณของคู่นี้ใกล้ศูนย์ (ตารางที่ 12) แต่เป็นตัวเลขที่ไม่ได้ทดสอบ จึงใช้ได้เพียงเป็นข้อมูลสำหรับวางแผนงานถัดไป ไม่ใช่หลักฐานว่ากลไกการโหลดไม่มีผล

## 6.2. ทำไมชุดที่ 3 สรุปได้ ขณะที่สองชุดแรกสรุปไม่ได้

ผลต่างเฉลี่ยของทั้งสามชุดชี้ไปทางเดียวกัน คือ A2 สูงกว่า A1 เล็กน้อย (ตารางที่ 19) สิ่งที่ทำให้ชุดที่ 3 สรุปได้จึงไม่ใช่ข้อมูลที่ "โชคดี" แต่มาจากการเปลี่ยนแปลงสามอย่าง

**อย่างแรก คำถามที่ถามเปลี่ยนไป** สองชุดแรกถามว่า "สองวิธีต่างกันหรือไม่" ซึ่งถ้าความต่างจริงเล็ก จะต้องใช้ข้อมูลจำนวนมากจึงจะเห็นนัยสำคัญ ชุดที่ 3 เพิ่มคำถามว่า "สองวิธีต่างกันเกินเกณฑ์ที่มีความหมายหรือไม่" ซึ่งตอบได้ด้วยข้อมูลที่มี เมื่อความต่างจริงเล็ก

**อย่างที่สอง เครื่องมือวัดถูกแก้** ในชุดที่ 2 โจทย์ 3 ใน 6 ข้อที่เสมอกันเสมอเพราะเครื่องมือวัดบกพร่อง โจทย์ที่ให้ข้อมูลจึงเหลือน้อย ชุดที่ 3 แก้โจทย์เหล่านั้น เพิ่มโจทย์เป็น 22 ข้อ และให้ทุกโจทย์ผ่านด่านยอมรับห้าด่านก่อนใช้

**อย่างที่สาม การหยุดถามไม่ถูกลงโทษอีกต่อไป** ผู้วิจัยทำนายไว้ในแผนว่า ความได้เปรียบของ A2 ในชุดที่ 2 มาจากการที่ A1 หยุดถามบ่อยกว่าแล้วถูกนับว่างานไม่สำเร็จ และรอบตอบกลับน่าจะลบความได้เปรียบนี้ ผลของชุดที่ 3 เป็นไปตามคำทำนาย ผลต่างลดจาก +11.0 จุดเหลือ +2.8 จุด และ run ของกลุ่มที่มีกฎซึ่งหยุดถามในรอบแรก ส่วนใหญ่ทำงานต่อจนสำเร็จหลังได้รอบตอบกลับ (ตารางที่ 16) ข้อนี้เตือนว่า การวัดเอเจนต์แบบรอบเดียวอาจลงโทษพฤติกรรมที่ผู้ใช้ต้องการ คือการถามเมื่อไม่แน่ใจ

## 6.3. ข้อเสนอแนะเชิงปฏิบัติ

สำหรับทีมพัฒนาที่ใช้เอเจนต์เขียนโค้ด ผลของงานนี้นำไปใช้ได้ดังนี้

1. **เขียนกฎให้เอเจนต์** ในการทดลองนี้ ความต่างระหว่างมีกฎกับไม่มีกฎใหญ่กว่าความต่างระหว่างรูปแบบของกฎหลายเท่า เอเจนต์ที่ไม่มีกฎทำงานสำเร็จได้ แต่แก้ไฟล์นอกขอบเขต ทำให้ใบแจ้งหนี้ย้อนหลังเปลี่ยน และแตะไฟล์ข้อมูลบ่อยกว่ากลุ่มที่มีกฎหลายเท่า (ตารางที่ 14ก) ส่วนกฎเรื่องห้ามทำเกินสั่งกลับตกพอ ๆ กันทุกกลุ่ม แปลว่ากฎที่เขียนไว้ยังกันการทำเกินสั่งได้ไม่ดี
2. **เลือกรูปแบบตามการดูแลรักษาและต้นทุน ไม่ใช่ตามความเชื่อว่าแบบใดเชื่อฟังกว่า** ในการทดลองนี้ ซึ่งชุดกฎยาวราว 2,000–3,300 token และใช้โมเดลเดียว สองรูปแบบให้ผลเทียบเท่ากัน Agent Skills ใช้ต้นทุนต่ำกว่าเล็กน้อยในชุดข้อมูลนี้ (ตารางที่ 14 · เชิงพรรณนา) และแยกกฎเป็นหมวดที่แก้ไขง่าย ส่วนไฟล์เดียวง่ายกว่าและไม่ต้องกังวลว่าเอเจนต์จะเลือกโหลดถูกหรือไม่
3. **ถ้าใช้ Agent Skills ให้ตรวจคำอธิบายของ skill** คำอธิบายคือสิ่งที่ตัดสินว่า skill จะถูกโหลดเมื่อใด skill ที่คำอธิบายกว้างเกินจะถูกโหลดในงานที่ไม่เกี่ยว ส่วน skill ที่คำอธิบายแคบเกินอาจไม่ถูกโหลดเมื่อจำเป็น
4. **เปิดช่องให้เอเจนต์ถามได้** เอเจนต์ที่มีกฎหยุดถามเมื่อเจอข้อกำหนดกำกวมหรือขัดกัน และทำงานต่อได้ดีเมื่อได้คำตอบ ระบบงานที่ไม่มีใครตอบคำถามของเอเจนต์จะเสียประโยชน์ส่วนนี้ไป

## 6.4. ข้อจำกัดของการวิจัย

1. **โมเดล เครื่องมือ และภาษาอย่างละหนึ่ง** ทุก run ใช้ Claude Sonnet 5 ผ่าน Claude Code รุ่นเดียว และใช้คำสั่งภาษาไทย ผลอาจต่างไปกับโมเดลอื่น เครื่องมืออื่น หรือคำสั่งภาษาอังกฤษ
2. **ระบบจำลองหนึ่งระบบ และชุดโจทย์ที่ผู้วิจัยสร้าง** โจทย์ถูกออกแบบให้มีกับดักที่แยกพฤติกรรมได้ ข้อสรุปจึงใช้กับชุดโจทย์ประเภทนี้ ไม่ใช่งานเขียนโค้ดทั่วไป
3. **ผู้ออกแบบใกล้ชิดกับสิ่งที่ถูกทดสอบ** ผู้วิจัยเขียนทั้งกฎ โจทย์ และตัวตรวจ โดยมี Claude ช่วยออกแบบและเขียนโค้ด ซึ่งเป็นโมเดลตระกูลเดียวกับที่ถูกทดสอบ การล็อกแผนล่วงหน้าและการเปิดเผยสิ่งที่เห็นก่อนออกแบบลดความเสี่ยงนี้ได้ แต่ไม่ได้ขจัด
4. **คะแนนใกล้เพดาน** กลุ่มที่มีกฎได้ RCRc เฉลี่ย 94–97% และโจทย์ 14 จาก 22 ข้อได้ค่าเท่ากันระหว่าง A2 กับ A1 เพดานนี้จำกัดโอกาสที่จะเห็นความต่าง ถ้าโจทย์ยากขึ้น ความต่างอาจปรากฏ
5. **เทียบเท่าไม่ได้แปลว่าเหมือนกัน** ข้อสรุปคือความต่างไม่เกิน ±12.5 จุด ความต่างที่เล็กกว่านั้น เช่น 3 จุดที่สังเกตได้ อาจมีจริง แต่ข้อมูลชุดนี้แยกไม่ออกจากความบังเอิญ
6. **ข้อความของ A1 กับ A2 ต่างกันทั้งถ้อยคำและความยาว** แม้ข้อผูกพันจะเท่ากันทุกข้อ ข้อสรุปจากคู่นี้จึงเป็นเรื่องของชิ้นงานสองแบบ ไม่ใช่กลไกการโหลดล้วน ๆ
7. **ตัวตรวจที่บกพร่อง 3 จุดพบหลังล็อกแผน** ผลหลักใช้ตัวตรวจเดิมตามแผน และการวิเคราะห์ความไวทั้งสองแบบให้ข้อสรุปเดียวกัน แต่ข้อบกพร่องนี้แสดงว่าด่านตรวจก่อนเก็บข้อมูลยังจับปัญหาไม่ได้ทั้งหมด
8. **เก็บข้อมูลได้ 3 จาก 4 รอบที่วางแผนไว้** การหยุดที่ 3 รอบเป็นไปตามกฎสำรองที่ประกาศไว้ และตัดสินก่อนดูผลแยกกลุ่ม การคาดการณ์แบบไม่แยกกลุ่มชี้ว่ารอบที่ 4 จะทำให้ช่วงความเชื่อมั่นแคบลงเพียงเล็กน้อย
9. **รอบตอบกลับเป็นข้อความตายตัว** ไม่ใช่การตอบของผู้ใช้จริง ผู้ใช้จริงอาจตอบคำถามได้ ซึ่งอาจทำให้ผลต่างออกไป
10. **ผลต่างส่วนใหญ่มาจากโจทย์ไม่กี่ข้อ** ผลต่าง +2.8 จุดมีส่วนจาก S19 มากที่สุด เมื่อตัด S19 ออก ผลต่างเหลือ +1.3 จุด การวิเคราะห์นี้เป็นเชิงสำรวจ และไม่เปลี่ยนข้อสรุปเทียบเท่า
