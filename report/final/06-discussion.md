# 6. อภิปรายผลและข้อจำกัด

## 6.1. มีกฎหรือไม่ต่างกันมาก แต่รูปแบบของกฎต่างกันไม่เกินเกณฑ์

ผลจากการทดลองชุดที่ 3 ควรมองแยกเป็น 2 คำถาม คำถามแรกคือการมีกฎช่วยให้เอเจนต์ทำตามข้อกำหนดได้ดีขึ้นหรือไม่ การเปรียบเทียบเชิงสำรวจพบว่า A0 ซึ่งไม่มีกฎทำงานสำเร็จได้ใกล้เคียงกับกลุ่มอื่น แต่ผ่านกฎ critical ครบน้อยกว่าและแก้ไฟล์นอกขอบเขตบ่อยกว่า (ตารางที่ 13) ความต่างนี้มีขนาดค่อนข้างมากและไปในทิศทางเดียวกันหลายตัวชี้วัด อย่างไรก็ตาม การเปรียบเทียบกับ A0 ไม่ใช่ผลหลักของงาน คำถามที่สองคือกฎสองรูปแบบให้ผลต่างกันหรือไม่ ผลหลักตามแผนสรุปว่า A2 และ A1 เทียบเท่ากันภายในเกณฑ์ที่กำหนด (ตารางที่ 10) และข้อสรุปนี้คงเดิมในการวิเคราะห์ความไวทั้งสองแบบ (ตารางที่ 11)

เมื่อนำ RCRc มาแยกดูเป็นสองส่วน (ตารางที่ 13ก) ผลต่างที่เห็นส่วนใหญ่สัมพันธ์กับอัตราการทำงานสำเร็จ ไม่ใช่อัตราการทำตามกฎเมื่อทำงานสำเร็จแล้ว ในการวิเคราะห์เชิงสำรวจนี้ ทั้งสองรูปแบบมีอัตราการทำตามกฎใกล้เคียงกันมาก ประเด็นนี้ช่วยอธิบายว่าทำไมค่า RCRc ซึ่งรวมสองเรื่องไว้ในตัวเลขเดียวจึงต่างกันเล็กน้อย

ผลการเปรียบเทียบ A0 กับกลุ่มที่มีกฎมีทิศทางเดียวกับข้อสังเกตจากรายงานสัมมนาในปีการศึกษา 2568 (ศุภกร กรอบเพ็ชร และ ศศิชา โสมวิภาต, 2568) ซึ่งพบว่าเอเจนต์ที่ได้รับบริบทปฏิเสธคำสั่งที่อาจทำให้โปรเจกต์เสียหาย ขณะที่เอเจนต์ที่ไม่ได้รับบริบทพยายามทำตามคำสั่งนั้น งานนี้พบรูปแบบใกล้เคียงกันจาก 264 run โดย A0 แตะไฟล์ข้อมูลและทำให้ข้อมูลย้อนหลังเปลี่ยนบ่อยกว่ากลุ่มที่มีกฎ (ตารางที่ 14ก) ทั้งนี้ การเปรียบเทียบนี้ยังเป็นเชิงสำรวจ

ผลหลักไม่ได้สนับสนุนความคาดหวังว่า การโหลดเฉพาะส่วนที่เกี่ยวข้องจะทำให้เอเจนต์ทำตามกฎได้ดีกว่าการเห็นกฎทั้งหมดตลอดเวลาเสมอไป งาน Lost in the Middle (Liu et al., 2024) พบว่าข้อมูลที่อยู่กลางบริบทยาวอาจถูกใช้น้อยลง แต่กฎของ A1 ในการทดลองนี้ยาวราว 2,000 token เท่านั้น ซึ่งสั้นมากเมื่อเทียบกับบริบทที่เอเจนต์ใช้อ่านไฟล์และเรียกเครื่องมือ ซึ่งรวมแล้วอาจมีหลายแสน token (ตารางที่ 14) จึงเป็นไปได้ว่ากฎขนาดนี้ยังไม่ยาวพอให้เกิดปัญหาจากการเห็นข้อมูลมากเกินไป ข้อสรุปจึงจำกัดอยู่ที่ชุดกฎขนาดนี้ และยังไม่ตอบว่าผลจะเป็นอย่างไรหากกฎยาวขึ้นหลายเท่า

ข้อมูลการโหลด skill ช่วยอธิบายผลอีกด้านหนึ่ง: A2 โหลด skill เพียงบางตัวในเกือบทุก run แต่ยังให้ผลเทียบเท่ากับ A1 ที่เห็นกฎครบทุกข้อตลอดเวลา (ตารางที่ 17) ข้อมูลนี้ชี้ว่าในโจทย์ส่วนใหญ่ เอเจนต์เลือกโหลด skill ที่เกี่ยวข้องได้เหมาะสมพอ และ skill ที่ไม่ได้โหลดมักเป็นกฎที่โจทย์นั้นไม่ต้องใช้ ค่า Trigger F1 ก็สนับสนุนการตีความนี้ โดย `trace-to-requirement` ถูกเรียกเกือบทุกครั้งที่ควรเรียก ส่วน `impact-analysis` ถูกเรียกเกินจำเป็นบ่อย ความผิดพลาดของการโหลดจึงเกิดจากการโหลดเกินมากกว่าการโหลดไม่ครบ ซึ่งเพิ่มต้นทุน แต่ไม่ได้ทำให้กฎหายไปจากบริบท

คำถามเรื่องกลไกการโหลดต้องเปรียบเทียบ A2 กับ A5 ซึ่งใช้ข้อความเหมือนกันทุกตัวอักษร งานนี้ยังตอบคำถามดังกล่าวไม่ได้ เพราะตามแผนแบบลำดับตายตัว จะทดสอบคู่นี้ได้ก็ต่อเมื่อผลหลัก A2 เทียบ A1 พบความต่าง แต่ผลหลักสรุปว่าเทียบเท่า แม้ค่าประมาณของ A2 เทียบ A5 จะอยู่ใกล้ศูนย์ (ตารางที่ 12) ก็เป็นเพียงค่าประมาณที่ไม่ได้ทดสอบ จึงใช้วางแผนการทดลองครั้งต่อไปได้เท่านั้น ไม่ใช่หลักฐานว่ากลไกการโหลดไม่มีผล

## 6.2. ทำไมชุดที่ 3 สรุปได้ ขณะที่สองชุดแรกสรุปไม่ได้

ค่าเฉลี่ยของผลต่างจากการทดลองทั้ง 3 ชุดไปในทิศทางเดียวกัน คือ A2 สูงกว่า A1 เล็กน้อย (ตารางที่ 19) เหตุผลที่ชุดที่ 3 สรุปผลได้ ขณะที่สองชุดแรกสรุปไม่ได้ ไม่ใช่เพราะผลชุดที่ 3 "โชคดี" แต่เป็นเพราะมีการปรับวิธีทดลอง 3 เรื่อง

ข้อแรก — ชุดที่ 3 เพิ่มเกณฑ์เพื่อตอบว่า ผลต่างมากพอจะมีความหมายในทางปฏิบัติหรือไม่ ไม่ได้ถามเพียงว่าพบความต่างหรือไม่ เมื่อความต่างจริงมีขนาดเล็ก การทดสอบแบบเดิมอาจต้องใช้ข้อมูลจำนวนมากจึงจะพบความต่างอย่างมีนัยสำคัญ

ข้อที่สอง — มีการแก้เครื่องมือวัด ในชุดที่ 2 โจทย์ 3 จาก 6 ข้อที่ได้คะแนนเสมอกันเกิดจากตัวตรวจบกพร่อง ไม่ใช่เพราะเอเจนต์ทำได้เท่ากัน ชุดที่ 3 แก้โจทย์เหล่านี้ เพิ่มจำนวนโจทย์เป็น 22 ข้อ และตรวจทุกโจทย์ผ่านด่านยอมรับทั้ง 5 ขั้นก่อนนำมาใช้

ข้อที่สาม — การหยุดถามไม่ได้ถูกนับเป็นงานไม่สำเร็จทันทีอีกต่อไป ผู้วิจัยคาดไว้ล่วงหน้าว่าความได้เปรียบของ A2 ในชุดที่ 2 ส่วนหนึ่งมาจาก A1 หยุดถามบ่อยกว่า และการหยุดถามถูกนับว่างานไม่สำเร็จ เมื่อมีรอบตอบกลับ ความได้เปรียบดังกล่าวควรลดลง ผลชุดที่ 3 เป็นไปตามที่คาด โดยผลต่างลดจาก +11.0 จุดเหลือ +2.8 จุด และ run ของกลุ่มที่มีกฎซึ่งหยุดถามในรอบแรกส่วนใหญ่ทำงานต่อจนสำเร็จหลังได้รับข้อความตอบกลับ (ตารางที่ 16) ข้อนี้แสดงว่าการประเมินแบบรอบเดียวอาจลงโทษพฤติกรรมที่ต้องการในงานจริง เช่น การหยุดถามเมื่อไม่แน่ใจ

## 6.3. ข้อเสนอแนะเชิงปฏิบัติ

สำหรับทีมที่ใช้เอเจนต์ช่วยเขียนโค้ด ผลจากการทดลองนี้นำไปใช้เป็นแนวทางได้ดังนี้

1. เริ่มจากเขียนกฎให้ชัด — ในการทดลองนี้ ความต่างระหว่างการมีกฎกับไม่มีกฎมากกว่าความต่างระหว่างรูปแบบของกฎหลายเท่า กลุ่มที่ไม่มีกฎยังทำงานสำเร็จได้ แต่แก้ไฟล์นอกขอบเขต ทำให้ใบแจ้งหนี้ย้อนหลังเปลี่ยน และแตะไฟล์ข้อมูลบ่อยกว่ากลุ่มที่มีกฎ (ตารางที่ 14ก) อย่างไรก็ตาม กฎที่ห้ามทำงานเกินคำสั่งยังถูกละเมิดในอัตราใกล้เคียงกันทุกกลุ่ม แสดงว่ากฎลักษณะนี้ยังต้องปรับปรุง
2. เลือกรูปแบบจากความสะดวกและต้นทุน — ไม่ควรเลือกเพราะเชื่อว่ารูปแบบหนึ่งจะทำให้ AI เชื่อฟังมากกว่า ในการทดลองนี้ ซึ่งใช้โมเดลเดียวและชุดกฎยาวราว 2,000–3,300 token ทั้งสองรูปแบบให้ผลเทียบเท่ากัน ข้อมูลเชิงพรรณนาชี้ว่า Agent Skills มีต้นทุนประเมินต่ำกว่าเล็กน้อย (ตารางที่ 14) อีกทั้งแบ่งกฎเป็นหมวดที่ดูแลแยกกันได้ ส่วนไฟล์เดียวจัดการง่ายกว่าและไม่ต้องพึ่งการเลือกโหลด skill ให้ตรงงาน
3. ตรวจคำอธิบายของ skill — คำอธิบายเป็นตัวช่วยให้เอเจนต์ตัดสินใจว่าจะโหลด skill ใด หากเขียนกว้างเกินไป skill อาจถูกโหลดในงานที่ไม่เกี่ยวข้อง แต่ถ้าแคบเกินไป เอเจนต์อาจไม่โหลด skill ในเวลาที่จำเป็น
4. เปิดโอกาสให้เอเจนต์ถาม — เมื่อพบข้อกำหนดที่กำกวมหรือขัดกัน เอเจนต์ที่มีกฎอาจหยุดเพื่อขอคำชี้แจง หากระบบงานไม่มีทางให้ใครตอบ ควรออกแบบวิธีจัดการคำถามไว้ เพราะการให้เอเจนต์ถามเป็นส่วนหนึ่งของการทำงานอย่างระมัดระวัง

## 6.4. ข้อจำกัดของการวิจัย

1. ใช้โมเดล เครื่องมือ และภาษาเพียงแบบเดียว — ทุก run ใช้ Claude Sonnet 5 ผ่าน Claude Code รุ่นเดียวและคำสั่งภาษาไทย ผลอาจต่างออกไปเมื่อใช้โมเดลหรือเครื่องมืออื่น หรือเปลี่ยนเป็นคำสั่งภาษาอังกฤษ
2. ใช้ระบบจำลองและโจทย์ชุดเดียว — ผู้วิจัยสร้างระบบจำลองและโจทย์ขึ้นเอง โดยออกแบบให้มีกับดักเพื่อแยกพฤติกรรมบางประเภท ผลจึงใช้สรุปกับโจทย์ลักษณะนี้ได้โดยตรง แต่ยังไม่ควรขยายไปสู่งานเขียนโค้ดทั่วไปทั้งหมด
3. ผู้วิจัยมีส่วนในการออกแบบสิ่งที่ทดสอบ — ผู้วิจัยเขียนกฎ โจทย์ และตัวตรวจ โดยใช้ Claude ช่วยออกแบบและเขียนโค้ดด้วย ซึ่งเป็นโมเดลตระกูลเดียวกับที่ถูกนำมาทดลอง การประกาศแผนล่วงหน้าและเปิดเผยข้อมูลที่เห็นก่อนออกแบบช่วยลดความเสี่ยงจากอคติ แต่ไม่สามารถขจัดความเสี่ยงนี้ได้ทั้งหมด
4. คะแนนอยู่ใกล้ค่าสูงสุด — กลุ่มที่มีกฎได้ RCRc เฉลี่ย 94–97% และ 14 จาก 22 โจทย์มีค่าเฉลี่ย A2 กับ A1 เท่ากัน เมื่อคะแนนสูงอยู่แล้ว พื้นที่ที่จะเห็นความต่างจึงเหลือน้อย หากใช้โจทย์ที่ยากขึ้น ผลอาจต่างออกไป
5. เทียบเท่าไม่ได้หมายความว่าเหมือนกันทุกด้าน — ข้อสรุปหมายถึงผลต่างอยู่ภายใน ±12.5 จุดตามเกณฑ์ที่กำหนด ไม่ได้หมายความว่าความต่างเป็นศูนย์ ความต่างขนาดเล็ก เช่น 3 จุดที่สังเกตได้ อาจมีจริง แต่ข้อมูลชุดนี้ยังแยกไม่ได้ชัดว่าเป็นความต่างจริงหรือความบังเอิญ
6. ข้อความกฎของ A1 และ A2 ไม่เหมือนกัน — แม้ข้อผูกพันของกฎจะเท่ากันทุกข้อ แต่ถ้อยคำและความยาวต่างกัน ดังนั้นข้อสรุปจาก A1 เทียบ A2 เป็นการเปรียบเทียบชุดกฎสองรูปแบบ ไม่ใช่ผลของกลไกการโหลดเพียงอย่างเดียว
7. พบตัวตรวจบกพร่องหลังล็อกแผน — พบข้อบกพร่อง 3 จุดหลังเริ่มเก็บข้อมูล ผลหลักยังใช้ตัวตรวจเดิมตามแผน และการวิเคราะห์ความไวทั้งสองแบบให้ข้อสรุปเดียวกัน อย่างไรก็ตาม เหตุการณ์นี้แสดงว่าการตรวจเครื่องมือก่อนเก็บข้อมูลยังไม่สามารถจับข้อผิดพลาดได้ทั้งหมด
8. **เก็บข้อมูลได้ 3 จาก 4 รอบที่วางแผนไว้** — การหยุดที่ 3 รอบเป็นไปตามกติกาสำรองที่ประกาศไว้ และตัดสินใจก่อนตรวจผลแยกกลุ่ม การคาดการณ์จากข้อมูลรวมระบุว่าการเพิ่มรอบที่ 4 จะทำให้ช่วงความเชื่อมั่นแคบลงเพียงเล็กน้อย
9. ใช้ข้อความตอบกลับมาตรฐาน — ข้อความที่ส่งหลังรอบแรกเป็นข้อความตายตัว ไม่ใช่คำตอบจากผู้ใช้จริง ในการใช้งานจริง ผู้ใช้อาจตอบคำถามของเอเจนต์ได้ ซึ่งอาจทำให้ผลต่างจากการทดลองนี้
