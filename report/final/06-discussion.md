# 6. อภิปรายผลและข้อจำกัด

## 6.1. ผลของรูปแบบกฎและผลของการมีกฎ

ผลจากการทดลองชุดที่ 3 ควรมองแยกเป็น 2 คำถาม คำถามแรกซึ่งเป็นคำถามหลักคือ กฎสองรูปแบบให้ผลต่างกันหรือไม่ ผลหลักตามแผนสรุปว่า A2 และ A1 เทียบเท่ากันภายในเกณฑ์ที่กำหนด (ตารางที่ 10) และข้อสรุปนี้คงเดิมในการวิเคราะห์ความไวทั้งสองแบบ (ตารางที่ 11) เมื่อพิจารณาร่วมกับเรื่องคะแนนใกล้ค่าสูงสุด (หัวข้อ 6.4. ข้อ 4) สิ่งที่การทดลองนี้ยืนยันได้ชัดคือ Agent Skills ที่เขียนแบบนี้ *ไม่ด้อยกว่า* ไฟล์เดียว โดยขอบล่างของช่วงความเชื่อมั่น 90% อยู่ที่ −0.1 จุด

คำถามที่สองคือการมีกฎช่วยให้เอเจนต์ทำตามข้อกำหนดได้ดีขึ้นหรือไม่ การเปรียบเทียบเชิงสำรวจพบว่า A0 ซึ่งไม่มีกฎทำงานสำเร็จได้ใกล้เคียงกับกลุ่มอื่น แต่ผ่านกฎสำคัญครบน้อยกว่าและแก้ไฟล์นอกขอบเขตบ่อยกว่า (ตารางที่ 13) ความต่างนี้ไปในทิศทางเดียวกันหลายตัวชี้วัด แต่เมื่อใช้เกณฑ์เดียวกับผลหลัก ผลต่าง A1 − A0 ชัดเฉพาะ CRIT ส่วน SCOPE และ RCRc ยังสรุปไม่ได้ (หัวข้อ 5.5.) และชุดที่ 3 ไม่มีกลุ่มที่มีข้อความยาวเท่ากันแต่ไม่ใช่กฎ จึงแยกไม่ได้ว่าความต่างมาจากเนื้อหาของกฎ หรือจากการมีข้อความเพิ่มในบริบท ซึ่งเป็นการควบคุมที่ Yang and Ding (2026) แสดงว่ามีผลจริงในบางโมเดล

เมื่อนำ RCRc มาแยกดูเป็นสองส่วน (ตารางที่ 13ก) ผลต่าง 2.8 จุดเกือบทั้งหมดมาจาก run ของ A1 ที่ทำงานไม่สำเร็จ 2 run ไม่ใช่จากอัตราการทำตามกฎเมื่อทำงานสำเร็จแล้ว ในการวิเคราะห์เชิงสำรวจนี้ ทั้งสองรูปแบบมีอัตราการทำตามกฎใกล้เคียงกันมาก ประเด็นนี้ช่วยอธิบายว่าทำไมค่า RCRc ซึ่งรวมสองเรื่องไว้ในตัวเลขเดียวจึงต่างกันเล็กน้อย

ผลการเปรียบเทียบ A0 กับกลุ่มที่มีกฎมีทิศทางเดียวกับข้อสังเกตจากรายงานสัมมนาในปีการศึกษา 2568 (ศุภกร กรอบเพ็ชร และ ศศิชา โสมวิภาต, 2568) ซึ่งพบว่าเอเจนต์ที่ได้รับบริบทปฏิเสธคำสั่งที่อาจทำให้โปรเจกต์เสียหาย ขณะที่เอเจนต์ที่ไม่ได้รับบริบทพยายามทำตามคำสั่งนั้น งานนี้พบรูปแบบใกล้เคียงกันจาก 264 run โดย A0 แตะไฟล์ข้อมูลและไม่ตรวจผลกระทบต่อข้อมูลย้อนหลังบ่อยกว่ากลุ่มที่มีกฎ (ตารางที่ 14ก) ทั้งนี้ การเปรียบเทียบนี้ยังเป็นเชิงสำรวจ

ผลหลักไม่ได้แสดงว่าชุดกฎแบบ Agent Skills ที่เขียนแบบนี้ทำให้เอเจนต์ทำตามกฎได้ดีกว่าไฟล์เดียว แต่ผลนี้ไม่ได้ทดสอบกลไกการโหลดโดยตรง เพราะ A1 กับ A2 ต่างกันทั้งรูปแบบและถ้อยคำ งาน Lost in the Middle (Liu et al., 2024) พบว่าข้อมูลที่อยู่กลางบริบทยาวอาจถูกใช้น้อยลง แต่กฎของ A1 ในการทดลองนี้ยาวราว 4,500 ตัวอักษร (≈2,000 token) ขณะที่บริบทในแต่ละครั้งที่เรียกโมเดลมีขนาดเฉลี่ยราวหลายหมื่น token (ประมาณจาก input token รวมในตารางที่ 14 หารด้วยจำนวนครั้งที่เรียกเครื่องมือ) กฎขนาดนี้จึงอาจยังไม่ยาวพอให้เกิดปัญหาจากการเห็นข้อมูลมากเกินไป ข้อสรุปจึงจำกัดอยู่ที่ชุดกฎขนาดนี้ และยังไม่ตอบว่าผลจะเป็นอย่างไรหากกฎยาวขึ้นหลายเท่า

ข้อมูลการโหลด skill ช่วยอธิบายผลได้อีกทางหนึ่ง กล่าวคือ A2 โหลด skill เพียงบางตัวในเกือบทุก run แต่ยังให้ผลเทียบเท่ากับ A1 ที่เห็นกฎครบทุกข้อตลอดเวลา (ตารางที่ 17) ค่า Trigger F1 (ตารางที่ 18) แสดงว่าการโหลดพลาดได้ทั้งสองทาง `impact-analysis` ถูกโหลดเกินจำเป็นบ่อย (precision 60.6%) ขณะที่ `safe-shell` และ `acceptance-first` ไม่ถูกโหลดในราวหนึ่งในห้าของโจทย์ที่ควรโหลด (recall 77.8% และ 81.3%) ในกรณีหลัง กฎใน skill นั้นไม่ได้อยู่ในบริบทของเอเจนต์จริง การที่ RCRc ของ A2 ยังเทียบเท่า A1 อาจเป็นเพราะกฎสำคัญที่ตรวจในโจทย์เหล่านั้นไม่ได้ขึ้นกับ skill ที่ขาดไป หรือเอเจนต์ทำตามได้เองโดยไม่ต้องอ่าน skill งานนี้ยังไม่ได้แยกตรวจข้อนี้ แต่ข้อมูลนี้สนับสนุนข้อเสนอแนะเรื่องการตรวจคำอธิบายของ skill ในหัวข้อ 6.3.

คำถามเรื่องกลไกการโหลดต้องเปรียบเทียบ A2 กับ A5 ซึ่งใช้ข้อความเหมือนกันทุกตัวอักษร งานนี้ยังตอบคำถามดังกล่าวไม่ได้ เพราะตามแผนแบบลำดับตายตัว จะทดสอบคู่นี้ได้ก็ต่อเมื่อผลหลัก A2 เทียบ A1 พบความต่าง แต่ผลหลักสรุปว่าเทียบเท่า แม้ค่าประมาณของ A2 เทียบ A5 จะอยู่ใกล้ศูนย์ (ตารางที่ 12) ก็เป็นเพียงค่าประมาณที่ไม่ได้ทดสอบ จึงใช้วางแผนการทดลองครั้งต่อไปได้เท่านั้น ไม่ใช่หลักฐานว่ากลไกการโหลดไม่มีผล

ผลการทดลองมีข้อสังเกตสองประการที่เกี่ยวข้องกับงานด้านลำดับชั้นของคำสั่ง (หัวข้อ 2.3.) ประการแรก กับดักแบบคำสั่งฝังในโค้ด (S02, S13) แทบไม่แยกกลุ่ม เพราะแม้ A0 ที่ไม่มีกฎก็ไม่ทำตามคอมเมนต์ในโค้ดเลย (RCRc 100% ในสองโจทย์นี้) จึงเป็นไปได้ว่าโมเดลรุ่นนี้ไม่ทำตามคำสั่งจากเนื้อหาบุคคลที่สามลักษณะนี้อยู่แล้ว หรือกับดักยังไม่ยากพอ ประการที่สอง ใน S08 และ S09 เอเจนต์กลุ่มที่มีกฎแก้ `REQUIREMENTS.md` ตามคำขอเปลี่ยนกฎธุรกิจในโจทย์ ทั้งที่ไฟล์กฎห้ามไว้ และทำเช่นเดียวกับ A0 ที่ไม่ได้รับกฎ (หัวข้อ 5.1.) กล่าวคือเมื่อคำขอของผู้ใช้กับกฎในไฟล์ขัดกันโดยนัย เอเจนต์เลือกทำตามคำขอ ข้อสังเกตนี้ไปทางเดียวกับที่ Geng et al. (2026) พบว่าการแยกแหล่งที่มาของคำสั่งไม่ได้สร้างลำดับชั้นที่เชื่อถือได้ แต่ในงานนี้เป็นเพียงสองโจทย์ จึงยังเป็นข้อสังเกต ไม่ใช่ข้อสรุป

## 6.2. ปัจจัยที่ทำให้การทดลองชุดที่ 3 ได้ข้อสรุป

ค่าเฉลี่ยของผลต่างจากการทดลองทั้ง 3 ชุดไปในทิศทางเดียวกัน คือ A2 สูงกว่า A1 เล็กน้อย (ตารางที่ 19) ชุดที่ 3 ตอบคำถามได้ในแบบที่สองชุดแรกตอบไม่ได้ด้วยปัจจัย 4 ประการ ดังนี้

ประการแรก ชุดที่ 3 เพิ่มเกณฑ์เพื่อตอบว่า ผลต่างมากพอจะมีความหมายในทางปฏิบัติหรือไม่ ไม่ได้ถามเพียงว่าพบความต่างหรือไม่ เมื่อความต่างจริงมีขนาดเล็ก การทดสอบแบบเดิมอาจต้องใช้ข้อมูลจำนวนมากจึงจะพบความต่างอย่างมีนัยสำคัญ

ประการที่สอง มีการแก้เครื่องมือวัดและเพิ่มจำนวนโจทย์ ในชุดที่ 2 โจทย์ 3 จาก 6 ข้อที่ได้คะแนนเสมอกันเกิดจากตัวตรวจบกพร่อง ไม่ใช่เพราะเอเจนต์ทำได้เท่ากัน ชุดที่ 3 แก้โจทย์เหล่านี้ เพิ่มจำนวนโจทย์เป็น 22 ข้อ และตรวจทุกโจทย์ผ่านด่านยอมรับทั้ง 5 ขั้นก่อนนำมาใช้

ประการที่สาม การหยุดถามไม่ได้ถูกนับเป็นงานไม่สำเร็จทันทีอีกต่อไป ในชุดที่ 3 run ของกลุ่มที่มีกฎซึ่งหยุดถามในรอบแรก ทำงานต่อจนสำเร็จหลังได้รับข้อความตอบกลับ 22 จาก 25 run (ตารางที่ 16) ผลต่าง A2 − A1 ก่อนและหลังรอบตอบกลับใกล้กัน (+2.4 จุดในตารางที่ 15 และ +2.8 จุดในตารางที่ 10) แต่ช่วงความเชื่อมั่น 95% แคบลงมาก จาก [−8.0, +13.8] เหลือ [−0.6, +6.4] เพราะ run ที่หยุดถามไม่ถูกนับเป็น 0 อีก ถ้าวัดผลเพียงรอบเดียว ช่วงความเชื่อมั่น 90% จะกว้างจนเกือบชนขอบเกณฑ์ (−6.8 ถึง +12.1 จุด) นอกจากนี้ การหยุดถามเมื่อไม่แน่ใจ ซึ่งเป็นพฤติกรรมที่ต้องการในงานจริง ก็ไม่ถูกลงโทษเป็นงานไม่สำเร็จอีก

ประการที่สี่ คะแนนของกลุ่มที่มีกฎอยู่ใกล้ค่าสูงสุด เนื่องจาก A1 ได้ RCRc 94.5% A2 จึงนำได้มากที่สุดเพียง 5.5 จุด ขอบบน +12.5 ของเกณฑ์เทียบเท่าจึงไม่มีโอกาสถูกทดสอบ และโจทย์ 14 จาก 22 ข้อได้คะแนนเท่ากัน ทำให้ช่วงความเชื่อมั่นแคบพอจะอยู่ในเกณฑ์ ระดับคะแนนนี้มาจากทั้งความยากของโจทย์และรอบตอบกลับในประการที่สาม (คะแนนเมื่อจบรอบแรกอยู่ที่ราว 86–89% ตารางที่ 15) ผลคือข้อสรุปเทียบเท่าตอบได้ชัดเฉพาะด้านที่ A2 ไม่ด้อยกว่า A1 (หัวข้อ 6.4. ข้อ 4)

## 6.3. ข้อเสนอแนะเชิงปฏิบัติ

สำหรับทีมที่ใช้เอเจนต์ช่วยเขียนโค้ด ผลจากการทดลองนี้นำไปใช้เป็นแนวทางได้ดังนี้

1. เลือกรูปแบบจากความสะดวกและต้นทุน ไม่ควรเลือกเพราะเชื่อว่ารูปแบบหนึ่งจะทำให้เอเจนต์ปฏิบัติตามกฎได้ดีกว่า ในการทดลองนี้ ซึ่งใช้โมเดลเดียวและชุดกฎยาวราว 2,000–3,300 token (ประมาณจากจำนวนตัวอักษร) Agent Skills ไม่ด้อยกว่าไฟล์เดียวเกินเกณฑ์ และมีต้นทุนประเมินต่ำกว่าราว 10% (ตารางที่ 14 เชิงสำรวจ) อีกทั้งแบ่งกฎเป็นหมวดที่ดูแลแยกกันได้ ส่วนไฟล์เดียวจัดการง่ายกว่าและไม่ต้องพึ่งการเลือกโหลด skill ให้ตรงงาน
2. ให้เอเจนต์มีกฎ โดยเฉพาะกฎเรื่องขอบเขตงานและการตรวจผลกระทบต่อข้อมูลเดิม ในการเปรียบเทียบเชิงสำรวจ กลุ่มที่ไม่มีกฎยังทำงานสำเร็จได้ แต่มีแนวโน้มแก้ไฟล์นอกขอบเขต ไม่ตรวจผลกระทบก่อนแก้ระบบคิดเงิน และแตะไฟล์ข้อมูลบ่อยกว่ากลุ่มที่มีกฎ (ตารางที่ 14ก) ส่วนกฎห้ามทำงานเกินคำสั่ง ข้อมูลชุดนี้ยังประเมินไม่ได้ เพราะตัวตรวจหลักของกฎกลุ่มนี้บกพร่อง
3. ตรวจคำอธิบายของ skill คำอธิบายเป็นตัวช่วยให้เอเจนต์ตัดสินใจว่าจะโหลด skill ใด ในการทดลองนี้ skill หนึ่งถูกโหลดเกินจำเป็นบ่อย และอีกสอง skill ไม่ถูกโหลดในราวหนึ่งในห้าของงานที่ควรโหลด (ตารางที่ 18) หากเขียนคำอธิบายกว้างเกินไป skill อาจถูกโหลดในงานที่ไม่เกี่ยวข้อง แต่ถ้าแคบเกินไป เอเจนต์อาจไม่โหลด skill ในเวลาที่จำเป็น
4. เปิดโอกาสให้เอเจนต์ถาม เมื่อพบข้อกำหนดที่กำกวมหรือขัดกัน เอเจนต์ที่มีกฎอาจหยุดเพื่อขอคำชี้แจง หากระบบงานไม่มีทางให้ใครตอบ ควรออกแบบวิธีจัดการคำถามไว้ เพราะการให้เอเจนต์ถามเป็นส่วนหนึ่งของการทำงานอย่างระมัดระวัง
5. ไม่ควรพึ่งพาเพียงกฎห้ามแก้เอกสาร ใน S08 และ S09 เอเจนต์กลุ่มที่มีกฎแก้เอกสารข้อกำหนดเองเมื่อผู้ใช้บอกว่ากฎธุรกิจเปลี่ยน แม้กฎจะห้ามไว้ ถ้าเอกสารบางไฟล์ต้องไม่ถูกแก้ อาจป้องกันด้วยสิทธิ์ของไฟล์หรือการตรวจก่อน merge ร่วมด้วย ข้อนี้เป็นข้อสังเกตจากสองโจทย์ และวิธีป้องกันดังกล่าวเป็นข้อเสนอของผู้วิจัยที่ยังไม่ได้ทดสอบ

## 6.4. ข้อจำกัดของการวิจัย

1. ใช้โมเดล เครื่องมือ และภาษาเพียงแบบเดียว ทุก run ใช้ Claude Sonnet 5 ผ่าน Claude Code รุ่นเดียวและคำสั่งภาษาไทย ผลอาจต่างออกไปเมื่อใช้โมเดลหรือเครื่องมืออื่น หรือเปลี่ยนเป็นคำสั่งภาษาอังกฤษ
2. ใช้ระบบจำลองและโจทย์ชุดเดียว ผู้วิจัยสร้างระบบจำลองและโจทย์ขึ้นเอง โดยออกแบบให้มีกับดักเพื่อแยกพฤติกรรมบางประเภท ผลจึงใช้สรุปกับโจทย์ลักษณะนี้ได้โดยตรง แต่ยังไม่ควรขยายไปสู่งานเขียนโค้ดทั่วไปทั้งหมด
3. ผู้วิจัยออกแบบสิ่งที่ทดสอบเอง และใช้เครื่องมือตระกูลเดียวกับที่ถูกทดลอง ผู้วิจัยกำหนดกฎ โจทย์ และตัวตรวจ โดยใช้ Claude เป็นเครื่องมือร่างเอกสารแผนและโจทย์ เขียนโค้ด เฝ้าติดตามการรัน และช่วยวิเคราะห์ ซึ่งเป็นโมเดลตระกูลเดียวกับที่ถูกนำมาทดลอง การตรวจทานแผนก่อนล็อกก็ใช้ Claude อีก session หนึ่ง ซึ่งไม่เป็นอิสระจากตระกูลโมเดล และการยืนยันว่าไม่ได้ดูผลแยกกลุ่มระหว่างเก็บข้อมูลอาศัยลำดับ commit ใน repository เป็นหลัก ไม่มีบุคคลที่สามยืนยัน การประกาศแผนล่วงหน้าและเปิดเผยข้อมูลที่เห็นก่อนออกแบบช่วยลดความเสี่ยงจากอคติ แต่ไม่สามารถขจัดความเสี่ยงนี้ได้ทั้งหมด
4. คะแนนอยู่ใกล้ค่าสูงสุด และเกณฑ์เทียบเท่ากว้างเมื่อเทียบกับพื้นที่ที่เหลือ กลุ่มที่มีกฎได้ RCRc เฉลี่ย 94–97% และ 14 จาก 22 โจทย์มีค่าเฉลี่ย A2 กับ A1 เท่ากัน เนื่องจาก A1 ได้ 94.5% ผลต่าง A2 − A1 จะเกิน 5.5 จุดไม่ได้ ขอบบนของเกณฑ์ (+12.5) จึงไม่มีโอกาสถูกทดสอบ ด้านที่ข้อมูลทดสอบได้จริงคือ A2 ไม่ด้อยกว่า A1 นอกจากนี้เกณฑ์ ±12.5 จุดยังกว้างกว่าผลต่างระหว่างไม่มีกฎกับไฟล์เดียวบน RCRc (+9.5 จุด) ดังนั้น "เทียบเท่า" ตามเกณฑ์ที่ประกาศไว้หมายถึงสองรูปแบบต่างกันไม่เกินขนาดที่ใกล้เคียงกับผลของการมีกฎ ไม่ได้หมายความว่ารูปแบบไม่มีผลเลย ถ้าใช้เกณฑ์ที่แคบกว่า เช่น ±5 จุด การทดสอบแบบสองด้านจะไม่ผ่านเพราะขอบบนอยู่ที่ +5.8 แต่ด้านไม่ด้อยกว่ายังผ่าน เพราะขอบล่างอยู่ที่ −0.1 จุด (การพิจารณานี้ทำหลังเห็นผล) หากใช้โจทย์ที่ยากขึ้น ผลอาจต่างออกไป
5. เทียบเท่าไม่ได้หมายความว่าเหมือนกันทุกด้าน ข้อสรุปหมายถึงผลต่างอยู่ภายใน ±12.5 จุดตามเกณฑ์ที่กำหนด ไม่ได้หมายความว่าความต่างเป็นศูนย์ ความต่างขนาดเล็ก เช่น 2.8 จุดที่สังเกตได้ อาจมีจริง แต่ข้อมูลชุดนี้ยังแยกไม่ได้ชัดว่าเป็นความต่างจริงหรือความบังเอิญ
6. ข้อความกฎของ A1 และ A2 ไม่เหมือนกัน แม้ข้อผูกพันของกฎจะเท่ากันทุกข้อ แต่ถ้อยคำและความยาวต่างกัน ดังนั้นข้อสรุปจาก A1 เทียบ A2 เป็นการเปรียบเทียบชุดกฎสองรูปแบบ ไม่ใช่ผลของกลไกการโหลดเพียงอย่างเดียว คู่ที่ตอบคำถามเรื่องกลไกได้ตรงคือ A2 กับ A5 แต่แผนผูกการทดสอบคู่นี้ไว้กับผลหลักที่ทำนายไว้ตั้งแต่ต้นว่าน่าจะใกล้ศูนย์ จึงมีโอกาสสูงตั้งแต่ขั้นออกแบบที่คู่นี้จะไม่ได้ทดสอบ ข้อนี้เป็นข้อจำกัดของการออกแบบ นอกจากนี้ข้อความของ A5 ซึ่งยกมาจาก skill ยังมีวลีที่ชวนให้เรียก skill ทั้งที่ A5 ไม่มี skill ให้เรียก (ตารางที่ 17)
7. ชุดโจทย์และเครื่องมือวัดเอนไปทาง A1 ชุดโจทย์ตั้งใจให้เอื้อ A1 และรอบนำร่องทั้ง 4 รอบใช้ A1 กลุ่มเดียวในการปรับชุดทดสอบและตัวตรวจ อคตินี้ดึงผลต่าง A2 − A1 ลง จึงทำให้การสรุปว่า A2 ไม่ด้อยกว่าหรือดีกว่า A1 ทำได้ยากขึ้น ข้อสรุปไม่ด้อยกว่าที่ได้จึงไม่ได้เกิดจากอคตินี้ แต่ถ้าผลจริงของ A2 เป็นบวก อคตินี้อาจทำให้ประเมินข้อได้เปรียบของ A2 ต่ำไป ขนาดของอคตินี้ประเมินเป็นตัวเลขไม่ได้
8. พบตัวตรวจบกพร่องหลังล็อกแผน หลังเริ่มเก็บข้อมูลพบตัวตรวจที่น่าสงสัย 3 จุด เป็นข้อบกพร่องจริง 2 จุด (S05 GP1, S06 FL1) อีก 1 จุด (S08/S09 SC1) ระหว่างเก็บข้อมูลผู้วิจัยบันทึกว่าเป็นข้อบกพร่อง แต่เมื่อทบทวนแล้วเป็นการละเมิดกฎจริง ผลหลักยังใช้ตัวตรวจเดิมตามแผน และการวิเคราะห์ความไวทั้งสองแบบให้ข้อสรุปเดียวกัน อย่างไรก็ตาม เหตุการณ์นี้แสดงว่าการตรวจเครื่องมือก่อนเก็บข้อมูลยังไม่สามารถจับข้อผิดพลาดได้ทั้งหมด และตัวชี้วัดรายประเภทกฎบางแถวในตารางที่ 14ก ยังได้รับผลจากตัวตรวจที่บกพร่อง
9. หยุดเก็บข้อมูลที่ 3 รอบก่อนครบเวลาที่แผนกำหนด แผนให้นับทุกรอบที่เสร็จภายในวันที่ 11 ต.ค. 10. ไม่ได้ทำการวิเคราะห์แบบ mixed-effects ที่ประกาศไว้ แผนระบุการวิเคราะห์ mixed-effects ระดับโจทย์ไว้เป็นการวิเคราะห์ความไวเชิงสำรวจ แต่ไม่ได้ทำ และไม่ได้บันทึกเป็นส่วนเบี่ยงเบนไว้ระหว่างเก็บข้อมูล ผู้วิจัยจึงรายงานไว้ที่นี่ ผลหลักไม่ได้อาศัยการวิเคราะห์นี้
11. ใช้ข้อความตอบกลับมาตรฐาน ข้อความที่ส่งหลังรอบแรกเป็นข้อความตายตัว ไม่ใช่คำตอบจากผู้ใช้จริง ในการใช้งานจริง ผู้ใช้อาจตอบคำถามของเอเจนต์ได้ ซึ่งอาจทำให้ผลต่างจากการทดลองนี้
12. ผลต่างขึ้นอยู่กับโจทย์บางข้อ ผลต่าง +2.8 จุดได้รับอิทธิพลจาก S19 มากที่สุด เมื่อตัดโจทย์นี้ออก ผลต่างเหลือ +1.3 จุด การวิเคราะห์นี้เป็นเชิงสำรวจ และไม่ได้เปลี่ยนข้อสรุปหลักว่า A2 กับ A1 เทียบเท่ากันตามเกณฑ์ที่กำหนด
