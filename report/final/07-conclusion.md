# 7. สรุปผล

## 7.1. สรุปผลตามวัตถุประสงค์

**วัตถุประสงค์ข้อที่ 1 เปรียบเทียบการปฏิบัติตามกฎระหว่าง Agent Skills กับไฟล์กฎไฟล์เดียว** ในการทดลองชุดที่ 3 ซึ่งมีโจทย์ 22 ข้อ 4 กลุ่ม และ 264 run เอเจนต์ที่ได้รับกฎแบบ Agent Skills ได้ RCRc เฉลี่ย 97.2% และเอเจนต์ที่ได้รับกฎแบบไฟล์เดียวได้ 94.5% ผลต่าง +2.8 จุด (CI 90% −0.1 ถึง +5.8 จุด, p = 0.148) อยู่ภายในเกณฑ์ ±12.5 จุดที่ประกาศไว้ล่วงหน้า จึงสรุปได้ว่า **สองรูปแบบให้ผลเทียบเท่ากัน** ข้อสรุปนี้คงเดิมเมื่อแก้ตัวตรวจที่บกพร่อง และเมื่อตัดโจทย์ที่มีปัญหาออก การแยกผลเชิงสำรวจชี้ว่าผลต่างเล็กน้อยที่เหลือมาจากการทำงานสำเร็จ ส่วนการทำตามกฎในงานที่ทำเสร็จแทบเท่ากัน คำถามเรื่องกลไกการโหลด (A2 เทียบ A5) ไม่ได้ถูกทดสอบตามแผน จึงยังไม่มีข้อสรุป ส่วนความต่างระหว่างการมีกฎกับไม่มีกฎนั้นใหญ่ในการเปรียบเทียบเชิงสำรวจ เอเจนต์ที่ไม่มีกฎผ่านกฎสำคัญครบเพียง 53.0% ของ run เทียบกับ 78.8–83.3% ของกลุ่มที่มีกฎ

**วัตถุประสงค์ข้อที่ 2 พัฒนาระบบวัดผลที่ตรวจได้ทั้งเอเจนต์และตัวเอง** ผู้วิจัยพัฒนา SkillBench ซึ่งตรวจการปฏิบัติตามกฎจากร่องรอยการทำงานจริงด้วยโปรแกรมทั้งหมด และมีด่านตรวจความถูกต้องของตัวเองหลายชั้น ด่านเหล่านี้พบข้อบกพร่องของเครื่องมือหลายสิบจุดตลอดโครงการ และระหว่างเก็บข้อมูลชุดที่ 3 ก็ยังพบอีก 3 จุด ซึ่งจัดการได้โดยไม่ต้องทิ้งข้อมูล การทดลองสองชุดแรกที่สรุปไม่ได้ มีส่วนสำคัญมาจากข้อบกพร่องของเครื่องมือวัด ไม่ใช่จากพฤติกรรมของเอเจนต์ บทเรียนนี้ชี้ว่าการวัดเอเจนต์ต้องลงทุนกับการตรวจเครื่องมือวัดมากพอ ๆ กับการเก็บข้อมูล

**วัตถุประสงค์ข้อที่ 3 เสนอแนวทางการเขียนกฎให้เอเจนต์** สิ่งที่ส่งผลมากที่สุดคือการมีกฎ ส่วนรูปแบบของกฎเลือกได้ตามความสะดวกในการดูแลและต้นทุน ในการทดลองนี้ (ชุดกฎยาวราว 2,000–3,300 token โมเดลเดียว) Agent Skills ใช้ต้นทุนต่ำกว่าไฟล์เดียวราว 10% เชิงพรรณนา โดยไม่เสียการปฏิบัติตามกฎ ถ้าใช้ Agent Skills ควรตรวจว่าคำอธิบายของแต่ละ skill ทำให้มันถูกโหลดในงานที่ควรโหลด และควรเปิดช่องให้เอเจนต์ถามเมื่อเจอข้อกำหนดที่กำกวม เพราะเอเจนต์ที่มีกฎใช้การถามเป็นส่วนหนึ่งของการทำตามกฎ

## 7.2. ข้อเสนอแนะ

7.2.1. **สำหรับทีมพัฒนา** ภายใต้เงื่อนไขที่ใกล้เคียงกับการทดลองนี้ เริ่มจากเขียนกฎที่ครอบคลุมขอบเขตงาน การตรวจผลกระทบต่อข้อมูลเดิม และคำสั่งที่ห้ามรัน เพราะเป็นกฎกลุ่มที่สร้างความต่างได้มากที่สุดในงานนี้ ส่วนกฎห้ามทำเกินสั่งยังได้ผลน้อยในทุกรูปแบบ ควรเสริมด้วยการรีวิวโค้ดของคน

7.2.2. **สำหรับผู้ที่วัดพฤติกรรมของเอเจนต์** ตรวจเครื่องมือวัดด้วยข้อมูลที่รู้คำตอบก่อนเก็บข้อมูลจริง ประกาศแผนการวิเคราะห์ล่วงหน้า และอย่าวัดแบบรอบเดียวถ้าเอเจนต์ถูกออกแบบให้ถามได้ เพราะการวัดแบบนั้นลงโทษพฤติกรรมที่ผู้ใช้ต้องการ

## 7.3. ข้อจำกัดและงานในอนาคต

ข้อสรุปของงานนี้ใช้ได้ภายใต้เงื่อนไขของการทดลอง คือ โมเดลเดียว เครื่องมือเดียว คำสั่งภาษาไทย ระบบจำลองหนึ่งระบบ และชุดโจทย์ที่ผู้วิจัยสร้าง คะแนนของกลุ่มที่มีกฎใกล้เพดาน และผลเทียบเท่าหมายถึงต่างกันไม่เกินเกณฑ์ ไม่ได้หมายความว่าเหมือนกันทุกประการ รายละเอียดอยู่ในหัวข้อ 6.4.

งานที่ควรทำต่อ ได้แก่

7.3.1. ทดสอบคำถามเรื่องกลไกการโหลดโดยตรง ด้วยการออกแบบที่ให้ A2 เทียบ A5 เป็นผลหลัก

7.3.2. ทำซ้ำกับโมเดลที่สองและคำสั่งภาษาอังกฤษ เพื่อดูว่าข้อสรุปขึ้นกับโมเดลหรือภาษาหรือไม่

7.3.3. ทดสอบกับชุดกฎที่ยาวขึ้นหลายเท่า เพราะข้อได้เปรียบของการโหลดเฉพาะส่วน อาจปรากฏเมื่อกฎยาวจนเริ่มถูกมองข้าม

7.3.4. เพิ่มโจทย์ที่ยากขึ้น เพื่อลดผลจากคะแนนชนเพดาน

7.3.5. พัฒนา adapter ตัวที่สองของ SkillBench สำหรับเอเจนต์อื่น เพื่อพิสูจน์ว่าระบบวัดผลใช้ข้ามเครื่องมือได้จริง
