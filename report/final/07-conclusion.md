# 7. สรุปผล

## 7.1. สรุปผลตามวัตถุประสงค์

**วัตถุประสงค์ข้อที่ 1 เปรียบเทียบการปฏิบัติตามกฎระหว่าง Agent Skills กับไฟล์กฎไฟล์เดียว** ในการทดลองชุดที่ 3 ซึ่งมีโจทย์ 22 ข้อ 4 กลุ่ม และ 264 run เอเจนต์ที่ได้รับกฎแบบ Agent Skills ได้ RCRc เฉลี่ย 97.2% และเอเจนต์ที่ได้รับกฎแบบไฟล์เดียวได้ 94.5% ผลต่าง +2.8 จุด (CI 90% −0.1 ถึง +5.8 จุด, p = 0.148) อยู่ภายในเกณฑ์ ±12.5 จุดที่ประกาศไว้ล่วงหน้า จึงสรุปได้ว่า **สองรูปแบบให้ผลเทียบเท่ากันตามเกณฑ์** และเนื่องจาก A1 ได้คะแนนใกล้ค่าสูงสุดอยู่แล้ว สิ่งที่ข้อมูลยืนยันได้ชัดคือ Agent Skills ที่เขียนแบบนี้ไม่ด้อยกว่าไฟล์เดียว (ขอบล่างของช่วงอยู่ที่ −0.1 จุด) ข้อสรุปนี้คงเดิมในการวิเคราะห์ความไวทั้งสองแบบ

การแยกผลเชิงสำรวจชี้ว่าผลต่างเล็กน้อยที่เหลือมาจาก A1 ทำงานไม่สำเร็จ 2 run ส่วนอัตราการทำตามกฎในงานที่ทำเสร็จใกล้เคียงกันมาก คำถามเรื่องกลไกการโหลด (A2 เทียบ A5) ไม่ได้ถูกทดสอบตามแผน จึงยังไม่มีข้อสรุป

ส่วนความต่างระหว่างการมีกฎกับไม่มีกฎ (เชิงสำรวจ) เอเจนต์ที่ไม่มีกฎผ่านกฎสำคัญครบเพียง 53.0% ของ run เทียบกับ 78.8–83.3% ของกลุ่มที่มีกฎ แต่เมื่อใช้เกณฑ์เดียวกับผลหลัก ผลต่างระหว่างไม่มีกฎกับไฟล์เดียวชัดเฉพาะตัวชี้วัด CRIT ส่วน SCOPE และ RCRc ยังสรุปไม่ได้

**วัตถุประสงค์ข้อที่ 2 พัฒนาระบบวัดผลที่ตรวจได้ทั้งเอเจนต์และตัวเอง** ผู้วิจัยพัฒนา SkillBench ซึ่งตรวจการปฏิบัติตามกฎจากร่องรอยการทำงานจริงด้วยโปรแกรมทั้งหมด และมีด่านตรวจความถูกต้องของตัวเองหลายชั้น คำตอบของคำถามด้านเครื่องมือวัดในหัวข้อ 1.2. คือ ระบบตรวจพบข้อบกพร่องของตัวเองได้เกือบทั้งหมดแต่ไม่ครบ ช่วงพัฒนาพบ 23 จุด การรีวิวภายนอกยืนยันได้อย่างน้อย 6 จุด รอบนำร่องพบ 8 จุด และหลุดไปถึงช่วงเก็บข้อมูลจริง 2 จุด (S05 GP1, S06 FL1) ซึ่งหนึ่งในนั้นเป็นกฎสำคัญที่อยู่ในผลหลัก ทั้งสองจุดตรวจพบระหว่างเก็บข้อมูลและจัดการด้วยการวิเคราะห์ความไวที่ประกาศไว้ก่อนดูผลแยกกลุ่ม โดยไม่ต้องทิ้งข้อมูล และไม่เปลี่ยนข้อสรุปหลัก ส่วนการทดลองสองชุดแรกที่สรุปไม่ได้ อย่างน้อยส่วนหนึ่งมาจากเครื่องมือวัดที่บกพร่อง (โจทย์ 3 จาก 6 ข้อที่เสมอกันในชุดที่ 2) ร่วมกับตัวชี้วัดที่เลือกในชุดที่ 1 และจำนวนโจทย์ที่น้อย บทเรียนนี้ชี้ว่าการวัดเอเจนต์ต้องลงทุนกับการตรวจเครื่องมือวัดไม่น้อยกว่าการเก็บข้อมูล

**วัตถุประสงค์ข้อที่ 3 เสนอแนวทางการเขียนกฎให้เอเจนต์** รูปแบบของกฎเลือกได้ตามความสะดวกในการดูแลและต้นทุน เพราะในการทดลองนี้ (ชุดกฎยาวราว 2,000–3,300 token ประมาณจากจำนวนตัวอักษร โมเดลเดียว) Agent Skills ไม่ด้อยกว่าไฟล์เดียวเกินเกณฑ์ และใช้ต้นทุนต่ำกว่าราว 10% (เชิงสำรวจ) ส่วนการมีกฎเทียบกับไม่มีกฎ ในสองปัจจัยที่ทดลอง การมีกฎมีแนวโน้มสัมพันธ์กับการรักษาขอบเขตงานและการตรวจผลกระทบต่อข้อมูลเดิมมากกว่ารูปแบบของกฎ (จากการเปรียบเทียบเชิงสำรวจ) ถ้าใช้ Agent Skills ควรตรวจว่าคำอธิบายของแต่ละ skill ทำให้ skill นั้นถูกโหลดในงานที่ควรโหลด และควรเปิดช่องให้เอเจนต์ถามเมื่อเจอข้อกำหนดที่กำกวม เพราะเอเจนต์ที่มีกฎใช้การถามเป็นส่วนหนึ่งของการทำตามกฎ

## 7.2. ข้อเสนอแนะ

7.2.1. **สำหรับทีมพัฒนา** ภายใต้เงื่อนไขที่ใกล้เคียงกับการทดลองนี้ เลือกรูปแบบของกฎได้ตามความสะดวกในการดูแลและต้นทุน และให้เอเจนต์มีกฎที่ครอบคลุมขอบเขตงาน การตรวจผลกระทบต่อข้อมูลเดิม และการห้ามแก้ไฟล์ข้อมูลโดยตรง เพราะเป็นกฎกลุ่มที่มีแนวโน้มเห็นความต่างระหว่างมีกฎกับไม่มีกฎมากที่สุดในงานนี้ (ตารางที่ 14ก เชิงสำรวจ) ส่วนเอกสารที่ต้องไม่ถูกแก้ ไม่ควรพึ่งพาเพียงกฎในไฟล์ เพราะในสองโจทย์ เอเจนต์กลุ่มที่มีกฎแก้เอกสารข้อกำหนดเองเมื่อผู้ใช้บอกว่ากฎธุรกิจเปลี่ยน (ข้อสังเกตที่ยังไม่ได้ทดสอบวิธีป้องกัน) ส่วนกฎห้ามทำเกินสั่ง ข้อมูลชุดนี้ยังประเมินไม่ได้เพราะตัวตรวจหลักบกพร่อง

7.2.2. **สำหรับผู้ที่วัดพฤติกรรมของเอเจนต์** ตรวจเครื่องมือวัดด้วยข้อมูลที่รู้คำตอบก่อนเก็บข้อมูลจริง ประกาศแผนการวิเคราะห์ล่วงหน้า ไม่ควรวัดผลเพียงรอบเดียวถ้าเอเจนต์ถูกออกแบบให้ถามได้ เพราะการวัดแบบนั้นลงโทษพฤติกรรมที่ผู้ใช้ต้องการ และเลือกโจทย์ที่ไม่ทำให้คะแนนชนเพดาน ไม่เช่นนั้นการทดสอบความเทียบเท่าจะตอบได้เพียงด้านเดียว

## 7.3. ข้อจำกัดและงานในอนาคต

ข้อสรุปของงานนี้ใช้ได้ภายใต้เงื่อนไขของการทดลอง คือ โมเดลเดียว เครื่องมือเดียว คำสั่งภาษาไทย ระบบจำลองหนึ่งระบบ และชุดโจทย์ที่ผู้วิจัยสร้าง คะแนนของกลุ่มที่มีกฎใกล้เพดาน และผลเทียบเท่าหมายถึงต่างกันไม่เกินเกณฑ์ ไม่ได้หมายความว่าเหมือนกันทุกประการ รายละเอียดอยู่ในหัวข้อ 6.4.

งานที่ควรทำต่อ ได้แก่

7.3.1. ทดสอบคำถามเรื่องกลไกการโหลดโดยตรง ด้วยการออกแบบที่ให้ A2 เทียบ A5 เป็นผลหลัก และเพิ่มกลุ่มที่มีข้อความยาวเท่ากันแต่ไม่ใช่กฎ เพื่อแยกผลของการมีกฎออกจากผลของความยาวข้อความ

7.3.2. ทำซ้ำกับโมเดลที่สองและคำสั่งภาษาอังกฤษ เพื่อดูว่าข้อสรุปขึ้นกับโมเดลหรือภาษาหรือไม่

7.3.3. ทดสอบกับชุดกฎที่ยาวขึ้นหลายเท่า เพราะข้อได้เปรียบของการโหลดเฉพาะส่วน อาจปรากฏเมื่อกฎยาวจนเริ่มถูกมองข้าม

7.3.4. เพิ่มโจทย์ที่ยากขึ้น เพื่อลดผลจากคะแนนชนเพดาน

7.3.5. พัฒนา adapter ตัวที่สองของ SkillBench สำหรับเอเจนต์อื่น เพื่อพิสูจน์ว่าระบบวัดผลใช้ข้ามเครื่องมือได้จริง
