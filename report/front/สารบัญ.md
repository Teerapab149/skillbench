## เนื้อเรื่อง

### บทที่ 1 — บทนำ

- 1.1 ความเป็นมาและความสำคัญของปัญหา
- 1.2 คำถามวิจัย
  - ข้อเสนอหลักที่นำไปทดสอบ
  - คำถามนี้ตอบทางไหนก็มีค่า
- 1.3 วัตถุประสงค์ของการวิจัย
- 1.4 สมมติฐานการวิจัย
  - ลำดับชั้นของ endpoint
  - สมมติฐานเชิงเนื้อหา
- 1.5 ขอบเขตและข้อจำกัดของการวิจัย
  - ขอบเขต
  - ข้อจำกัดเชิงระเบียบวิธีที่รู้ตัวและควบคุมไว้
  - สิ่งที่งานนี้ไม่ได้ทำ
- 1.6 ประโยชน์ที่คาดว่าจะได้รับ
- 1.7 นิยามศัพท์เฉพาะ

### บทที่ 2 — ทฤษฎีและงานวิจัยที่เกี่ยวข้อง

- 2.1 Context Engineering และ Agent Skills
  - แนวคิดพื้นฐาน
  - Progressive disclosure
- 2.2 การประเมินความสามารถของ LLM ในงานพัฒนาซอฟต์แวร์
  - เกณฑ์มาตรฐานที่ใช้กันแพร่หลาย
  - ช่องว่างที่สำคัญต่องานนี้
- 2.3 การวัดการปฏิบัติตามคำสั่ง
- 2.4 ลำดับชั้นของคำสั่ง ความยาว context และความสุ่ม
  - 2.4.1 ลำดับชั้นของคำสั่งไม่มั่นคงอย่างที่คาด
  - 2.4.2 ตำแหน่งของข้อมูลใน context มีผลต่อการถูกนำไปใช้
  - 2.4.3 ความสุ่มของโมเดลเป็นข้อเท็จจริงที่ต้องออกแบบรองรับ
- 2.5 Requirements Traceability Matrix ในบทบาทเครื่องมือวัดพฤติกรรม
  - สาขาเดิมและคำถามเดิม
  - คำถามกลับด้านของงานนี้
  - การเชื่อมกับศัพท์ทางการจัดการโครงการ
- 2.6 การออกแบบการทดลองแบบมีกลุ่มควบคุม
  - ปัญหาของการเทียบแบบ "มี" กับ "ไม่มี"
  - ข้อจำกัดที่ต้องระบุอย่างตรงไปตรงมา
  - การประกาศแผนวิเคราะห์ล่วงหน้า
- 2.7 สรุปช่องว่างของงานวิจัยที่ผ่านมา
- 2.8 รายการงานที่อ้างถึงและสถานะการตรวจสอบ

### บทที่ 3 — ระเบียบวิธีวิจัย

- 3.1 กรอบแนวคิดการวิจัย
  - คำถามวิจัย
  - ตัวแปรต้นและตัวแปรตาม
  - สิ่งที่ทำให้งานนี้ไม่ใช่การรีวิวเครื่องมือ
- 3.2 การออกแบบกลุ่มทดลอง 5 กลุ่ม
  - การเปรียบเทียบแต่ละคู่ตอบคำถามอะไร
  - ความเท่าเทียมของเนื้อหากฎระหว่าง A1 กับ A2
  - การจับคู่ความยาวของ contextual control
- 3.3 ตัวแปรควบคุมและการสุ่มแบบ randomized block
  - ตัวแปรที่ล็อกให้เหมือนกันทุกกลุ่ม
  - การสุ่มแบบ randomized block
  - การประกาศตัวแปรควบคุมไม่ใช่การควบคุม
  - ข้อจำกัดของการควบคุมที่ต้องระบุตามตรง
- 3.4 การออกแบบโจทย์และกับดัก
  - เหตุผลที่ต้องมีโจทย์ธรรมดา
  - เหตุผลที่เลือกสถาปัตยกรรมแบบเก็บลำดับเหตุการณ์
  - วิธีให้คะแนน
- 3.5 ตัวชี้วัดและสูตรคำนวณ
  - พื้นเชิงโครงสร้างของ RCR — ข้อจำกัดที่ต้องระบุคู่กับตัวเลขเสมอ
  - เหตุผลที่ pass^k เป็นตัวชี้วัดหลักไม่ได้ ทั้งที่มีความหมายเชิงการใช้งานมากที่สุด
- 3.6 สถิติที่ใช้และการคำนวณขนาดตัวอย่าง
  - หน่วยของการวิเคราะห์คือโจทย์ ไม่ใช่ run
  - แผนการทดสอบตามลำดับตายตัว (fixed-sequence)
  - ขนาดตัวอย่างและเหตุผลของจำนวนรอบ
- 3.7 ตารางการอ่านผลที่กำหนดไว้ล่วงหน้า
  - กฎการรายงานที่ผูกมัดไว้ล่วงหน้า
  - ประตูตรวจสภาพก่อนเก็บข้อมูลเต็มชุด
- 3.8 การออกแบบของชุดที่ 2 — อะไรเปลี่ยน และเพราะอะไร
  - 3.8.1 กลุ่มทดลอง — เพิ่ม A5 ตัด A3 และ A4
  - 3.8.2 ตัวชี้วัดหลัก — จาก CRIT เป็น RCRc
  - 3.8.3 การลดชั้นกฎที่วัดข้อความในโค้ดแทนพฤติกรรม
  - 3.8.4 ลำดับชั้นการทดสอบและการจัดสรรของชุดที่ 2
  - 3.8.5 สิ่งที่ยกมาทั้งหมดโดยไม่เปลี่ยน
- สรุปบทที่ 3

### บทที่ 4 — การออกแบบและพัฒนาระบบวัดผล

- 4.1 สถาปัตยกรรมของระบบวัดผล
  - ลำดับการทำงานของหนึ่ง run
  - เหตุผลที่แยกชั้น adapter ออกมา
  - การทำซ้ำได้
- 4.2 ระบบจำลองที่ใช้เป็นสนามทดสอบ
  - เหตุผลที่ต้องเป็นสถาปัตยกรรมแบบนี้
  - ข้อกำหนดและเอกสารประกอบ
- 4.3 การติดตั้งบริบทของแต่ละกลุ่มทดลอง
  - กลไกรีเซ็ตและติดตั้ง
  - หลักฐานว่าบริบทถูกติดตั้งจริง
- 4.4 ตัวตรวจกฎแบบกำหนดผลได้แน่นอน
  - หลักการที่ห้ามละเมิด
  - ชนิดของตัวตรวจ
  - ตัวตรวจต้องเป็นฟังก์ชันบริสุทธิ์
- 4.5 กลไกตรวจสอบความถูกต้องของเครื่องมือวัด
  - ทำไมระบบวัดเอเจนต์จึงล้มเหลวแบบเงียบเป็นพิเศษ
  - หลักการรับมือ: ป้อนข้อมูลที่รู้คำตอบล่วงหน้า
  - การให้คะแนนซ้ำ: แยก "เครื่องมือเปลี่ยน" ออกจาก "เอเจนต์เปลี่ยน"
  - การบังคับตัวแปรควบคุมในระดับ run
  - การป้องกันการวิเคราะห์ที่อ่านผลผิด
  - สรุปหลักการที่นำไปใช้กับงานอื่นได้
- 4.6 ส่วนขยายของระบบวัดผลสำหรับชุดที่ 2
  - 4.6.1 การติดป้าย "เข้าเงื่อนไข" ให้กฎแต่ละข้อ
  - 4.6.2 ด่านพื้นของตัวชี้วัด — ออกแบบให้ล้มได้
  - 4.6.3 แยก "เรียก skill" ออกจาก "skill เข้าบริบท"
  - 4.6.4 แผนการวิเคราะห์ที่โค้ดทำตามจริง
  - 4.6.5 การแยกชุดข้อมูลสองชุดออกจากกัน
  - 4.6.6 บทเรียนร่วมของข้อบกพร่องชุดนี้
- สรุปบทที่ 4

### บทที่ 5ก — ผลการทดลอง ชุดที่ 1

- 5ก.1 ชุดข้อมูลที่ใช้
- 5ก.2 ผลหลัก (primary endpoint)
- 5ก.3 ความไวของผลหลักต่อเกณฑ์ที่เลือก
  - 5ก.3.1 run ที่ชนเพดานงบ turn
  - 5ก.3.2 ICC ที่วัดได้จริง เทียบกับค่าที่ใช้วางแผน
- 5ก.4 ตัวชี้วัดรายกลุ่มทดลอง
- 5ก.5 CO-PRIMARY — RCR · A2 เทียบ A1
- 5ก.7 การตรวจสภาพการทดลอง (manipulation check)
- 5ก.8 ความแม่นของการยิง skill (Trigger F1)

### บทที่ 5ข — ผลการทดลอง ชุดที่ 2

- 5ข.1 ชุดข้อมูลที่ใช้
- 5ข.2 ผลหลัก (primary endpoint)
- 5ข.3 ความไวของผลหลักต่อเกณฑ์ที่เลือก
  - 5ข.3.1 run ที่ชนเพดานงบ turn
  - 5ข.3.2 ICC ที่วัดได้จริง เทียบกับค่าที่ใช้วางแผน

### บทที่ 6 — อภิปรายผลและข้อจำกัด

- 6.1 อภิปรายผล
  - 6.1.1 คำตอบต่อสมมติฐาน H1–H4
  - 6.1.2 ผลหลักสองชุดบอกอะไรเมื่ออ่านคู่กัน
  - 6.1.3 ข้อสังเกตที่สำคัญที่สุดจากข้อมูล — กฎแลกความสำเร็จกับความสอดคล้อง
  - 6.1.4 กลไกทำงาน แต่ผลปลายทางไม่ขยับ — ตีความอย่างไร
  - 6.1.5 สิ่งที่ผลนี้บอกกับคนที่ต้องเขียนกฎให้เอเจนต์จริง
- 6.2 ข้อจำกัดของการวิจัย
  - 6.x.1 ข้อจำกัดเชิงกำลังการทดสอบ — ข้อที่หนักที่สุด
  - 6.x.2 ผลกระทบจากพื้นและเพดานของโจทย์
  - 6.x.3 ตัวชี้วัดหลักเป็นการ "และ" กันของกฎหลายข้อ
  - 6.x.4 ผู้วิจัยเป็นผู้ออกแบบทั้งกฎ โจทย์ และตัวตรวจ
  - 6.x.5 กลุ่มควบคุมเชิงความยาวไม่ใช่ยาหลอกที่พิสูจน์แล้ว
  - 6.x.6 ทุกกลุ่มเห็น skill ของเครื่องมือจำนวนหนึ่งเท่ากัน
  - 6.x.7 เวลาของระบบจำลองถูกตรึงไว้
  - 6.x.8 นิยามของ run ที่ใช้ turn จนหมดงบ
  - 6.x.9 ข้อจำกัดของตัวชี้วัดการเรียกใช้ skill
  - 6.x.10 ขอบเขตของการสรุปอ้างอิง
  - 6.x.11 เหตุการณ์ระหว่างเก็บข้อมูลและผลต่อความถูกต้อง
  - 6.x.12 ข้อมูลที่ถูกกันออกจากการวิเคราะห์โดยเจตนา
  - 6.x.13 ข้อจำกัดที่เพิ่มขึ้นจากชุดที่ 2
- สิ่งที่ต้องทำกับบทนี้หลังข้อมูลครบ
