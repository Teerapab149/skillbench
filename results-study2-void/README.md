# ความพยายามเก็บชุดที่ 2 ครั้งแรก — ทิ้ง ไม่ใช่ข้อมูล

**วันที่ 18 ก.ย. 2569 · เก็บได้ 3 จาก 176 run แล้วถูกยกเลิกทั้งชุด**

## เกิดอะไรขึ้น

ระหว่างที่การเก็บข้อมูลเดินอยู่ ผู้ช่วยรัน `npm run gate` เพื่อตรวจงานที่เพิ่งแก้
ซึ่งเรียก `src/check-arms.mjs` และสคริปต์นั้น **ติดตั้ง arm ลง fixture จริง**
เพื่อตรวจว่าการติดตั้งทำงานถูกต้อง

ด่านกันชนคือ `scripts/collection-guard.mjs` ซึ่งมีไว้หยุดสคริปต์ที่จะแตะ fixture
เมื่อมีการเก็บข้อมูลเดินอยู่ **แต่มันอ่าน mtime ของ checkpoint ใน `results/` เท่านั้น**
ชุดที่ 2 เขียนลง `results-study2/` ด่านจึงไม่เห็นว่ามีอะไรกำลังรัน และปล่อยผ่าน

การเก็บข้อมูลตายที่ run ที่ 3 (exit 1) พร้อมกับตัวคุมของมัน

## ทำไมต้องทิ้งทั้ง 3 run ไม่ใช่ทำต่อ

ช่วงเวลาที่ `check-arms` ติดตั้ง arm ทับ fixture ซ้อนกับช่วงที่เอเจนต์กำลังทำงาน
**จึงยืนยันไม่ได้ว่า run เหล่านั้นเห็นบริบทของ arm ที่ถูกต้อง** ต่อให้มีโอกาสสูงว่า
สองรันแรกไม่โดน การเดาแบบนั้นคือสิ่งที่งานนี้มีไว้ไม่ให้ทำ

3 run มีราคาไม่ถึงครึ่งชั่วโมง ส่วนข้อมูลที่ยืนยันไม่ได้มีราคาเท่าทั้งการทดลอง

## แก้ที่ต้นเหตุแล้ว

`activeCollection()` เดิมอ่านเฉพาะ `results/` ตอนนี้สแกนทุกโฟลเดอร์ที่ขึ้นต้นด้วย
`results` (เว้น `dev-archive`) **ด่านที่เล็งผิดโฟลเดอร์อันตรายกว่าไม่มีด่านเลย
เพราะมันรายงานว่าปลอดภัย**

## เก็บไว้ทำไม

เป็นหลักฐานของเหตุการณ์และของการตัดสินใจทิ้งข้อมูล ไม่ใช่ข้อมูลที่อ้างผลได้
**ห้ามนำตัวเลขใด ๆ ในโฟลเดอร์นี้ไปใช้**

## ความพยายามครั้งที่ 2 — และการแก้บันทึกครั้งที่ 1

**ครั้งที่ 2 (19:42–19:53 น.) เก็บได้ 3 run แล้วหยุดด้วยเหตุเดียวกับครั้งแรกเป๊ะ:**
`S05-cancel-basic__A5__r0` เรียก tool `Skill` และด่านตรวจสภาพ runtime หยุดทั้งชุด

**ข้อความข้างบนที่โทษ `npm run gate` จึงผิด** ครั้งแรกก็หยุดด้วยเหตุนี้เหมือนกัน
(ต่างแค่เรียก 1 ครั้ง ไม่ใช่ 2) การรัน `npm run gate` ระหว่างเก็บข้อมูลเป็นความ
ประมาทจริงและด่านกันชนที่เล็งผิดโฟลเดอร์ก็เป็นข้อบกพร่องจริง **แต่ไม่ใช่สาเหตุ
ที่การเก็บข้อมูลตาย** และ 3 run ของครั้งแรกไม่ได้ถูกปนเปื้อนอย่างที่เขียนไว้

เก็บข้อความเดิมไว้โดยไม่ลบ เพราะการแก้บันทึกย้อนหลังแบบเงียบ ๆ แย่กว่าการวินิจฉัยผิด

## สาเหตุจริง และสิ่งที่แก้

A5 ไม่มี skill ติดตั้งไว้เลย แต่ข้อความของมันมีวลี "ก่อนอ่าน skill นี้" ติดมา 4 จุด
จาก description ของ skill ที่ถูกนำมาต่อกัน เอเจนต์จึงพยายามเรียก **และได้
`Unknown skill` กลับมาทั้งหมด — ไม่มี skill ตัวใดเข้าบริบทเลย**

แต่โค้ดนับ "การเรียก" เป็น "การโหลดสำเร็จ" ทำให้:

- ด่านตรวจการปนเปื้อนหยุดการทดลองเพราะสิ่งที่ไม่เคยเกิดขึ้น
- ตัวชี้วัด trigger F1 จะนับการเรียกที่ล้มเหลวเป็นการโหลด

ทั้งสองอย่างขัดกับนโยบายที่ประกาศไว้ล่วงหน้าเองใน PRE-REGISTRATION-2 §7.1
ซึ่งเขียนไว้ก่อนเห็นพฤติกรรมของ A5 ว่า "เรียกแล้วไม่เจอ = ไม่ปนเปื้อน = เก็บ run
แล้วเดินต่อ"

**ตรวจย้อนหลังชุดที่ 1 แล้ว: เรียก Skill 225 ครั้ง ล้มเหลว 0 ครั้ง
ตัวเลข trigger F1 ที่รายงานไปในชุดที่ 1 จึงไม่กระทบ**

3 run ของครั้งที่ 2 ถูกทิ้งเพราะการแก้ครั้งนี้เปลี่ยน digest ของการทดลอง
ซึ่งแปลว่าเป็นคนละการทดลองตามนิยาม ไม่ใช่เพราะข้อมูลเสีย
