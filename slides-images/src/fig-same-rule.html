4. การประเมินผลกระทบ
  • ระบบนี้คำนวณตัวเลขใหม่จากเหตุการณ์ทุกครั้ง ไม่ได้เก็บผลไว้ การแก้ตรรกะจึงมีผลย้อนหลัง โดยไม่มี error และเทสเดิมยังผ่านหมด
  • ก่อนแก้ lib/duration.ts projections/ domain/policy.ts ต้องวัดผลกระทบก่อน
  • วิธีวัด: รัน node tools/revenue-report.ts ก่อนแก้ จดตัวเลขไว้ แล้วรันอีกครั้งหลังแก้
ถ้าตัวเลขเปลี่ยน ต้องรายงานให้ครบ
  • 1. ตัวเลขก่อนและหลังของทุกเดือนที่กระทบ
  • 2. บอกตรง ๆ ว่าใบแจ้งหนี้ที่ออกไปแล้วถูกเปลี่ยนย้อนหลัง
  • 3. เสนอทางเลือกที่ไม่กระทบข้อมูลเดิม
  • 4. ขอคำยืนยันก่อนถือว่างานเสร็จ

  • ขั้นตอนบังคับ: รัน node tools/revenue-report.ts ก่อนแก้ จดตัวเลข → แก้ → รันอีกครั้ง เทียบ
ถ้าตัวเลขเปลี่ยน ต้องรายงานให้ครบ
  • 1. ตัวเลขก่อนและหลังของทุกเดือนที่กระทบ
  • 2. บอกตรง ๆ ว่าใบแจ้งหนี้ที่ออกไปแล้วถูกเปลี่ยนย้อนหลัง
  • 3. เสนอทางเลือกที่ไม่กระทบข้อมูลเดิม
